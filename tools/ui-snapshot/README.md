# celadon_ui_snapshot · 界面截图与交互检查（Linux / macOS）

> v0.1.8.0 界面改版（V4 设计稿「融合版」）引入。Mac 上照旧用 Xcode 编真插件看；这个工具让没有 Mac 的环境（CI、云端会话）
> 也能看到整个编辑器画出来是什么样、控件的手感对不对。

## 它做什么

把整个插件（`PluginProcessor` + `PluginEditor` + `Source/ui/*` + `Source/dsp/*`）连同 JUCE 的界面模块编成一个命令行程序：

1. 建处理器、`prepareToPlay (48 kHz, 512)`，建编辑器；
2. 喂 30 秒合成的音乐（120 BPM 的鼓、贝斯、和弦，未做母带的电平），每约 33 ms 让界面刷新一帧——GLAZE 听完、表与频谱稳定；
3. 按几种状态离屏渲染编辑器成 PNG：

`--only check` 另跑一组交互检查：直接给真实控件发鼠标事件（拖动、⌘ 精调、双击回默认、Alt 单击输入（含中文输入法的全角数字、
输入框开着时按键抬起不外传——Windows 上松开 Alt 会激活宿主菜单栏）、滚轮、滑条、
分段选择、曲风 / 交付两个选择（T-038：点选、说明格不可点、位置不压旋钮与左下说明）、CLAY 手动值、电源键、AUTO、等响、A / B、试听差值与 A / B 互斥、LIMIT 旁通时退出试听、「高级」面板开合、参考学习/取消、归一化预听互斥/离线/关窗清理、语言切换），
逐项打印 PASS / FAIL，任何一项失败退出码为 1；同时存下 `check-drag.png`（拖动中的数值气泡）、`check-original.png`、
`check-audition.png`、`check-advanced.png`、`check-english.png`。

T-100（ADR-037）起旋钮外圈换成 CometDial 的手感、读数带弹簧和彗尾，检查里多了一组（滚轮那条之后）：外圈 / 中间的分区、点外圈跳到所点角度、
沿外圈拖值跟着角度走、快甩松手多滑一段（落点 0.5 → 约 0.698）、停 120 ms 再松手不多滑、拖进底部缺口锁在最大、⌘ 在外圈按下不跳
且相对转动慢 8 倍、拖到一半松开 ⌘ 不跳、外圈双击回默认、小旋钮外圈与帽子上下拖（外圈挪约 5 px 就开始跟手：门槛按轨道半径换算）、
减少动效时读数直接落下且快甩不多滑、拖到一半按住不动时动画自己停（按钮还按着）、弹簧在跑时滚一下滚轮彗尾不猛闪。这组鼠标事件带确定的
时间戳（甩动按事件时间算速度），弹簧用 `DialControl::advanceMotion (1 / 60)` 手动推，不靠墙钟；每条都核对停稳后读数精确等于参数值、
彗尾为 0、动画定时器已停。缓存检查 ⑬ 也随之改写：减少动效时改一次值只合成 1 次；正常动效时读数在路上每帧合成、停稳后 5 次重画 0 次合成；
末尾一条改 0.1 %（在动时瓷面的容差 0.004 以内，往裂纹条数不变的方向改），动画停下后瓷面要按读数逐位精确地补生成一次。

T-102 在语言那条（⑪）之后加了 ⑪b：设置面板「减少动效」下面那行说明是单行画的（放不下截成省略号），中英两句按画它的字体与宽度
（`SettingsPanel::reduceMotionNoteFont / reduceMotionNoteWidth`，242 px）用 `drawText` 同一个排版函数排一遍，与不限宽时逐字相同才过，
并打印量出的宽度。界面缩放是整体变换，逻辑宽度各档位相同。这里量的是本机实际用的字体：JUCE 在 Linux 上扫字体只认 `.ttf` / `.otf`
（`juce_Fonts_freetype.cpp`），DGX 的 Noto Sans CJK 只有 `.ttc` 合集，JUCE 的字体列表里没有它，界面字体落到 `system-ui` = DejaVu Sans，
汉字由系统回退到 Noto Sans CJK JP。DejaVu 的拉丁字母比苹方、微软雅黑 UI 都宽，所以英文这里过了 Mac / Windows 也放得下；
中文是微软雅黑 UI 最宽，那两种按字体文件另算（`docs/validation/2026-10-18-T102-reduce-motion-note/`）。

**存图之前一律停稳**：工具不跑消息循环，弹簧会停在半路，所以 `save` 先对所有旋钮调 `finishMotion()`（读数落到参数值、彗尾清零），
存下的是真机静止时的样子，与没有动画时逐像素相同（`check-drag.png` 也是：拖动中途的读数在真机上本来就只落后约 60 ms）。

倒数第三、四条是 T-041（BUG-008）加的小数像素比检查：编辑器保持 1 倍，只把离屏画布的像素比设成 0.7 ～ 2.5（含 T-039 实测的
1.03293），看状态胶囊呼吸与对齐缓存（`AlignedComponentCache`）的局部作废是不是只重画作废区、结果与整块重画逐字节相同；
1 倍及以上呼吸帧一段字都不排版，低于 1 倍最多排第一段（设备像素比逻辑像素大，圆点区取整后可能与它的字形余量落进同一列）。

末尾两条是 T-051 的频谱仪检查：

- **IN 虚线**：频谱仪自己切段的 `createDashedStrokeReusing`（中线段与虚线都写进成员路径，播放中每帧重建不再新建路径；
  评审 R-07）与 JUCE 的 `PathStrokeType::createDashedStroke` 逐元素逐位相同——84 条随机折线（乱跳、缓变、贴顶贴底、带重复点）。
  JUCE 升级后改了切段算法，这一条会先报出来。
- **增量重画 vs 整帧**（评审 R-08 的建议，守 R-02 那一类「脏区漏标、旧画面留在屏上」）：给编辑器挂一个只记账的缓存图，
  记下每帧所有 `repaint` 的区域，按窗口系统的口径只把脏区画进一张一直留着的「屏幕」图——×1 矩形列表（Windows Direct2D、Linux）、
  ×1 包围盒（macOS）、×2 矩形列表，再与同一时刻整帧重画的频谱仪那一块逐字节比，有一个像素不同就失败。场景照评审 B1 的 S8：
  GLAZE 0、峰值线关、斜率 0，6 kHz −12 dBFS 稳态正弦 12 s（最后 1 s 频谱仪必须 0 帧被标脏：确认已静止）→ 斜率换 4.5 →
  切到 B（OUT 清零重来）→ 再跑 1 s，每帧都比。与评审时有一处不同：换斜率之后先「只重画、不推频谱」一帧（点击引起的重画
  先于显示器的帧回调到达，两者谁先到不固定）——T-036 修订（评审 R-07）改按加斜率后的纵坐标判变化之后，换到 4.5 时压在底边下、
  还在往下落的峰值保持数据会露出来，先推一帧的话旧区域当帧就跟上了，照原样走抓不到 R-02。验证过有效：在 main 的临时副本里撤掉
  R-02 的修复，这一条失败（×1、×2 矩形列表各 6 帧有残影，切 B 后第一帧 6 kHz 峰顶 80 / 243 个像素）；放回去通过
  （做法与输出见 `docs/validation/2026-10-04-T051-spectrum-dash-snapshot/`）。这条检查守的是 R-02 的 ①（paint 里重建路径时把画出的区域
  并进旧区域）；只撤 ②（`curveRegion` 不论 PEAK / IN 开关都算峰值线与 IN 线）它照样通过（T-058 实测）。
  T-058 起「建会话、挂记账缓存图、每帧送音频 → `advanceForSnapshot` → 取脏区」抽成 `SpectrumRig`（之后的频谱仪检查与
  `--only spectrum-peak-bench` 共用）；抽完在 main 的临时副本里只撤 ① 复跑，失败的帧数、像素与首个残影位置与上面逐字相同。

接下来是 T-058 的频谱仪检查（S9 两个斜率各两行、播放、S10a / b / c；峰值线 PEAK 关着时 `setSpectrum` 不再比峰值线、计算器此刻的值每帧拷一份、任何重建都先换成它、
打开 PEAK 那一刻按此刻的值整组重建，见 `SpectrumView.h` 文件头）。逐帧比较抽成推进器 `DirtyRun`、场景放进场景表
`dirtyScenarios`（S8 的行为与输出文字与 T-051 逐字相同），S10 另走两个视图：

- **S9：PEAK 关 → 停播 → 打开 → 切 B**（增量重画 vs 整帧，三种口径同 S8；守打开 PEAK 时的重建；R-02 ② 在 T-058 上是第二道保险，
  单独撤它 S9 照样全过，要验 ② 只能在 main 上撤，见下）：GLAZE 0、峰值线关，6 kHz −12 dBFS 正弦 2 s → 数字静音（暖机不画）。
  停播后 OUT 约 0.3 s 落到底边以下，峰值保持 1.5 s 后按 12 dB/s 落，6.0 s 时 6 kHz 的保持值约 −42 dB（面板中部），远高于底边上
  OUT / 平均线的区域：这时点开 PEAK → 只重画一帧 → 中间不推、紧接着切 B（峰值线清到底线）→ 静音 30 帧，每帧都比。点开之后只要推过一帧、
  或在稳态正弦里点开（峰值线贴着 OUT 峰顶），撤掉 ② 也漏不出来。**T-070 起斜率 0 与 4.5（出厂默认）各一份**，并在停播后把鼠标悬停在
  6 kHz（光标列与读数框的增量重画也比；悬停场景逐像素比放 1 级通道差的容差：悬停之后光标列的左边缘在面板最上、最下一行各有一个像素差 1 级，
  是 JUCE 软件渲染器裁剪边界的取整，真残影差几十级以上；其余场景零容差）。
- **S9 另一行：PEAK 关、只剩峰值保持在落时 0 次重建**：上面 5.5 ～ 6.0 s 那 30 帧（PEAK 关、屏上什么都没变）里，路径重建次数
  （`SpectrumView::getCurveBuildCount` 的差）与脏区够到频谱仪底边的帧（= 重建路径 + 重画曲线区）都必须为 0。main `218789a` 是 30 / 30——
  这就是 T-058 要修的毛病；T-070 起数真的重建（原来拿脏区当代理，「每帧无条件重建、只在判变了时才重画」的改法数不出来）。
- **播放**（评审 B1 的第一个场景，最常见的路径）：峰值线开、斜率 4.5，合成音乐暖机 1 s、鼠标悬停在 3 kHz（T-070：光标圆点跟着曲线走、
  `repaintCurves` 补光标那一列），再比 2 s（×1 两种口径）。守各条线都进区域（峰值线常高出 OUT）与描边外扩的余量。
- **S10a / S10b / S10c：打开 PEAK、换斜率、悬停那一刻画的是此刻的数据**。残影检查拿同一视图的整帧重画作对照，路径是旧的时两边一样旧、抓不到；
  这里不建编辑器，一个计算器 + 两个不进窗口的频谱仪：test 的 PEAK 先关、到时点开，ref 的一直开着（峰值在落时每帧按此刻的值重建）。
  同样的正弦 2 s → 静音 4 s（两边的 OUT / 平均线都画成同一条底线），6.0 s 时点开 test 的 PEAK（b：同时把两边的斜率 0 换成 4.5），
  不推、两边各整帧画一张逐字节比，再推 30 帧每帧比；c 不点 PEAK，两边鼠标都移到 6 kHz，只比读数框那一片（图例开关左边）。
  a 守「打开时重建」与「PEAK 关时每帧拷峰值」，b 守「任何重建都先换成此刻的值」（曲线静止时换斜率，存下的旧 OUT 不被斜率抬出来；
  换斜率的读数也是此刻的），c 守悬停的读数用此刻的值（不用画出来的那组：PEAK 关着停播后它停在约 0.3 s 时）。T-070 起失败信息带第一个不同的后续帧号。

T-070（夜间评审 `wf_3e784f42-2fa` 指出的覆盖缺口）再加：

- **S9b：PEAK 开 → 关**（斜率 0 与 4.5 各一份，增量重画 vs 整帧）：已显示过的视图上点关 PEAK。T-058 之后 `setPeakShown(false)` 里的整面重画是擦掉峰值线的
  唯一手段（原来峰值保持往下落会每帧判变了顺手擦掉），其他检查都在第一帧之前把 PEAK 关好或只测 关 → 开，撤掉它全过。
- **S11：IN 虚线开着**（合成音乐，PEAK 关、IN 开、斜率 0 → 3、IN 关、IN 开，每步先只重画一帧再比 30 帧，增量重画 vs 整帧）：T-058 动过 IN 的两处，
  之前没有任何检查进过 IN。
- **S12：与「没有历史的全新视图」逐字节对照 + 绝对探针**。前面所有检查都是「视图对它自己」——两边跑同一份代码，数据通路上丢了一条曲线、
  「看没看变化」少比一条线、换斜率后虚线没作废，两边一起错、全过。这里不建编辑器：一个计算器 + 长期运行的视图（`SpectrumTimeline`；**构造时先画一次**，与真窗口一开窗就画过一样——
  否则第一次 paint 才用此刻的值建路径，会把「某条曲线之后一直没更新」整个掩盖，`no-compare-output` 变体第一轮就是这样幸存的），
  每个比较时刻现起一个全新视图（同开关、同斜率、同悬停；读数框 0.27 s 才刷新，所以连推 20 次 `setSpectrum`）整帧画一张：
  S12a 6 kHz 正弦 2 s → 静音，停播 4 / 5 / 6 s 与换斜率 0 → 4.5 的每一刻（PEAK 关 / 开各一遍，零容差）；S12b IN 开、稳态 10 s 后斜率 0 → 3 → 4.5
  （换斜率那一刻视图用此刻的值整组重建、与全新视图逐位相同；稳态那一刻本身不比：虚线的相位沿路径累计，0.1 px 的合法滞后会放大成半个像素）；
  S12c 白噪声 2 s → 静音、斜率 4.5（纯音的平均线在面板外，要宽带内容；斜率把高频曲线抬进面板；容差 24 级、只比读数框以下）；
  S12d 稳态正弦、斜率 0 / 4.5（OUT 一直在变，「少比 OUT」会让视图从没重建过）。
  **绝对探针**（不靠历史）：曲线应该在的那个点（位置由计算器的值与 `SpectrumView::xOf / yOf` 算出）附近必须有像素与「从没喂过数据的空视图」不同——
  OUT 填充、平均线（白噪声停播后 OUT 已落出面板、平均线还在）、峰值线、IN 虚线（对同一视图 IN 关）；悬停读数必须等于计算器此刻 OUT 在 6 kHz 的值（加斜率），
  探针先核对平均线与峰值线此刻读成别的值（读错来源会差好几 dB），否则算空转。
- **T-072：截图模式下定时器的看门狗不补推频谱仪**（T-070 评审 F9，`probeTimerPush`）。编辑器平时由垂直同步推频谱仪，垂直同步 100 ms 没来就由 30 Hz 定时器按墙钟接着推；
  离屏没有垂直同步，`advanceForSnapshot` 自己按给定时长推。原来只靠「把最近一次垂直同步记成现在」让看门狗以为垂直同步还活着——最后一帧之后过 100 ms、
  或那一帧自己耗时 ≥ 100 ms（慢机、Debug、机器被占满），看门狗就按墙钟再推一次，`--deterministic` 的出图随机器快慢变。现在 `advanceForSnapshot`

## 用法

```bash
# 依赖：freetype2 / fontconfig / X11（含 XInput2、Xcursor、Xinerama、Xrandr）的开发包；中文字体（Noto Sans CJK）
cmake -S . -B build-ui -G Ninja -DCMAKE_BUILD_TYPE=Release -DCELADON_JUCE_DIR=../JUCE
cmake --build build-ui --target celadon_ui_snapshot

xvfb-run -a build-ui/celadon_ui_snapshot --out shots                    # 全部状态，1 倍
xvfb-run -a build-ui/celadon_ui_snapshot --out shots --scale 2          # 2 倍（看 Retina 上的细节）
xvfb-run -a build-ui/celadon_ui_snapshot --out shots --only zh-default,en-help
xvfb-run -a build-ui/celadon_ui_snapshot --out shots --only check       # 交互检查
xvfb-run -a taskset -c 5 build-ui/celadon_ui_snapshot --only spectrum-bench --seconds 4   # 频谱仪 30 / 60 / 120 帧基准（T-036）
xvfb-run -a taskset -c 5 build-ui/celadon_ui_snapshot --only spectrum-peak-bench          # 峰值线关着时多做的重建 / 重画（T-058）
```

`--only spectrum-bench`（T-036）：音乐按帧率在放，每帧处理 1 / fps 秒音频、`advanceForSnapshot (1 / fps)`、只重画频谱仪那一块，
30 / 60 / 120 帧 × 1 / 2 倍各跑 `--seconds` 秒，打印每帧与每秒的 CPU（软件渲染器口径，绑单核跑更稳）。只用改前改后都有的接口，
能在改前的树上量基线。每帧重画整块频谱仪是上限：真机上只重画曲线新旧包围盒。

`--only spectrum-peak-bench`（T-058）：PEAK（峰值线）关着时频谱仪多做的重建 / 重画。每帧照真实窗口走：送 1 / fps 秒音频 →
`advanceForSnapshot (1 / fps)` → 只按记下的脏矩形（矩形列表口径）把频谱仪那一块画进一直留着的「屏幕」图。GLAZE 0、6 kHz −12 dBFS
正弦，两个场景：① S8（斜率 0，正弦 12 s → 斜率换 4.5、先只重画一帧 → 切 B → 1 s，同上面的增量重画检查）；② 停止（正弦 4 s →
数字静音 10 s，斜率 0 与 4.5 各一遍：峰值保持 1.5 s 后按 12 dB/s 落过整块面板，最后约 1.5 ～ 2.5 s 全静，作「什么都没变」的对照）。
各 × PEAK 关（被测）/ 开（对照）× 60 / 120 帧 × 1 / 2 倍，按秒打印：频谱仪被标脏的帧数、其中的「曲线帧」（脏区够到频谱仪底边：
`setSpectrum` 判变了、重建路径后 `repaintCurves` 的区域总是从最高的曲线顶到底边、横跨整块，读数框与响度小窗的重画够不到；
整块重画也算）、脏区设备像素、advance 与增量重画的墙钟与本线程 CPU（曲线帧与其余帧分开按帧平均：advance 两者之差约是一次重建 +
标脏）。末尾每种组合一行汇总。同样只用改前改后都有的接口：改前改后各跑一遍、逐行比（帧数与像素数每次运行都相同，时间有几 % 起伏）。
改前的数与交叉核对（临时副本里给频谱仪加探针，逐帧核对「曲线帧」与「判变了」一一对应、PEAK 关时有几次只因峰值线在变）见
`docs/validation/2026-10-04-T058-spectrum-peak-off/`。

Windows 上也能编（CMake + MSVC 或 clang-cl，GUI 目标在 Windows 上不需要额外的依赖包），用法相同。

`EXCLUDE_FROM_ALL`：默认构建（`celadon_tests`）不编它，工具坏了也不挡测试。它会改写用户设置文件里的语言 / 动效 / 默认大小
（`~/.config/Celadon/Celadon.settings`），跑完会留下最后一种状态的设置。`check` / `bench` / `spectrum-bench` / `spectrum-peak-bench` /
`digest` 开跑前都先放回同一基线（中文、不减少动效、默认大小 1），不受上一次留下的值影响（T-039：之前 `check` 漏了默认大小，
跑过 `zh-zoom70` / `zh-zoom150` 后再跑检查，编辑器按 0.7 / 1.5 倍打开，T-032 的两条缓存检查必然失败，看起来像偶发）。
`check` 要求编辑器正好 1200 × 820：虚拟屏幕至少 1240 × 900（`xvfb-run` 默认 1280 × 1024 够），否则第一条就报失败并停下。

## macOS 验证说明

消息泵支持 CoreFoundation，可将工具链接到同一轮 Xcode Release 的 `libCeladon.a`，验证实际发布代码中的处理器与编辑器。
macOS 验证时必须为工具单独编译 `UiSettings.cpp` 副本，把设置目录改到专用临时目录；不能让截图操作覆盖日常插件偏好。
`--only check` 会直接运行检查并退出；生成各状态图片请另一次调用，不要把 `check` 与图片名称放在同一列表。
新增检查还包括主/参考使用不同信号的总线隔离、参考工程保存和重启，以及实际 Apple Release 库的差值试听精确静音回归。
