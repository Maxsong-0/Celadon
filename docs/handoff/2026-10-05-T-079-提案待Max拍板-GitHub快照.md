## A. 「受限」旧说法（官网 3 处 × 中英，另加同根的状态表 1 处）

**已定事实**（代码）：

1. 顶栏阶段标签「受限 / Limited」（橙色）有**两个来源**（`PluginEditor.cpp:1326-1327` 把两者画成同一个标签）：
   - 状态行「方案受限 · 已退让 x dB / Plan limited」＝播放中保护层按 1 dB/s 退让，退到下限（−3 dB，`GlazeGuard.h:134`）**仍超约束**才置位（`GlazeGuard.cpp:285-297`、`GlazeController.cpp:3325`）；回到下限以上就清除（`GlazeGuard.cpp:309-310`）。
   - 状态行「受手动设置限制 / Limited by manual settings」＝手动设置已让某个模块超预算（或 LIMIT 旁通），该模块的自动增量撤回（`GlazeTypes.h:252`、`GlazePlanner.cpp:1773-1799`、`GlazeController.cpp:3326`）。**官网一处也没写这一种（本会话新发现，卡片没列）。**
   - GLAZE 为 0 时两者都不显示（`GlazeStatusText.cpp:190-202`）。
2. 决策器按预算少推、目标降低时，状态仍写「已锁定 · … · 目标 x LUFS」（`GlazeStatusText.cpp:275-295` 第 8 行），**不写受限**。T-077 新写的「交付」节已是这个口径（「目标是方向，不是保证」），所以站内现在是**旧句子不准、新句子没说**。

- 建议 en：「Look at the “Target … LUFS” on the status line first: dynamics protection comes before loudness, so once each module's budget is used up GLAZE stops pushing and the target comes down; the status usually still reads Locked. A status of Limited means one of two other things: “Limited by manual settings” means your manual values have already used up a module's budget, so that module's automatic increment is withdrawn; “Plan limited” means the protection layer has backed off to its floor (−3 dB) during playback and a constraint is still exceeded.
