## 2. 已定事项（不要重开）

1. Max 2026-11-18 在三版设计稿里选了 A「一釉」；2026-11-19 对细化稿答「可以，写计划」。决定记在 ADR-044（已采纳）。
2. ADR-044 第 2 条的 8 项照办：
   - 模块行固定在主区正下方，展开面板紧贴其下，频谱在最下面并让出高度；
   - 默认全收起，同一时刻最多展开一个，展开的是哪个、停在哪页随工程存；
   - 「高级」浮层取消，三页并进 BALANCE（推响不刺、目标频谱）和 LIMIT（发行安全）；
   - 顶栏状态胶囊平时不出现；模块行第二行写模块自己的读数；
   - 粒子取消；电源键只放在模块行；字号加 15 与 44 两档，色板不动。
3. 做法是「先加新的 → 一次切换 → 删旧的」：M1 ～ M5 编辑器仍是 V4，截图摘要和 M0 基线逐字节相同；M6 一次换版面；M7 删旧的；M8 才加动效。
4. 计划第 10 节的决定照办。有异议写进回执，不要悄悄改。
5. 不碰声音处理；参数表（ID、范围、默认值、个数）不变。
6. 整条分支做完、Max 在宿主里看过才合 main。
7. 实施由别人做是 Max 定的。他没有另说计划要改，交出方按「照这版计划实施」理解；Max 另有说法以他的为准。

M0 基线交 108，交法见 `docs/BUILDING.md`「测试机」一节。下面是 2026-11-18 T-121 复查时在 108 的 testbox 沙盒里实际跑通的入口（包目录里放 `Celadon/` 源码和 `JUCE/` 的 `modules`、`LICENSE.md`）：

```bash
export PYTHONUSERBASE=/cache/local PATH="/cache/local/bin:$PATH"
command -v cmake >/dev/null && command -v ninja >/dev/null || python3.12 -m pip install --user cmake ninja
BUILD="$PWD/build/base"   # 第二遍换成 build/v3，并加 -DCMAKE_CXX_FLAGS=-march=x86-64-v3
cmake -S Celadon -B "$BUILD" -G Ninja -DCMAKE_BUILD_TYPE=Release -DCELADON_JUCE_DIR="$PWD/JUCE"
cmake --build "$BUILD" --target celadon_tests && "$BUILD/celadon_tests"
```

- 这个入口只跑通过 `celadon_tests`。界面截图工具还要 freetype、fontconfig、x11 的开发头和 `xvfb-run`（`docs/BUILDING.md` 第 177 行一带、`tools/ui-snapshot/README.md` 第 217 行起），在 108 的沙盒里交出方没试过。
- 新包目录的第一个任务单独交（几个一起交会抢着装 cmake）；`--wait` 后面不接 `| tail`（会吞掉退出码）。
