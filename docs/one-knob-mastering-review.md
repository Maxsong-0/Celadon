# Celadon 一旋钮自动母带评估与改进

日期：2026-09-26。评估对象：本工作区源码。目标：插在母带轨，仅提高 GLAZE，即自动增响、实时调整频谱并加入适量染色；控制 CPU 开销。

## 客观判断

原版部分满足。它已包含前瞻限幅器、27 段实时动态 EQ、总线压缩和过采样谐波染色，但自动编排有三处空白：达到风格偏好响度后不再请求增益；首次画像缺少问题证据时可能长期不给频谱处理权限；没有削峰需求时可能完全不染色。

这三款产品适合作为目标方向，不能据此宣称 Celadon 复制了其算法或达到相同音质：

- [A.O.M. Invisible Limiter](https://aom-factory.jp/products/invisible-limiter/) 的官方定位是自动攻击/释放优化的透明前瞻砖墙限幅。Celadon 保留增益、前瞻和自动释放结构；音质接近程度须用真实歌曲做同响度对比。
- [The God Particle](https://cradle.app/products/the-god-particle/) 结合谐波处理和自适应限幅。Celadon 使用自己的 Tube、Glue 和 Tone 实现温和染色，不是其声音模型的复刻。
- [Gullfoss Master 官方手册](https://www.soundtheory.com/static/Gullfoss%20Operation%20Manual.pdf) 描述了其感知模型及 Master 版本的质量/CPU 取舍。Celadon 是 27 段局部动态频谱平衡，不具有经过证明的 Gullfoss 感知等效性。

## 本次实现

1. 已达到偏好响度的素材，仍有满刻度 3 dB 的增响请求下限。实际输出提升仍受音乐置信度、峰值与动态预算限制；并非保证多出 3 LU，也不是线性的 +24 dB Gain。
2. 自动 Recover/Tame 保留低水平基础力度（满强度 8/12，受风格上限与置信度缩放）。实际每段增减由输入频谱持续决定，首次聆听没有问题不再使后续修正永久为零。
3. 自动 Recover 与手动份额分开。仅内部频段、两侧有能量支持的持续缺口可被自动提升；150 ms 后渐入、500 ms 达到完整许可。端点、单调自然滚降及静音门下不被自动补齐，手动设置保留。
4. 在同一响度/峰值模型内加入轻微 Heat 底量（满强度 3，受风格与预算约束）；无法合理补偿时退让。没有额外的神经网络、FFT 或过采样链。
5. 独立 16 倍重建压力测试揭示原限幅在特定宽带噪声上最高超出 Ceiling 0.3039 dB。现在仅在限幅增益需求处预留 0.35 dB，成本为每样本一次乘法；Clip、用户 Ceiling 和输出硬钳位仍沿用原参数。这是经验保护，不能证明任意波形、编码转换或采样率转换都绝无超限。
6. 算法版本升至 2，默认方案与常量共用版本，修复 GLAZE=0 学完后保存、恢复被误判为旧版空方案的问题。旧版保存方案保留原自动参数与 Recover 行为；旧常量缺失的新字段按 0 读入。旧工程重新聆听后才采用完整的新出厂底量。限幅安全余量是全局修复，旧工程进行限幅时也可能多约 0.35 dB 的衰减。

## 使用方式与边界

新实例保持自动风格和其余默认值，播放音乐，从 0 逐渐提高 GLAZE 即可。首次 15–30 秒自动建立歌曲画像；频谱处理本身持续实时运行。极轻/极响的段落仍有校准及保护退让。换成另一首歌时，可用重新聆听更新整首歌画像。

当前不会持续重判整首歌的风格或无条件补回已经收紧的响度预算。保护触顶后，继续转大不能保证继续变响。是否更好听、染色是否足够、与三款参考的差异，需要真实歌曲同响度试听确认；合成信号测试不能替代听感验收。

## 验证

完整测试覆盖 101,088 项断言：第二次全套运行仅剩两条旧 GR 预期未计入 0.35 dB 保护余量；更新预期后，受影响的 GlazeCalibration 全类 670 项断言重新运行，0 失败。其余完整测试已通过，无 DSP 源码在该全套之后改变。

- 新插入只调 GLAZE=50：合成音乐的累计响度提升 6.47 LU；自动学习完成，增响、染色与频谱处理均启动。
- 同一学习状态，GLAZE 0/25/50/75/100：−23.97 / −20.61 / −17.24 / −13.96 / −10.64 LUFS（这是单一合成素材结果，不是任意歌曲保证）。
- 独立真峰值：48 案例，16×、128 抽头 double Kaiser sinc，逐插值位置检查；最坏为 Ceiling−0.0461 dB，通过 Ceiling+0.01 dB 门槛。
- 真实音频路径测试包含新频谱凸起、持续缺口、自然滚降、静音、手动份额、分块一致性、自动化平滑、旧状态恢复、校准/保护协作、实时 C++ 堆零分配。

### CPU 实测

Apple M2 Pro，接电、低电量模式关闭，Apple Silicon Release（O3+LTO），立体声，UI 关闭。完整 AudioProcessor::processBlock，含参数、两块表、学习/编排与所有 DSP。每行先处理 45 秒素材（所有行均确认 profileReady=1；当时仍在自动校准），再测 3 遍各 8 秒。

百分比 = 每块处理时间 / 该音频块的播放时长，表示单个音频线程实时预算占用，**不是整机 CPU 百分比或某个 DAW 的表值**。平均和 p99.9 是各遍的最小值；最后一列是所有遍中最慢一次，保留调度抖动。

| GLAZE 100 | 缓冲样本 | 平均预算占用 | p99.9 | 全部遍最慢块 |
|---|---:|---:|---:|---:|
| 48 kHz | 32 | 1.276% | 3.175% | 13.231% |
| 48 kHz | 64 | 1.259% | 2.484% | 10.131% |
| 48 kHz | 512 | 1.171% | 1.691% | 1.993% |
| 96 kHz | 32 | 2.557% | 7.350% | 23.625% |
| 96 kHz | 64 | 2.522% | 5.513% | 12.506% |
| 96 kHz | 512 | 2.330% | 3.548% | 6.841% |
| 192 kHz | 32 | 5.094% | 18.525% | 51.150% |
| 192 kHz | 64 | 5.031% | 12.812% | 32.962% |
| 192 kHz | 512 | 4.652% | 7.759% | 9.516% |

本次测量没有单块超过其音频预算。48 kHz/64 时平均约 16.8 微秒/块。延迟保持 282/378/570 样本（48/96/192 kHz，默认 Lookahead=2 ms）。

同条件短预热的已有 typical 场景，48 kHz/64 平均从 1.194% 到 1.235%，96 kHz/64 从 2.346% 到 2.457%；处理行为增强，开销小幅增加，没有为了省 CPU 降低过采样品质。该前测的低电量字段未读到，不能将细小差异当作精确优化收益。老电脑、Intel、其他 DAW、界面打开或多实例并发仍须各自测量。
