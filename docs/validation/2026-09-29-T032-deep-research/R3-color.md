## R3-01 Glue 分频施压：检测器非互补驼峰 + 二阶分裂相位凹陷（high / P1 / 算法设计）

**规格与文档承诺**：`设计规格-Color.md`「2026-09-28 修订」：「中 = 侧链 − 低 − 高」「音频按同样的 180 Hz / 5 kHz 分三路（中 = 原样本 − 低 − 高，三路相加精确还原）」「中频跟联动攻击」「响的一侧保持原来的压缩」；`docs/reference-chain-algorithm.md:48-50`：「表和统计仍是原来的联动包络……所以稳态方波的压缩量读数不变」。

**证据（代码）**：
- 分频器是 RBJ 二阶 Butterworth（Q = 0.7071，`ColorModule.cpp:50,439-440`），设计函数 `designLowpass` / `designHighpass`（`:330-362`）。
- mid 检测器 = `hp − detectedLow − detectedHigh`：打包路径 `:1090,1093`，标量路径 `:1131`。
- 三路压缩量包络 `:1238-1240`；Δ = clamp(0.5 × (联动 − 本路), −0.6, +3.2) × glueOn：`:1247-1252`（常数 `:70-72`）。
- 音频施加 `sample = midGain·(x − low − high) + lowGain·low + highGain·high`：`:1279-1282`。
- GR 表与统计只报联动包络：`:1264,1267,1287-1290`。
- 现有测试只断言「低音比中音少压 ≥ 1 dB」（`ColorTests.cpp:904-935`）和联动 GR 在 3～10 dB（`:939-954`），没有任何用例核对**实际施加增益**与联动静态曲线的关系。

**机理**：
1. **检测器驼峰**：`1 − LP₂(180) − HP₂(5k)` 不是互补分频，二阶 Butterworth 在 fc 处相移 −90°，`1 − LP` 的幅度 |1 + 0.707j| = +1.77 dB，峰值 **+2.10 dB @ 229 Hz 与 @ 3969 Hz**（numpy 频响，见实验记录 B）。一条带的读数不可能高于整段，但 mid 检测器读数比联动高 2.1 dB → 纯中频音色的 `midReductionDb` 比联动深 ≈ 1.05 dB → Δmid 触到 −0.6 dB 钳位（`glueBandDeltaMinDb`）。规格「中频跟联动」被系统性违反；该钳位在稳态里几乎只被这个伪像触发。
2. **音频分裂相位凹陷**：低 / 高带「自己更轻」时被抬 +3.2 dB（对纯中频音色，低 / 高检测器只看到中频经滤波器裙边的泄漏，必然「更轻」，Δ 恒被钳到 +3.2），而音频侧的 `(g_low − g_mid)·LP(x)` 在 fc 以上 Re{LP} < 0（Butterworth 在 1.5 fc 处 Re = −0.206），抬升的泄漏与主信号反相叠加：`1 + 0.445·LP + 0.445·HP` 的响应范围 **−0.77 … +3.18 dB，凹陷 −0.77 dB @ 3042 Hz；只抬低带时凹陷 −0.75 dB @ 301 Hz**（实验记录 B）。即「保护低音」的动作本身把 300 Hz 与 3 kHz 附近的中频再压 0.75 dB。
3. 两者叠加：−6 dBFS 纯音、Glue 100、48 kHz 稳态（实验记录 A）：联动静态曲线净增益 −2.53 dB（GR 8.53 − 补偿 6），实际 **229 Hz −0.84、250 Hz −0.97、300 Hz −1.13、400 Hz −1.05、2.5 kHz −1.11、3.5 kHz −0.99 dB**（比联动多压），60～120 Hz +0.19～+0.32、≥ 7 kHz +0.07～+0.21（少压）；跨频率偏差幅度 1.45 dB。GR 表按联动读数：300 Hz 时表报 8.5 dB、实际 9.6 dB。96 kHz 复算数字相同（采样率无关，实验记录 A 末）。文档「6 kHz 方波的联动压缩量仍落在原静态曲线上」说的是**读数**，不是施加量。

**修法**：
- **当晚（S）**：mid 直接跟联动——去掉 mid 检测器与其包络，`midDb = gainDb`。改动点：`:1090,1093,1131`（不再算 `midPeak`）、`:1239`（删 `midReductionDb` 推进）、`:1251-1252`（`midDb = gainDb`）、`:1260-1261`（`midGain = gain`）、`:1253`（`useSplit = deltaLow != 0 || deltaHigh != 0`）；`midReductionDb`、`glueMidPeaks` 相关成员与 `restartGlueFromOff`/`reset` 里的清零同步删掉。仿真（mode 7）：最坏偏差 −1.13 → **−0.65 dB**，跨频率幅度 1.45 → 0.76 dB，低音保护不变（双音 90 Hz +0.68 / 2.5 kHz −2.59 dB）；同时每样本少 1 次 log10 + 1 次 exp（与 R3-02 叠加）。低 / 高检测器是 Butterworth（|H| ≤ 1），此后 `glueBandDeltaMinDb = −0.6` 在稳态里成为死码（只在瞬态振铃时触发），注释要改。
- **跟进（L，需试听）**：消除凹陷要改分裂结构，三个候选已仿真（实验记录 A/C）：
  - 一阶互补分裂（检测器与音频都用一阶双线性低通、高通 = x − 低通；`Re ≥ 0`，`1 + gl·LP₁ + gh·HP₁` 范围 0.26 … 3.18 dB、无凹陷）：跨频率幅度 **0.44 dB**、永不比联动更深，但一阶裙边让 2.5 kHz 人声在低音伴奏下只压 −1.15 dB（联动 −1.9）——选择性变差。
  - LR2（Q 0.5）分裂 + mid 跟联动：凹陷减半（−0.4 dB），但 LR2 低通在 90 Hz 已 −1.9 dB，双音里低音保护从 +0.66 掉到 +0.01 dB——功能几乎失效，不推荐。
  - LR4 + 全通补偿的标准三路分频（低 = LR4LP·AP₅ₖ、中 = LR4HP₁₈₀·LR4LP₅ₖ、高 = LR4HP·AP₁₈₀，检测器复用音频分裂 + 低带再过 100 Hz 高通）：各带同相、陡峭、无凹陷，是多段压缩的标准做法；代价每声道约 11 个双二阶（现 5），且 Glue 开着时输出带一个固定全通（Δ = 0 时不再逐位等于单增益乘法，需改「三路 Δ 为 0 退回单增益」的契约注释与测试）。
  - 若暂不动结构，把 `glueBandDeltaMaxDb` 从 3.2 降到 1.5 可把凹陷压到 −0.34 dB（凹陷 ∝ 10^(Δ/20) − 1）。
- **文档**：规格「三路相加精确还原」正确但要补一句「Δ ≠ 0 时施加增益随频率偏离联动曲线」；`docs/reference-chain-algorithm.md:82` 的双音数字要在修后重测。

**changes_output**：是——仅 Glue 开着且 Δ ≠ 0 的样本；Glue 关、Δ = 0 逐位不变（`:1253-1254` 的 `useSplit` 分支保留）。

**验证**：新增 `ColorTests` 用例「Glue applied gain tracks the linked static curve」：48 kHz、Glue 100、−6 dBFS 正弦 {60, 90, 150, 229, 300, 500, 1000, 2500, 3969, 7000, 10000} Hz，稳态后 0.5 s 的输出 / 输入 RMS 与 `getAndResetGainReductionDb()` − 6 dB 补偿之差：当晚修法后断言 |偏差| < 0.7 dB（现行 1.13 dB 必败）、跟进 LR4 后收紧到 < 0.3 dB；保留 `:904-935` 双音用例并把阈值改为记录实际数字。仿真程序 `glue_sim.cpp`（附录 D）可直接改成该测试的参照。

## R3-02 Glue 增益计算器的超越函数成本（medium / P1 / 优化）

**证据**：每个样本、Glue 开着时：联动 + 三路各一次 `20·log10(peak)`（`reductionTargetFor`，`:1198`，被 `:1215,1235` 调用 4 次），`std::exp` 最多 4 次（`:1254,1257,1259,1261`）；`log10` 只在 `peak > kneeStartLinear` 时省掉（`:1195`），响的母带素材四路都过拐点。
107（x86-64，glibc 2.4x，g++ 15 −O2）基准（实验记录 E）：4× log10 + 4× exp = **69.5 ns/样本**；48 kHz 单声道联动即 3.3 ms/s ≈ **0.34 % 单核**。文档实测 Color 在 48 kHz / 512：Glue 关 0.16 %、GLAZE 100（Glue 开）0.60 %（`设计规格-Color.md` 2026-09-28 段，同一台 x86 虚拟机），差 0.44 % 与本估算量级一致——Glue 增益计算器是 Color 里最贵的一块，超过 Heat 整条 8× 半带 + tanh 链（后者按抽头对数估算约 164 次 pair-MAC + 8 次 tanh4/样本）。M2 Pro 的 libm 更快，绝对数字会小（Color 满载 0.32 %），比例关系不变。

**机理**：dB 域检测 + dB 域包络是 Giannoulis 2012 的标准拓扑，本身没错；问题是每个样本每条带都走一次 double `log10` 与 `exp`，而带数从 1 变成 4 后这部分线性放大，其他部分（双二阶）都已 SIMD 化。

**修法（M）**：
1. 先吃 R3-01 的当晚修法：少一路 → 3× log10 + 3× exp（−25 %）。
2. 四路检测器的 dB 与四路增益改成 **4 路 SIMD 多项式**：`fastLog2x4`（指数位分离 + 尾数 [1,2) 上 5～6 次极小极大多项式，rel. err ≈ 1e-7）与 `fastExp2x4`（整数部分位拼装 + 小数部分 5 次多项式），写法与 `Saturator.cpp:139-178` 的 `tanh4` 相同：NEON / SSE2 / 标量同一串 IEEE 运算、不用融合乘加（ADR-013），三平台逐位相同。`over = 20·log10(p) − thr` 改为 `over = (20·log10(2))·log2(p) − thr`，`exp(dB·k)` 改为 `exp2(dB·k/ln2)`；`peak ≤ kneeStartLinear` 的分支保留（`log2` 输入 > 0）。预期每样本 < 15 ns。
3. 零代码风险的过渡：`20·log10(p)` → `8.685889638065035·std::log(p)`（基准 −25 %），或改 float `log10f/expf`（−43 %）。

**changes_output**：是——增益值在 1e-6 dB 量级上变动（≈ −120 dBFS）。Color 的逐位契约（空闲跳过 / 块长无关 / 打包 vs 标量 / L = R vs 单声道）都是同一代码两次运行的对照，新代码只要确定性、各路径同一份即可全部保持；GLAZE 标定表不含 Glue。

**验证**：`ColorTests` 现有全部用例不改；新增「fastLog2 / fastExp2 accuracy」穷举或抽样对照 `std::log2` / `std::exp2`（rel. err < 2e-7，±0、Inf、NaN 行为写明）；`tools/perf` 复测 Color 48 kHz / 512 Glue 100 前后。

## R3-03 Heat 8× 过采样倍率与采样率无关：驱动 10 时代的遗留（medium / P1 / 优化 / 采样率归一）

**证据**：
- 三级半带（`ColorModule.cpp:466-471`），注释「8× 沿用原有抗混叠设计：旧 Heat 驱动 10 时，4× 的折返实测 −56.7 dB」（`:459-461`）；规格 2026-09-24 夜间修订「Heat 4× → 8×：Heat = 100（驱动 10）时 Tube 曲线第 19 次谐波在 4× 域折返」；v0.5 段「已知现象：44.1 kHz、Heat 100 时 18 kHz 正弦的折返约 −56.8 dB」。
- 现行映射：驱动 `1 + h`（`heatDriveRange = 1.0f`，`:78,364-368`）、残差比例 `0.25h`（`:79,655`）、Side 驱动 `1 + 0.5h`（`:81,706`）。
- 倍率与采样率无关：`prepare` 对任何 `spec.sampleRate` 都加三级；44.1k～192k 延迟恒 64（`ColorTests.cpp:1174-1193`）。
- 唯一的混叠测试只在 48 kHz / 10 kHz / −6 dBFS（`ColorTests.cpp:557-610`）。

**机理与实验（记录 F）**：把现行 Mid 曲线 `Tube(x) − x`（drive 2、asym 0.04）的谐波乘 0.25 后按内部速率 R = M·fs 折返：
- 0 dBFS 20 kHz（极端）：8×@48k 最坏 −133.6 dB；**4×@48k −70.6 dB**（第 9 次谐波折到 12 kHz）；2×@48k −45.4 dB（不够）。
- 规格验收点（−6 dBFS 10 kHz）：4×@48k −363 dB，2×@48k −102 dB。
- **4×@96k、2×@192k 与 8×@48k 的内部速率同为 384 kHz，逐项折返数字完全相同**（表中三组行一致）；8×@96k / 192k 的内部速率 768 k / 1536 k 只是把本来就在 −130 dB 以下的分量再压低，没有可听收益，却让 Heat 的成本随采样率线性上涨（96k ×2、192k ×4）。
- 抽取滤波器阻带（−55 / −70 / −75 dB）的泄漏路径核过：0 dBFS 20 kHz 的 2、3 次谐波经各级阻带后 ≤ −139 dB。
- 规格里「44.1 kHz 18 kHz 折返 −56.8 dB」是驱动 10 时代的数字，按现行映射为 −133.6 dB，档案该句已过时。

按各级抽头对数（由延迟 49 / 60 / 64 与记忆 133 反推：各级上+下长度 198 / 90 / 66，例如 115+83、51+39、39+27）估算每个 1× 样本的 pair-MAC：第 1 级 50、第 2 级 46、第 3 级 68 → 去掉第 3 级省 FIR 41 %，tanh4 从 8 个样本减到 4 个（−50 %），整条 Heat 湿路约 **−45 %**；再去第 2 级（192k 用 1 级）约 −70 %。需 `tools/perf` 实测。

**修法（M）**：
- **方案 A（无损）**：`prepare` 按采样率选级数使内部速率 ≈ 352.8～384 kHz：fs ≤ 50k → 3 级（不变）；50k < fs ≤ 100k → 2 级（前两级参数不变）；fs > 100k → 1 级。延迟补齐：2 级 60、1 级 49（`:507` 注释、Limit Clip 两级 60），在湿路输入 `heatInputScratch` 前加一条 `BlockDelay`（4 或 15 样本），使 `getLatencySamples()` 恒为 64、干湿逐样本对齐；`heatPrimeLength = 256` ≥ 记忆 + 补齐延迟，预热逻辑不变；`proxyAlignment = 64 − 49` 不变；`coefficientUpdateInterval` 的过采样域计数改为 `2 × oversamplingFactor`，保持「每 2 个 1× 样本更新驱动量」；`heatResidualScratch`、`processTubeSegments` 已按 `oversamplingFactor` 写，无需改。
- **方案 B（更省）**：所有采样率都 2 级（48k 也省 45 %），代价是 44.1/48k 输出改变（差别在 −70 dB 以下、规格点 −200 dB 以下）与 GLAZE 45 点 Heat 标定表需复核（残差幅度不变，只有 −100 dB 级折返与抽取纹波变化，预计在标定容差内）。

**changes_output**：方案 A：44.1/48k 逐位不变，88.2k 以上改变（差别 ≤ 现有 48k 的折返水平）；方案 B：全部改变。

## R3-04 Heat 1× 热路径两处逐位不变的小优化（low / P2 / 优化）

**证据**：
- `prepareHeatInput`（`:1338-1364`）对 Mid / Side 各走一次标量 `processBiquad`，而 Tone（`:900-939`）、侧链高通（`:985-1017`）、分频（`:1054-1114`）都已在 ARM / x64 上用 `StereoBiquad` 两声道打包，且有「打包与标量逐位相同」的测试（`ColorTests.cpp:2190,2228`）。

**changes_output**：否。**验证**：现有「idle skipping bit-identical」「stereo L = R == mono」「packed == scalar」三组用例即为证据；再加一次 `countBitDifferences` 对照修改前后的整段输出（同输入、同参数剧本）= 0。

## R3-05 Heat = 0 时近似残差链常驻运行（low / P2 / 优化）

**证据**：`proxyWanted = heatDcProxyEnabled && heatSmoothed.getTargetValue() == 0`（`:1569`），每块都跑 `runHeatProxy`（`:1606-1612`）：第 1 级半带上采样 + `proxyTube`（tanh）+ 下采样 + 对齐延迟（`:1447-1478`）。按抽头对数，第 1 级上+下 ≈ 50 pair-MAC/样本 + 2 次 tanh4，约为满载 8× 链的 30 %；文档实测默认（Heat 0、Glue 关）Color 仍 0.11 %（M2 Pro）。目的只是让 5 Hz 直流阻断的状态在 Heat 重开时「与一直在跑」接近（规格 v0.5 第 3 条已接受 −90.6 dBFS 级差别）。

**changes_output**：是（Heat 重开后几十毫秒，≤ 已接受量级）。**验证**：上述用例 + `tools/perf` 默认参数前后。

## R3-06 湿路比例未经 64 样本延迟对齐（low / P2 / 设计一致性）

**证据**：规格 2026-09-24 实现细节「响度补偿用『驱动该样本时』的 Heat 值（经 64 样本延迟对齐）」；实现里 `heatDelayedScratch`（`:1634`）用于 makeup（`:1650`）与 `useProxy` 判断（`:1657`），但湿路比例 `mix = heatMixSmoothed.getNextValue()`（`:1651`）是当前值、未延迟；`heatMixSmoothed` 的目标 `0.25 × heat/100`（`:655`）与 `heatSmoothed` 同为 20 ms 线性平滑。Heat 0 → X 时，湿路淡入从本块第 1 个样本开始，而该样本的残差是 64 样本前（Heat 仍为 0 的驱动量）生成的；X → 0 时反之。

**机理与影响**：残差的驱动量与其混入比例错位 64 样本（48k 下 1.33 ms），只在参数斜坡的头尾各 64 样本存在，幅度是 25 % 残差 × 斜坡步长，不可闻；但 `useProxy` 依赖 `mix <= 0`，与延迟后的 Heat 值组合出「驱动量为 0 但仍在淡出」的 64 样本窗口，逻辑上多一种状态。

**修法（S）**：把 `mix` 也过 `heatValueDelay`（或直接由 `heatDelayedScratch[i]` 算 `0.25 × h/100`，删掉 `heatMixSmoothed`，两者本来就是同一斜坡的线性函数）；`isHeatWetIdleCondition`（`:1330-1336`）与 `BlockStats.heatDrive`（`:1654`）同步改。**changes_output**：是（仅参数斜坡期间）。**验证**：「heat on / off crossfade has no jump」（`ColorTests.cpp:1239`）与「heat stays gradual」（`:1320`）照跑；新增断言：Heat 阶跃后输出与「延迟 64 样本的输入」的差在前 64 个样本精确为 0。
