## 2. 逐条判决

### R4-01 · 守护把加宽几乎全部回收 —— **confirmed**（high · P0，修法方向对、两处细节要改）

- **代码证据**（与报告一致，逐行核过）：`ClayModule.cpp:1129` `bound = max(localPeak, max(τ·env, F))`；`:1134` `exceeds = |wet| > bound`；`:1151` `limit = (bound − sgn(d)·x)/|d|`——k 是 ±W 窗最大值样本时 localPeak = |x(k)|，稳态密素材下 τ·P = P − 6 dB < E（粉噪 1 s 最大值只比 16 ms 最大值高约 2 dB），于是 B = |x|、limit = 0；`:61/943` 释放 100 ms（`releaseStep = 1/(0.1·fs)`）；`:1197-1221` 前瞻最小 → 线性释放 → 滑动平均，g ≤ g_req。密素材每 2W + 1 样本平均一个「自窗最大」样本（概率 1/(2W+1)），100 ms 释放追不上。压力格 `:1152` 只量 `max|y|/B`，对「效果丢了多少」天然失明。
- **不是已定取舍**：ADR-014 决定 1 写「手动设置在峰值瞬间也会让一点」、后果写「效果在峰值处会被让掉一部分」，预设的是「峰值处、一部分」；实测是全程 92 ～ 100 % 样本、效果剩 4 ～ 13 %，与预设量级不符，属 ADR-014 的假设错误，不是 Max 拍板接受过的结果。根治修订 §1 表第 14 行加宽一栏原本就写「交给先试后用」。T-024 REPORT:130 早看到「加宽 +1 dB 时 100 % 的样本 g < 1」但只当性能备注——报告引用无误。
- **测试为何没抓到**：`ClayTests.cpp:266-275` quietScale −44 dB、`:382-395` measureSide 压到地板下、`:1594` 守护上界用例把 (60 Hz, 300 Hz a=1, +3 dB) 只当阳性对照、`:1694` 稳态用例只断言「守护动了」；`ClayGlazeTests.cpp:1471` 只断言 `s.clayWidthDb > 0`。均核实。
- **文案**：`HelpText.cpp:414`「峰值处自动让一点」、`:437`「任何状态下峰值处都会自动让一点」、`:463`「修坯从不让峰值变高」——与实际不符，核实。
- **修法 A' 判定**：方向正确（③ 的增量在 M/S 解码后是可分离的加性项 ±delta；根治修订 §1 的原意；不改延迟与管线顺序；不守护 ③ 的峰值风险由 widthPeakCostDb + 相关度上限 + 自动 ≤ +1.5 dB 兜——我的数据：窄歌 +1.5 dB 不守护时峰值只 +0.04 dB，宽歌手动 +3 dB 也只 +0.53 dB）。ADR-014 放弃项「守护只管自动态」说的是按模式开关，不是按级拆分，A' 不与之冲突；但它把决定 1 的「|输出| ≤ B」改成「|输出 − ③增量| ≤ B」，**必须报 Max 点头**，报告这一点写对了。两处必须修正：
  1. **−0.0 逐位**：报告写「delta 为 0 时 x + 0 逐位 = x」——错。IEEE 下 (−0.0) + (+0.0) = +0.0，`ClayTests.cpp:280-301` 的特殊值素材含 ±0（含 256 个交替 ±0），`:796 / :1074 / :1379 / :1721` 用 countDifferentBits 断言逐位纯延迟。第 6 步必须写成 `delta != 0.0 ? guarded + delta : guarded`（沿用现有 `gain >= 1.0 → io = y` 的分支写法），不能无条件相加。
  2. **Inf**：delta 不能在所有分支都按 `wideSide − monoSide` 算——shelfWasIdle 且 ①/② 在作用时，±Inf 样本会得 Inf − Inf = NaN。写成 `shelfWasIdle ? 0.0 : wideSide − monoSide`，并在纯延迟分支（`ClayModule.cpp:707-712` 的 `continue`）显式置 0。
  - 其余照报告：`processed = !sameBits(x, y12) || delta != 0.0`（isPassThrough 语义不变）；Frame 加 delta 建议用 float（环长 G + 1，24 字节一格，T-024 的缓存足迹不翻倍；delta 是小增量，float 量化远在可闻之外，且 widthDb ≠ 0 时输出本来就变）；旁通淡化 `delta·(1 − bypass)`；processMono delta 恒 0；`guard_compare` 思路的新旧逐位对照必须把 widthDb = 0 的全部场景（含特殊值、随机块长）跑一遍 0 差异。
  - 文档：ADR-014 决定 1 与后果、`ClayModule.h` 文件头「④」一段、HelpText 三处、根治修订 §6「三态都生效」一句都要改。
- **严重度 / 优先级**：high / P0 维持——v0.1.8.5 已装的功能「加宽」在正常电平下等于没有，且界面显示在做；改动只影响 widthDb ≠ 0 的输出，22 首门槛里自动加宽从未触发（R4-04），GLAZE 0 与全部现有逐位契约不变，回归面小。**前提是 Max 点头**（改 ADR-014 一条假设）。

### R4-03 · 守护深度回收手动项时无指示 —— **confirmed**（medium · P2；修法的度量要换）

- 核实：`GlazeTypes.h:261-262` Status 只有 clayPhaseGuardActive / clayWidthGuardActive；`ClayModule.h:115-122` PeakGuardStats「只给测试 / 离线工具」；`GlazeController.cpp:1757-1765` clayScaleCanAct 只看自动项、`:2546-2555` 压力监测只在自动项可缩时跑（ADR-014 决定 3a 明写「只在『自动』项里确有可缩的量时才监测」——手动项没反馈是有意的，但**没指示**不是拍板过的）；`:2680-2681` 发布的两个保护灯与峰值守护无关。
- 我的数据让它更重：手动收单 120 Hz 在低音侧声道与中声道不相关的素材上 78 % 样本 g < 1、效果 −22.6 → −4.9 dB；手动低切 25 Hz 在宽密素材上 59 %、−17.4 → −8.6 dB；界面全绿。
- **修法不能照报告做**：报告用「g < 1 样本占比 > 25 %」当标志。ADR-014 3a 已论证回收量类的度量「改动量大、超出却很小时会夸大伤害」而弃用；而压力格（max|y|/B）又对「效果丢了多少」失明（收单那行压力只 0.032 dB）。要指示的是「你拧的量剩多少」，正确度量是保留比 Σ(g·d)² / Σd²（R4 EXP-A 的 retainDb），在守护第 6 步按 10 ms 代价格顺手累加 d² 与 (g·d)²（各一次乘加，逐位契约不受影响——只是统计），随 PressureReport 一起交给编排器做 300 ms 平滑，手动 / 自动都报；保留比 < 50 % 持续 ≥ 1 s → `Status::clayPeakGuardActive`，灯琥珀、气泡「峰值守护回收中」。与 R9 协作、排在 A' 之后（A' 落地后加宽不再进这个统计）。
- 严重度 medium 维持；P2 维持（UI 新功能，不是今晚必做）；但它的价值取决于第 4 节第 1 条 Max 怎么定。

## 4. 报告漏掉的（missed）

1. **同一机理对手动收单一样成立，A' 修不到**：② 的增量 ∓S_low 在局部峰值样本上与 x 同号的概率约一半，就足以让 g 常年 < 1。我的素材：收单 120 Hz a=1，S/M −10 dB 且侧声道与中声道独立 → 78 % 样本 g < 1、侧声道 < 100 Hz 能量只减 4.9 dB（标称 22.6 dB）；宽粉噪 45 %、−9.4 dB（标称 −23.1）。R4 的 EXP-C2 用相关低音得到「合理」，是素材相关的结论。自动收单已删（ADR-015），手动收单正是用户在宽而不相关的低音（kskdhjf 那类，ρ 0.03）上才会拧的，也正是守护回收最狠的地方。要报 Max 一起定：② 是否也拆出守护（它是线性相位，只削侧声道低频，抬峰值最多 |S_low|），还是接受并靠 R4-03 的指示。缩短释放不是出路（第 1 节对照实验）。
2. **A' 的两处逐位陷阱**（第 2 节 R4-01 已写）：`guarded + 0.0` 把 −0.0f 变 +0.0f，会让 `ClayTests` 的 ±0 特殊值逐位用例失败；shelfWasIdle 分支下 `wideSide − monoSide` 对 ±Inf 得 NaN。报告的「x + 0 逐位 = x」是错的。
3. **压力格对「效果丢失」结构性失明**：压力 = max|y|/B 只量「本会抬多少」，与保留比无关（收单那行压力 0.032 dB、效果丢 78 %）。A' 之后压力反馈仍看不见手动收单 / 低切被回收，R4-03 若做，度量要用保留比，不能沿用压力格也不能用 g<1 占比。
4. 小项：R4-01 表里「宽密粉噪 +3 压力格 0.131 dB」是素材相关的数，我的宽粉噪是 0.50 dB（> 0.2 门槛）——意味着在高频很宽的歌上，若自动加宽真触发（它只在窄歌触发，所以实际不会），压力反馈会先把它降档而不是失明；不改变任何结论，只提醒别把 0.13 当常数写进档案。

## 5. 建议主进程的顺序（对 R4 第 7 节的修正）

1. 报 Max 两句：「加宽被守护回收 95 %，改成守护只管低切 / 收单」+「手动收单在不相关低音上同样被回收到 1/4，要不要一起拆」——两个点头一起拿。
2. R4-01 A'（含第 2 节两处修正）+ R4-02 加宽用例，同一实现代理；widthDb = 0 全场景逐位对照 0 差异是验收门。
3. R4-02 其余两条特性用例按夹具记录现值。
4. R4-03（换度量）排 R9 批次；R4-04 待 Max；R4-05 不做；R4-06 随 ADR-015 写档定。
