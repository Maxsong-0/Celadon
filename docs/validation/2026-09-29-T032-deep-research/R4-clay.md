## 0. 一句话结论

Clay 的数学（低切 / 线性相位收单 / 高架）、延迟对齐（D + G）、分频点分摊预热、块长无关、反相判定、压力反馈时基、极端输入与实时安全都核对无误（第 2 节）。
**真正的问题只有一条，但很大（R4-01，P0）**：峰值守护（ADR-014 第④级）的界 B = max(E, τ·P, F) 在干路 ±8 ms 局部峰值那个样本上没有任何余量（B = E = |x|），所以任何「在峰值处同向增加」的处理在那个样本上 g_req 恰为 0，再经 100 ms 线性释放——**加宽这一级在正常电平（> −40 dBFS）下被回收约 95 %**：真 ClayModule 实测手动 +3 dB 只剩 +0.36 dB、纯侧声道内容 +3 dB 实际 0.00 dB，而状态 / 指示灯 / 气泡都显示「加宽 +3 dB 在处理」；压力反馈也看不到它（0.01 ～ 0.13 dB < 0.2 dB 门槛）。仓库里所有机制用例把素材压到 −44 dB 地板之下，正常电平下的效果从没被测过。修法：把③加宽的增量从守护的 y 里拆出来、绕过守护后再加回（守护只管①②，与根治修订第 1 节「加宽……交给先试后用」的原意一致）。其余 5 条都是 P1 / P2。

## 3. 发现（按 优先级 × 置信度）

### R4-01 · 峰值守护把加宽几乎全部回收（局部峰值样本零余量）· high · P0

- **类别**：算法 / 设计缺陷（功能失效 + 状态与实际不符）。
- **文件与行号**：`Source/dsp/ClayModule.cpp:1129`（B = max(E, τP, F)）、`1131-1134`（exceeds）、`1149-1152`（g_req = (B − sgn(d)x)/|d|）、`1197-1221`（100 ms 释放 + 3 ms 滑动平均）、`1224-1237`（输出）；`ClayModule.h:24-35`（契约「只回收修坯的改动量……任何时刻都不会比不修坯更响」）；`tests/ClayTests.cpp:266-275`（quietScale = −44 dB）、`382-395`（measureSide 把素材压到守护地板下）、`1594`（守护用例把加宽 +3 dB 只当阳性对照）、`1694`；`tests/ClayGlazeTests.cpp:1471`（GLAZE 60 用例只断言状态值 `s.clayWidthDb > 0`，不量输出）；`Source/ui/HelpText.cpp:414 / 437 / 463`（「峰值处自动让一点」「修坯从不让峰值变高」）；ADR-014 第 26 行（「手动设置在峰值瞬间也会让一点」）；根治修订第 14 行（「加宽……影响小，交给先试后用」）；T-024 REPORT 第 130 行（「加宽 +1 dB 时 100 % 的样本 g < 1」——当时只当性能备注）。
- **证据**（真 ClayModule，48 kHz / 512，20 s，EXP-C；侧声道 > 4 kHz 能量增益，延迟对齐后 out / dry）：

  | 素材 · 设置 | g < 1 样本 | 最小 g | 压力格平均 | 标称（同素材 −44 dB） | **实际** |
  |---|---|---|---|---|---|
  | 宽密粉噪 −12 dBFS · 手动 +3 dB | 99.89 % | 0.000 | 0.131 dB | +2.94 dB | **+0.36 dB** |
  | 同上 · +1.5 dB | 99.89 % | 0.000 | 0.055 | +1.47 | **+0.17** |
  | 同上 · +0.5 dB | 99.89 % | 0.000 | 0.016 | +0.49 | **+0.05** |
  | 窄（S/M −14 dB）密 · +1.5 dB | 99.75 % | 0.000 | 0.011 | +1.47 | **+0.22** |
  | 纯 S 16 kHz 幅度 0.5 · +3 dB | 99.90 % | 0.000 | 3.09 | +3.00 | **0.00** |
  | 纯 S 16 kHz 幅度 0.5 · +0.5 dB | 99.90 % | 0.000 | 0.52 | +0.50 | **0.00** |

  独立模型（EXP-A）在同一组素材上给出完全相同的数字（0.36 / 0.17 / 0.05 / 0.22 dB），说明机理判断正确。
- **机理**：E(k) 是干路两声道 |x| 在 [k − W, k + W] 的最大值。凡是本身就是这个窗最大值的样本 k*，B(k*) = E(k*) = |x(k*)|（τP ≤ E、F 远小）。加宽让 L = M + γS 在 S 与 M 同号处变大——而 |L| 成为局部最大值时 S 与 M 几乎总是同号——所以 |y(k*)| > B 且 g_req = (B − |x|)/|d| = 0/|d| = **0**，与增加多少无关（+0.5 dB 与 +3 dB 一样）。宽带信号每约 16 ms 就有一个这样的局部最大值，而 g 从 0 线性回到 1 要 100 ms，于是 g 从不回到 1（平均 0.10 ～ 0.14），加宽只剩 5 ～ 14 %。压力格量的是 max|y|/B（0.01 ～ 0.13 dB），远低于 0.2 dB 门槛，所以压力反馈不会降档、界面照亮「宽」灯并显示 +3 dB。自动加宽（≤ +1.5 dB）同样命运，只是至今没有真歌触发过它（R4-04）。低切与收单是「去掉能量」，越界主要来自相位错开，回收比例小得多（EXP-C2：收单 −20.4 → −20.4 dB、低切 25 Hz 对 15 Hz 次声 −9.0 → −7.8 dB），守护对它们是合理的。
- **修法**（推荐 A'：拆分增量，守护只管①②，管线顺序与延迟不变）：
  1. `processStereo`（`ClayModule.cpp:697-725`）：算出 `wideSide` 后，令 `sideDelta = wideSide − monoSide`（shelfWasIdle 时精确 0）；`y12 = delayedMid ± monoSide`；旁通淡化只作用在 y12（`y12 += (dry − y12)·bypass`）与增量（`delta = sideDelta·(1 − bypass)`，bypass ≥ 1 → 0）；`io` 写 y12，另按段暂存 `deltaL = +delta`、`deltaR = −delta`（`std::array<double, 64>`，与 dryLefts 同法）。
  2. `PeakGuard::Frame` 加 `std::array<double, 2> delta`（或 float）；`process` 多收一个 `const double* const* delta`；`processBlock` 第 1 步存进环；第 6 步输出 `out = guarded + atJ.delta[c]`（delta 为 0 时 x + 0 逐位 = x，现有契约不变）；`processed = !sameBits(x, y12) || delta != 0`（isPassThrough 语义不变）。
  3. 单声道 `processMono` 不涉及③，delta 恒 0。
  4. 逐位契约保留：widthDb = 0 → delta 精确 0 → 与现版逐位相同；三项为 0 → 逐位纯延迟 D + G；旁通 → delta 0。
  5. 文档：ADR-014 补记「守护只管①②；③加宽的峰值风险由先试后用代价（widthPeakCostDb）+ 相关度上限 + 最多 +1.5 dB 控制（根治修订 §1 的原意）」；`ClayModule.h` 文件头与 HelpText 三处文案改掉「任何状态下峰值处都会让一点」。
  - **放弃的替代**：给 E 加 0.5 ～ 1 dB 余量（B = max(E·10^(ε/20), τP, F)）。EXP-A：ε = 1 dB 时加宽全部恢复（2.94 / 1.47 dB），但低切守护同时被削弱——低音密素材 25 Hz 低切 g < 1 从 80 % 降到 31 %、压力格 0.49 → 0.10 dB，压力反馈不再降档，正是 ADR-014 要防的 WTF 场景。按级拆分没有这个副作用。
- **改后输出是否逐位不变**：否（只在 widthDb ≠ 0 时变，这正是修复目的；widthDb = 0 逐位不变）。**属于修正 ADR-014 的一条假设（「让一点」），建议主进程报 Max 点头后落地。**
- **验证**：
  - 新用例 ClayTests「−12 dBFS 宽粉噪 + 手动加宽 +3 / +1.5 / −3 dB：延迟对齐后 > 4 kHz 侧声道能量增益 = widthDb ± 0.3 dB」，阳性对照 = 现版本给 +0.36 / +0.17（必须失败）；「纯 S 16 kHz 幅度 0.5 + 3 dB：输出侧声道 +3.0 ± 0.1 dB」（现版本 0.00）。
  - 现有「峰值守护上界」用例（`ClayTests.cpp:1579-1660`）改为对①②路断言：params 的 width 置 0（或断言 |out − delta| ≤ B）；阳性对照仍由低切 60 Hz + 收单提供。
  - ClayGlazeTests GLAZE 60 用例（`1436-1520`）加一条「自动链输出的高频侧声道能量比全关高 ≥ 0.6 × widthDb」。
  - widthDb = 0 的全部现有用例与 T-024 `guard_compare` 思路（新旧并排、随机块长、怪值）逐位对照：必须 0 差异。
- **工作量**：M（2 ～ 3 h 含测试与文档）。**置信度**：0.9。

### R4-02 · 测试缺口：三级经守护后的正常电平效果没有任何用例 · medium · P1

- **类别**：test-coverage。
- **文件与行号**：`tests/ClayTests.cpp:266-275`（所有机制用例统一压到 −44 dB，「量到的是③本身的增益（ADR-014）」）、`382-395`、`850-885`、`1203-1224`；`tests/ClayGlazeTests.cpp:1436-1520`（只断言 Status，`1471`）；`tests/ClayGuardTests.cpp` 全部是 ClayGuard 单元（不含守护）。

### R4-03 · 守护深度回收手动项时没有任何指示 · medium · P2

- **文件与行号**：`ClayModule.h:115-122`（PeakGuardStats「只给测试 / 离线工具」）；`GlazeTypes.h:257-265`（Status 只有反相 / 宽度两个保护标志）；`GlazeController.cpp:2676-2687`；`GlazeController.cpp:1757-1766`（压力反馈只监测「自动」项）；`HelpText.cpp:414`。

### R4-04 · 自动修坯在真歌上基本不做事，价值待 Max 重新拍板 · low · P2

- **类别**：设计 / 标定（不是代码缺陷）。
- **文件与行号**：`docs/validation/2026-09-28-T022-replay-gate/gate4-snapA-check.txt`（22 首 × g35 / g70：「自动」对「同决策重放·关」dInPk / dLUFS 在 17 首上恰为 +0.000 —— 逐位就是关；只有 emotapes / fule / somggggg / somggggg_mp3 / woqu 有差别，全是低切）；`trial-3songs-metrics.csv`（三首 g70 自动行成品末尾 lowcut 0 / mono 0 / width 0；WTF `clay_pressure_scale` 0.00 = 第一遍就被压力反馈降到 0）；`docs/validation/2026-09-26-clay/render/findings.md:33`（「加宽在六首歌上都没有触发」）；`GlazeConstants.h:243-244`（真次声 need 从 −40 dB 起）、`254-256`（加宽 need 从侧中比 −10 dB 起、上限 1.5 dB）；`GlazePlanner.cpp:1134-1135`（自动收单恒中性，ADR-015）。
- **机理**：ADR-012 把低切限定到 < 16 Hz 的真次声（成品母带里几乎没有）、ADR-015 删了自动收单、加宽只给高频侧中比 < −10 dB 的窄歌（22 首无一首），密歌又被压力反馈降到 0——每一步都有理，合起来的结果是：所有用户都付 23 ms 延迟 + 约 0.14 ～ 0.2 % CPU + 学习期的候选运算，换来的自动动作只在 Max 自己的粗混上出现。而且 R4-01 说明「加宽」这一级即使触发也基本听不见，没人试听过它真正的效果。

## 4. 回答任务里的几个专项问题

- **低切 / 线性相位收单 / 加宽三级的数学与延迟对齐（D + G）**：无误（第 2 节）。唯一的口径差别：低通 −3 dB 点在 0.948 fc 而不是 fc（规格写「约在 fc」），互补高通在 fc 处 −9.88 dB 与规格 −9.9 一致。
- **峰值守护的窗口与压力反馈**：窗口 W = 8 ms 对低切的相位前移论证成立（2fc 处 +78°，≤ 5.4 ms）；但界在局部峰值样本上零余量的结构性后果（R4-01）没有被任何数据量过；压力反馈的时基正确、对加宽失明（R4-01 顺带解决）。
- **分频点切换的分摊预热**：序列连续、追赶时间 2(L − 1)、单声道记账一致；无问题。
- **反相检测**：ADR-015 起只提示；判定逻辑、块长无关拆分、资格期容差都无误。
- **先试后用逻辑的漏洞**：① 只看聆听窗口——ADR-014 用压力反馈补上，但压力反馈对加宽失明（R4-01）；② 候选跑在链入口原始信号上，而 Clay 在 Balance 之后：Balance 的最小相位 EQ 会改变低频相位，代价可能与真实位置有偏差——守护兜底，未量化，不列为发现；③ P99 top-8、块对齐、有效门都正确。
- **REPORT 6.2 / 6.4 逐位不变的优化能不能今晚做**：6.4 能做但不值得（R4-05 实测 ±3 %，clang 上还可能变慢）；6.2 不建议今晚做。
