### R4-01 · A'：守护只管①②，③ 的增量在守护之后加回

**改动位置**（`Source/dsp/ClayModule.cpp`）

- `processStereo<widthActive>`（`:594-811`）：①② 的输出 y = M_d ± S'（旁通淡化 `y += (dry − y)·bypass` 照旧作用在它上），
  写回 io；③ 的高架只用来算增量：`shelfWasIdle` 时 δ 显式取 0（不算 S'' − S'，±Inf 不会变 NaN），否则 δ = HS(S') − S'；
  bypass ≥ 1 → 0，0 < bypass < 1 → ×(1 − bypass)，bypass = 0 不乘；`static_cast<float>` 后按段暂存 deltaL = +δ、deltaR = −δ
  （`std::array<float, 64>`，与 dryLefts 同法），整段 δ 全为 0 时交给守护的是 nullptr。①② 都不作用（没低切过、a = 0）时 y 逐位取
  纯延迟线——与「三级都不作用」原来的分支相同，只是条件里不再要求高架直通：③ 在作用时守护看到的 y 与干路逐位相同、不动作，
  输出 = 干路 ± δ（要是这时也走 M/S 往返，(L + R)/2 + (L − R)/2 的舍入会当成 y − x 送进守护：局部峰值样本上一个 ulp 的越界就让
  g_req 变 0，守护白白动作，统计与代价格也就不再与加宽无关）。
- **按段两份**（第二任接续者 `85a7296`，任务书没有，核过保留）：`process` 在段首看 `widthIdle()`（高架系数逐位直通且状态为 0）。
  成立时走 `processStereo<false>`：整段不碰③（不跑高架、不算 δ、不碰 δ 数组），逐样本做的事与 T-032 之前相同；否则走 `<true>`
  逐样本判断。段首成立则整段成立（系数只在 64 样本网格点换，段不跨网格点；直通时不跑高架，状态一直是 0），两份对这种段输出逐位
  相同（第 5 节变异 M0 / 第 4.3 节强制同一条路的并排对照）。这一手顺带把核验第二处细节（Inf − Inf）在 widthDb = 0 的段里从结构上
  排除了；`<true>` 里的显式 0 照样保留（变异 M0 + M2 证明它在 `<true>` 里是必需的）。
- `PeakGuard`：`Frame` 加 `std::array<float, 2> delta`（一格 16 → 24 字节，T-024 的缓存足迹不翻倍）；`process` 多收
  `const float* const* delta`（nullptr = 本段全为 0；单声道恒为 nullptr）；`processBlock<声道数, withIncrement>` 两条路：
  - 不带 δ（本段 δ 全为 0、且本段要输出的样本都晚于最近一个 δ ≠ 0 的样本）：逐样本的运算与 T-032 之前相同（`if constexpr` 去掉的只有
    δ 的部分）；
  - 带 δ：第 1 步把 δ 存进环、记 `lastIncrement`；第 6 步输出加回：g 精确为 1（快路与全速的 gain ≥ 1）时
    `plusIncrement (y, δ) = δ != 0 ? float(double(y) + double(δ)) : y`，g < 1 时 `float(δ != 0 ? guarded + δ : guarded)`
    （混合那一行的表达式原样保留，乘加融合与否的判断不变）。δ 不参与 E、P、B、g_req、代价格与统计。
  - 两条路之间切换时的正确性：带 δ 那条路这一轮的起点记在 `incrementsFrom`；更早的格是不带 δ 那条路写的（那些段 δ 全为 0，格上的
    δ 是旧值），输出时按 0 算。没有这一条（变异 M6）单元测试看不出来（差值在 1e-6 以下），并排对照抓得到（第 5 节）。
- `hasProcessedInRing`（`ClayModule.h:263`）= max(lastProcessed, lastIncrement) ≥ sampleCount − (G + 1)：任务书的「processed 含
  delta != 0」，拆成两个样本号是为了不在不带 δ 那条路里多一次比较；isPassThrough 语义不变（等 δ 走出前瞻环才报真）。
- `processMono`：交 nullptr。

**逐位契约**：widthDb = 0（高架逐位直通且无余振）→ 每段走 `<false>` + 不带 δ 的守护 → 与 e6b445b 逐位相同（第 4 节，唯一的
例外是 NaN 的符号位）；三项为 0 → 逐位纯延迟 D + G（全套里的逐位用例照过）；完全旁通 → δ = 0、y = 干路。

**行为变化（只在 widthDb ≠ 0）**：

- 加宽在正常电平下按标称值生效（上表）；守护统计、代价格与加宽无关（同一素材加宽 0 / +3 dB 两个模块逐块比：g < 1 样本数、
  最小 g、每块代价格逐位相同）。
- 加宽不再受界 B 约束：宽素材手动 +3 dB 时峰值会高一点（守护上界用例只记录不断言：两声道独立粉噪 + 30 Hz 的「母带式」素材上
  加宽后的输出相对界最多 +1.04 dB，高频很窄的谐波对 +0.08 dB；核验的数据：宽粉噪 +3 dB 不守护时峰值 +0.53 dB、自动 ≤ +1.5 dB
  只在窄歌触发、峰值 +0.04 dB），由末级限幅器与「先试后用」的 widthPeakCostDb 兜。
- 加宽开着时输入里的 ±Inf：那一个样本 δ = Inf − Inf = NaN，输出 NaN（改前那一个样本是 ±Inf，之后到下一个网格点前两边都是 NaN）。
  没有契约覆盖，链的 NaN 保护照样整体 reset。
- 旧工程里手动加宽 ≠ 0 的：升级后真的变宽（原来只剩一成），存下的校准仍按有效使用（参考条件的手动参数哈希不变），见待 Max。

**文档**：`ClayModule.h` 文件头④一段（为什么③ 不进守护、改动、契约、放弃的替代）、`PressureReport`、`isPassThrough`、实现要点、
`PeakGuard` 各成员的注释；`ClayModule.cpp` 守护一节开头的时序说明与快路说明。ADR-014 由主进程写（草稿见第 10 节）。

## 8. 待 Max / 待认领

**待 Max**

1. **点头 ADR-014 决定 1 的修改**：「|输出| ≤ B」→「|输出 − ③ 增量| ≤ B」（守护只管低切 / 收单）。研究与核验都判为 ADR-014 的

2. **② 收单要不要也拆出守护**（核验漏项）：同一机理（界在局部峰值样本上零余量）对手动收单一样成立，A' 修不到。夹具 B（M / S
   各自独立、S/M −10 dB）：收单 120 Hz a 1 标称 −22.6 dB、实际 −5.8 dB（72.9 % 样本 g < 1）；相关的低音几乎不回收（R4 的 wide-bass
   0.03 %）。可选：(a) 也拆出去（② 是线性相位、只削侧声道低频，抬峰值最多 |S_low|，增量同样可分离）；(b) 接受、靠 R4-03 的指示
   告诉用户；缩短释放不是出路（V4 对照实验）。定了以后改夹具 B 的记录值。
3. **可闻变化**：手动加宽 ≠ 0 的旧工程升级后真的变宽（原来正常电平下只剩约一成：+3 dB 只有 +0.3 dB），用户当初若因为「没效果」
   拧大了，现在可能发虚；自动加宽（只在窄歌触发，最多 +1.5 dB）同样到位。建议版本说明里写一句。
4. **校准是否加 Clay 算法版本**：校准参考条件的手动参数哈希含 Clay 三态与手动值，但没有算法版本——手动加宽 ≠ 0 的旧工程存下的

   「Mast 段没有算法版本盐」同一类，要不要加由 Max 定（动 GlazeController / GlazeProfile，不在本线范围）。
5. **R4-04 的重新标定要在 A' 之后做**（核验）：现在试听自动加宽才是真的效果。
