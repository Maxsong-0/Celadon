## 2. 逐条说明

### 2.1 R9-01 ② 带内文字小部件（`PluginEditor.cpp` Canvas 构造、`Controls.{h,cpp}`）

- GLAZE 标题、风格、重新聆听、A / B、等响、监听提示、左下说明、图例 8 个组件挂 `AlignedComponentCache`（`setBufferedToAlignedImage`）。
- **偏离（有意）**：不用 JUCE 的 `setBufferedToImage`。`StandardCachedComponentImage` 贴图是 `drawImageTransformed (scale (comp / image))`
  ——父上下文的默认插值、平移含小数（V9 M-4 的同一个问题），每帧双线性重采样且字发糊。自管版本与它同一套失效规则（`invalidate /
  invalidateAll` 记有效区、只重画作废的部分、设备丢失时整块作废），只把贴图换成 `drawCachedImage`：换回设备像素
  （`addTransform (scale (1 / pixelScale))`）+ `lowResamplingQuality` + `drawImageAt` 整数偏移；图按上下文实际像素比生成，像素比变了
  （同尺寸也算）整张重建。这些组件的状态改动都走 `repaint()`（V9 已核），缓存失效正确；⑭ 核挂上、读缓存、不重画。
- 实测的细节：JUCE 9 的 `Graphics::drawText` 自带 GlyphArrangement 的 LRU 缓存，**贵的是 paint 里的 `getStringWidth / textWidth`**
  （本机的中文字体：图例一次 paint 量 6 次字，约 3 ms），所以图例（6 次量字）、A/B、风格这类在 paint 里量宽度的件收益大；左下说明只有两次 `drawText`，
  直接画本来就便宜，缓存后的贴图在 2× / 4× 反而多 0.11 / 0.72 ms。按任务书保留了它的缓存（Mac 上 CoreGraphics 贴图与画字的相对代价不同），列待 Max。

### 2.5 R9-02 瓷面分层（`Porcelain.{h,cpp}`，`GlazeRenderer`）

- **① 偏离任务书**：不缓存 depth 0 / 1 两张基底图再混合，而是按像素比缓存每个像素里与 GLAZE 无关的量（覆盖率、在哪段渐变、段内位置、
  云斑与微粒，12 字节 / 像素），每次只按当次三档釉色用原算法同一个着色函数着色——底层与原算法**逐位相同**，没有混合的两次 8 位量化；
  代价是多占一半内存（2× 约 1.2 MB、4× 约 5 MB），每像素着色与混合同量级（4× 约 3.3 ms）。
- ② 裂纹：每条的描边轮廓按此刻物理像素比（与软件渲染器 `strokePath` 同一精度）缓存成 Path，渲染时 `fillPath`——软件渲染器上逐位相同；
  CoreGraphics / Direct2D 的 `strokePath` 走原生描边，改成填 JUCE 描好的轮廓后抗锯齿有亚像素差（UI 不在 ADR-013 逐位契约内）。
  积釉 / 釉光 / 反光 / 两圈外环一张覆盖层，帽子（柔影、帽、细上缘）另一张（并成一张时帽沿 13 个像素到 3 LSB，`9752499`）。
  叠放顺序与原算法相同：底层 → 裂纹 → 两张覆盖层 → 去色。没有做「t 增大只追加新裂纹」（V9 驳回）与后台线程（任务书不做）。
- 参照实现 `renderGlaze` 重构成与分层共用的着色 / 绘制函数，调用顺序不变，200 组摘要与 0.1.8.5 逐位相同（1.6）；⑫ 以它为基准。
- 任务书的目标「4× ≤ 5 ms、2× ≤ 1.5 ms」是 107 口径；本机分层 4× 7.2–10.0 ms、2× 3.1–5.0 ms（同机原算法 48–56 / 14–18 ms），
  没有达到绝对值。前任的分项（4×）：着色 3.3、裂纹 3.1、两张覆盖层 1.5 ms——再降要换裂纹的光栅化方式，不再逐位，没做。
- `GlazeKnob` 每次生成在 Debug 版打 `Celadon porcelain <边长> px: <ms> ms`（`9a5e9b7`），供 Mac 上实测。

### 2.7 R9-08 静态背景（`PluginEditor.cpp`）

- 阴影：7 块面板各两层 `DropShadow` 的模糊图（逻辑分辨率，与 `drawForPath` 同一算法）在第一次生成静态背景时做一次、存在 Canvas 里，
  之后每次只贴——与每次现算逐位相同（1.6 摘要；分项程序也逐字节比过）。

  预算好的 256 × 256 查表——逐位相同，2× 35 → 7.4 ms，与瓦片平铺同量级。

- **目标「2× < 60 ms」达不到**，原因是 R9 的估算漏了大头：2× 下 14 层阴影的「贴」（逻辑分辨率模糊图按 2 倍放大、`clipToImageAlpha`
