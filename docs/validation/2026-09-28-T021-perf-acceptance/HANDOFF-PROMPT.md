现状（T-021，2026-09-28 实测，当前源码对 v0.1.6.2，5 个场景各 2 轮，本机 Release，接电源，期间无编译）：
- 规格 01-框架/设计规格-Clay-分析决策与验收.md 第 5 节：48k/512 平均增加 ≤ 0.15 个百分点；192k/32 最坏块增加 ≤ 0.5 个百分点。
- 实测：48k/512 平均 +0.17～+0.30（均值 +0.24）；192k/32 结构性最坏 +0.75～+2.05（均值 +1.38）。整插件绝对值仍小（48k/512 单核 1.2～1.6 %，192k/32 结构性最坏约 19 %）。
- 原因是修坯每块的常态开销，不是尖峰。sample 剖析：ClayModule::PeakGuard::process 约七成，ClayModule::process 主体（低切双二阶、延迟线、M/S）约两成，LinearPhaseLowpass 约一成。
- 修坯中性（GLAZE 0、三项为 0、输出 = 输入逐位延迟）时守护照样全速在算，而这时 g 恒为 1。
- 原预算写于 ADR-014（峰值守护）之前。要达标，守护得便宜约 3 倍（48k），192k/32 那条几乎要零开销。

先问 Max 三选一（附上面的数字）：
A. 改预算为实测口径（例如 48k/512 平均 ≤ +0.3 pp、192k/32 结构性最坏 ≤ +2 pp），注明守护是 ADR-014 的安全网、开销是它的代价；守护优化挂待认领。
B. 改预算，并立刻优化守护：先做「修坯不改输出时守护走快路」，再评估要不要按 64 样本段重写。
C. 不改预算，优化到达标再验收（很可能要重新设计守护）。

如果做优化，约束：
- 守护契约见 Source/dsp/ClayModule.h 文件头与 ADR-014：每个输出样本 |out| ≤ B；输出与块长无关、逐位相同；音频线程 0 分配 0 锁；压力反馈的代价格（每 10 ms 一格、格数与时长）必须照旧上报给编排器。
- y 与 x 逐位相同时 g_req ≡ 1，g 路径（前瞻最小队列、释放环、滑动平均）会收敛到全 1，可以精确重建；E（±8 ms 局部峰）与 P（1 s 包络）依赖干路，不能跳过。
- 快路进出前后的输出要么与一直全速跑的实现逐位相同，要么先证明差异无害并经 Max 同意。
- 次要项，可一并考虑：LinearPhaseLowpass 与守护每 65536 样本一次性精确重算滑动和，192k 约 1.5 µs 尖峰。现在不和 Balance 的 FFT 那一块重合（structWorst64k 只比 structWorst 高 0.05～0.08 pp），但分频点切换后新低通从切换时刻 reset，它的重算网格可能对上。
