## 2. 渲染工具

### 2.1 用法

```bash
# 最快的追踪跑法（标定、扫参用）：每首 × 每个曲风 × 每个聆听起点只跑一遍第一遍，不出成品、不做重放
celadon_render --in <歌曲目录> --out <输出> --glaze 0 --genre deep --bpm 124 --live-trace --live-only [--segments-csv]
# 扫参：改常数必须给标签
celadon_render … --live-trace --live-only --live-constants fourOnFloor.memoryBars=24,newProgramLu=8 --live-tag mb24-np8
# 批量（Jamendo 45 首、合成曲；109 上 PY=~/.venvs/audio/bin/python）
$PY tools/render/calibrate_house.py render-live <工作目录> <celadon_render> -j 12 --tag default
$PY tools/render/calibrate_house.py render-live <工作目录> <celadon_render> -j 12 --tag general --genre general
$PY tools/render/calibrate_house.py analyze-live <工作目录> --auto-labels labels-auto.tsv --labels labels-override.tsv \
    --tags default,general --out <汇总.md> --figures <图目录>
$PY tools/render/calibrate_house.py prep-synthetic <合成曲工作目录>     # 之后照上面两步
```

| 选项 | 说明 |
|---|---|
| `--live-trace` | 每一遍新建的链 `prepare` 之后接实时画像（`setLiveSegmentSink`），逐段写 `live/<标签>/` |
| `--live-only` | 只跑第一遍出追踪（每首 × 曲风 × 起播点一遍，取网格里第一个这样的组合）；GLAZE 0 最快。一首 3～4 分钟的歌约 5 s |
| `--live-constants k=v,…` | 覆盖 `LiveConstants` 任意字段，35 个键（主段模型的 9 个字段带 `fourOnFloor.` / `loudness.` / `passive.` 前缀）；取值范围与 `LiveProfile.cpp` 的 `sanitise` 一一对应，不认识的键、不合法的值、重复的键都报错退出（那边会把坏值悄悄换成出厂值，扫参时不能这样） |
| `--live-model` | 主段模型一律用 `fourOnFloor` / `loudness` / `passive`（默认按曲风：House 三类 4/4 型、通用响度型） |
| `--live-tag` | 输出分组；改了常数或模型却不给标签、或这几个选项离开 `--live-trace`，都报错（免得与出厂常数的追踪混在一起） |

`render-live` 的曲风 `auto` = 各首的子类（deep / tech / melodic → Deep / Tech / Melodic-Progressive），`general` = 一律通用档；输出 `<工作目录>/live/<标签>/`
的 `traces/`、`segments/`（输入端逐小节统计，drop 响度的口径要它）、`logs/`、`run.tsv`（日期、渲染工具与它的 sha256、参数）；同一标签重跑先清掉上一次的。
109 上 45 首 `-j 12` 约 1 分钟一个标签。

### 2.2 做法（要点；全文在 README 与代码注释）

- **接收者 0 分配**：`segmentFinalized` 在音频线程上被调，把段交给 `LiveProfile`，再把「这一段并入之后」的 `MusicProfile` 整份与诊断拷进 64 格定长环形缓冲
  （可平凡拷贝，`static_assert` 钉住）。主线程每处理完一块 `readCommits`，按序号配上快照写一行；序号或 I 对不上记 `anomaly_mismatch`，读落后记 `anomaly_overrun`
  （45 首两组都是 0）。
- **快照取「这一段并入之后」，不是「这一块之后」**：任务书写的是「这一块之后」。一块里有两次提交时（大块长、不连续点截短的段），后者会把同一份画像写到两行上，
  追踪随宿主块长变；平常一块至多一次提交，两者相同（待拍板 3）。
- **收尾补一个 0 样本的块**：链在「下一块」开头才把上一块的 Balance 帧交给分析器（`CeladonChain::process` 第一行）。离线流在最后一块之后就停了，
  第一版追踪在 melodic 1062232 上块长 4096 与 512 的倒数第二段 lowShare 差 0.0005（歌尾少了最后一块的帧）。现在 `finish` 先补一个 0 样本的块
  （同样的宿主时间线接在流的末尾、同样的参数，不加音频），再 `setLiveSegmentSink (nullptr)` 交出歌尾那一截；放在这一遍的状态、成品、指标都读完之后。
  自检里加了对照：不补块时 4096 与 512 的追踪不同、且只差在歌尾。原来的自检合成曲歌尾留 1 s 静音，帧在帧门之下，所以没考到；现在歌尾不留静音。
- **只写一份**：同一首 × 曲风 × 起播点在一次运行里只写第一次跑到的**第一遍**；其余各遍照样追踪、只比较（`__passes.csv`：逐字相同的行数、第一处不同的段与列、
  位级摘要）。第二遍与重放不当写下的那份（2.5 节）。
- **小节号按歌曲的小节网格**：从第 N 小节起播时分析器时间轴从起播样本算 0，第一版的小节号从 1 重新数；现在加回起播样本再定小节（自检「从第 N 小节起播的小节号」）。

## 3. 指标的精确定义（`calibrate_house.py` 的 `live_track_metrics` 文档串是同一份）

- **记号**：I_k = 第 k 小节那一段并入之后的 I（追踪的 `main_level_lufs`；同一小节几段取最后一段）。**第 j 小节播放时决策器手里的 I 记作 held(j) = I_{j−1}**
  （段要等它播完、先试后用的块交齐才定稿，约晚 0.1 s）。I_end = 最后一次提交（歌尾不满一小节的那一截）之后的 I。
- **D**（drop 响度）= 人工标为 drop、已听的小节的段响度能量平均——T-038 analyze 的同一口径（`drop_loudness`，段响度来自同一次运行 `--segments-csv` 的输入端统计）。
- **计入的小节** = 已听（有效音频 ≥ 半小节）且标为 intro / drop / breakdown / outro 之一；transition（交界 ±1）、exclude、没有标签的小节一律不计；整首 exclude 的 7 首不算；
  没有 drop 标签的歌不算 M1 / M2 / M4（45 首里可算 38 首）。**d** = 第一个标为 drop 的小节（交界小节不算，真正的第一个 drop 小节多半是 d − 1）。
- **M1** = I_end − D（汇总取绝对值的中位 / P90 / 最大）。对照 T-038 离线门控画像的 0.15 / 0.60 / 0.92 LU。
- **M2** = 计入的小节 j ≥ 16 上 |held(j) − D| 的逐首中位；汇总 = 各首中位的中位 / P90 / 最大，对规格第 7 节第 1 条「中位 ≤ 0.3、P90 ≤ 1.0」。另给全部小节合在一起的分布（参考）。
  **M2b** 同上，从 j ≥ d + 4 起。
- **M3** = 每段 breakdown（连续标为 breakdown 的小节 a … b）里 max_{k=a…b} |I_k − I_{a−1}|：进入 breakdown 时手里的 I（held(a)）之后、到 breakdown 之后第一小节手里的 I（held(b + 1)）
  为止的最大漂移；第 2 条要 ≤ 0.5 LU（Gain 增量那半条阶段 2 才有）。
- **M4** = δ4 = held(d + 4) − I_end（第一个 drop 的 4 小节并入之后与最终值之差，第 3 条要 |δ4| ≤ 1 LU）；n = 达到并一直保持 ±1 LU 所需的 drop 小节数（最小的 n ≥ 1，使计入的
  j ≥ d + n 都满足 |held(j) − I_end| ≤ 1）。另给以「最后一个 drop 小节并入之后的 I」为终值的同一对（不受尾奏影响）。
- **另给**：各段落计入小节里 m ≥ 0.5 的占比（对照 T-038 出厂离线门控「前奏挡 60 %、drop 过 85 %、breakdown 挡 80 %」）；换歌软遗忘触发次数与小节、无主段时间衰减生效的段数与次数
  （逐首）；c 第一次 ≥ 0.8 时累计并入的有效音频（`active_s`）；held(d) − D（第一个 drop 开始时手里的 I）。

## 5. 看到的问题

1. **前奏当主段、drop 来了收敛慢**（M2、M4 不达标的主因）：35 首有前奏的歌里 28 首一半以上的前奏小节 m ≥ 0.5；19 / 35 首第一个 drop 开始时手里的 I 比 D 低 2 LU 以上
   （例：tech 0107869 −8.31、melodic 0560109 −6.38、tech 0120725 −5.40）。drop 来了之后 S_ref 几小节就跳到 drop 上，但主段域里前奏的质量只按进账遗忘
   （W_mem = 48 小节 ≈ 93 s），能量加权的 I 要 12（中位）～ 42（P90）个 drop 小节才进 ±1 LU。规格第 5 节说这只影响「第一个 drop 头 1～2 s」，实测影响的是之后的几十小节。
2. **低频参考被低音重的前奏定住，drop 被低频门挡掉**：lowRef = 过响度门各段 lowShare 的 P95，前奏播放时前奏都过响度门（它就是此刻最响的），lowRef 取的是前奏的低频占比。
   drop 加了中高频、低频占比反而低，lowShare ÷ lowRef < 0.6 → m = 0。tech 0268597：前奏 lowRef 0.41，drop 的 lowShare 0.13～0.19，127 个 drop 小节被挡 107 个（100 个只是低频门），
   I 停在前奏的 −17.9 LUFS（D = −14.67），到第 92 小节 lowRef 才按参考遗忘（τ 180 s）降到 0.32。同类：tech 0331159（62 / 79 被低频门挡）、deep 0155328（46 / 76）、
   deep 1086373（43 / 63）、melodic 1122111（34 / 167）、melodic 1033705（29 个低频门 + 46 个响度门 / 139）。离线门控用整首的 S_ref 选段再求 lowRef，没有这个问题。
3. **冷启动落在淡入小节上会卡住**：tech 0343381 第 1 小节是 −34.4 LUFS 的淡入（lowShare 0.15），冷启动「以这一段自己为参考」→ m = 1、I = −33.6、lowRef = 0.15；
   第 2～12 小节只有镲（lowShare 0.01～0.06），低频因子 0 → m = 0，I 在 −33.6 LUFS 停了 14 小节（真实前奏约 −17 LUFS），c 0.12。第 13 小节换歌软遗忘触发（比 I 响 6 LU 以上满 20 s），
   质量 × 0.2 之后 lowRef 才放开，第 15 小节 I 跳到 −17.3。
4. **换歌软遗忘在歌尾淡出上误触发**：deep 0944904 第 110 小节、tech 0244162 第 158 小节，都是带低音的淡出（比 I 轻 6 LU 以上、低频因子 ≥ 0.5）累计满 20 s，c 0.99 → 0.57 / 0.67。
   单曲导出时歌尾的 c 下降无关紧要；DJ 连放时等于提前给下一首腾地方，算不算错要按用法定（待拍板 4）。
5. **块长与学习状态**：2.4、2.5 节。只影响频谱证据的末位（这批数据里 I、c 到 4～5 位小数不受影响，m 最多差 0.0003），但违背逐位约束，且阶段 2 去掉学习后这几道门的参考要重新定。
6. **实时段落账的段响度与工具的逐段统计不是同一个数**：例 tech 0343381 第 1 小节，账本 −34.40 LUFS、已听；`--segments-csv` −30.53 LUFS、未听。两者的「有效音频」门参考不同
   （账本用学习区间的 I，工具用整首的 I，README「逐段统计」写过）。D 按 T-038 口径取工具的统计，所以 M1 / M2 比的是「实时 I」对「离线口径的 drop 响度」。
7. **从第 N 小节起播时账本的第一段可能是 1 个样本的碎段**：合成 House 曲从第 33 小节起播，第一段 [0, 1)（锚点取整落在下一个样本），之后各段起点离工具网格 1 个样本。
   不影响追踪的用法，记一笔给账本的维护者。
