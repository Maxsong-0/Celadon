## 0. 结论：够不够好

- **信号通路本身（Limit / Color / Balance / Clay 的 DSP）已经是专业水准**。我逐行读了四个模块的处理代码，没有找到会出爆音、拉链噪声、非规格化数卡顿、采样率写死这类「硬伤」。
- **不够好的地方在控制层（GLAZE 怎么决定增益）和默认档的调校**，而且都是听得见的：
  1. 输出修正 G_trim 的环路结构上不稳，一首歌里段落电平会慢漂最多 ±3 dB（项目自己的追踪已经拍到）。这是我认为现在最该修的一件事。
  2. 预算环在 breakdown 里把退让放回去，下一个 drop 又重新被多压再退，和「非主段增益只降不升」的规则对不上（这条是我这次新看出来的）。
  3. 比交付目标更响的混音没有往下的路（ADR-033 已拍板没实现）；开着等响监听导出，成品会被衰减（T-095 没合）。
  4. 默认 GLAZE 35 % 时，除了推响，音色类动作都在 0.2～0.5 dB 以下，等响对比几乎只剩电平差。
- **最大的阻塞不是没主意，是流程卡住了**：T-093 的 Top 10 过了一个月只落地 1 条（守护族 T-097）。量尺工具 T-096 和离线关监听 T-095 都停在没合的分支上，而 ADR-034 规定工具做完前任何改声音的提案都不立项。

## 2. 默认 GLAZE 35 % 时各模块实际动多少

新实例默认：GLAZE 35 %、风格 Auto、曲风通用、交付标准、推响不刺 Auto 50 %、目标频谱 Auto 35 %（`Source/ParameterDefaults.h:54-78`）。下表按代码里的公式算，「学熟」指置信度到 1；冷启动时再乘 0.35（`Source/dsp/GlazeConstants.h:252`、`Source/dsp/GlazePlanner.cpp:1520-1532`）。

## 3. 逐模块审视

### 3.1 Limit

**做得好的**
- 真峰值检测与电平表同源（8 倍、每相 64 抽头），需求增益先过「前瞻 + 63 样本」的滑动最小，再过两级滑动平均，峰值到达那一刻增益一定到位；硬钳位只是保险（`Source/dsp/LimiterModule.cpp:885-900, 916-924, 1029-1038`；`Source/dsp/LimiterModule.h:80`）。
- 参数与数值都有守卫：非有限值回默认（`LimiterModule.cpp:105-113`），静音尾巴的状态归零不进非规格化数（`:1002-1010`），释放包络用 double。
- 持续、周期稳定的低音会把快释放延长到 4 个周期（30～140 ms），减少低音调制高频（`:1011-1020`）；短过载结束后 35 ms 内按快释放回来，鼓点后面不拖（`:1057-1079`）。

**最该改的**
1. **中等压缩量下其实只有 30 ms 快段在干活**（见 1-11）。`held` 只要有一个样本回到 0.93 以上就算「短过载结束」，慢包络 35 ms 内不许低于快包络（`:1059-1079`）。低音每半个周期都会满足一次，所以慢段长期被架空。我逐段手算：50 Hz、超 Ceiling 2 / 5 / 9 dB 时，周期内增益纹波约 0.3 / 0.5 / 0.5 dB 峰峰（三次谐波约 −42 / −37 / −37 dB）。**比我一开始估的 1～3 dB 小得多，不算急**，但它正是 T-093 R2-03 阶段 1 / R2-06 要量的东西，还没量。
2. **限幅目标恒比 Ceiling 低 0.35 dB**（`:58-61, 890-891`，见 1-14）。这是补 8 倍检测器最坏情况少估 0.30 dB 的经验余量，代价是同样响度多压 0.35 dB。收益小。
- 另：硬钳位没有命中计数（R2-09a）、Clip 活动口径（#18）都还在，归第 1 节。

### 3.2 Color

**做得好的**
- Heat 走「残差」结构：原声不过非线性，只加回 150 Hz 以上的谐波残差，8 倍过采样，低频原样保住（`Source/dsp/ColorModule.cpp:88-98, 1400-1406, 1701-1713`）。
- 高频残差有预算（约 4 kHz 以上的新增谐波不超过干路的 3.5 %），系数按采样率算，只每 32 样本重定一次目标（`:509-512, 1720-1761`）。
- Glue 在 dB 域平滑、释放按最近压缩量自适应，低频与高频只吃一半压缩量，不抽空低音和空气感（`:57-84, 1257-1323`）。

**最该改的**
1. **自动 Heat 听不见，还白跑 8 倍过采样；失真量又跟着混音的绝对电平走**（见 1-08）。Color 在推响之前，同一个 Heat 值在轻 10 dB 的混音上谐波少约 20 dB。
2. **三套倾斜参考不一致**（R6-01，没做）：Tone 参考 −2.25 dB/oct，House 目标频谱 −1.5 / −0.75 / −1.25（`Source/dsp/CeladonChain.cpp:33-43`）。两者方向可能相反，互相抵消。

### 3.3 Balance

**做得好的**
- 参考 = 频率方向抹平的形状 + 稳健估计的共同电平（Huber），整体变响 / 变轻不会被当成频谱偏差（`Source/dsp/BalanceModule.cpp:1157-1352`）。
- 自动削峰有四重保护：持续时间、两侧距离 2 / 3 段的支撑、起音保持、谐波保护（`:1501-1529`）；每跳最多 1 dB、±1 dB 死区；完全旁通逐位等于输入（`:43, 661`）。
- 低频段按自由度加长时间平均（40 Hz 段约 1.4 s），执行用 double 的 TDF2，静音归零（`:69-77, 180`）。

**最该改的**
1. **27 段是级联，相邻段互相叠加**（见 1-10）。Q 4.318、1/3 倍频程间距下，单段在相邻段中心的响应约 20 %（小增益近似）。成片同号的修正在段中心被放大约 1.6 倍、段间约 1.3 倍，带约 ±0.16 dB/每 dB 的纹波。T-032 R2-02「串扰补偿」一直挂着。
2. **两端没人管**（见 1-13）：自动削峰要求两侧各有距离 2 和 3 的支撑段，所以最低 3 段（40 / 50 / 63 Hz）和最高 3 段永远不进自动份额（`:1507-1521`）；目标频谱只管第 3～25 段。再加上 48 kHz 下低段只有 1～2 个 FFT bin（#22）。

### 3.4 Clay

**做得好的**
- 收单用非负核的线性相位低通，没有预振铃；加宽只动侧声道 2 kHz 以上，不改中声道（`Source/dsp/LinearPhaseLowpass.h:9-11`；`Source/dsp/ClayModule.h:20-23, 44-62`）。
- 峰值守护保证低切 / 收单不抬峰，代价看得见：保留比指示（ADR-032）、混合损失进先试（ADR-027）。

**最该改的**：**没发现新的值得改的点。** 已知的两件都在等你拍板，不重提：手动收单被守护回收大半（ADR-032 你答过「不拆」）；Clay 占整链延迟约 80 %（23 ms / 28.8 ms），而自动态从不用收单（T-088 阻塞）。`ClayModule.cpp` 守护主体我没逐行读，见第 10 节。

### 1-01 的修法（细一点，因为它是发版门槛）

登记的修法是「条件积分 R5-03b」（守门在管的时候 G_trim 不积）。我的判断：**只做这个治不了根**。

- 根因是积分器比传感器快太多：G_trim 20 秒走 1 dB，而它看的「主段电平」是最长 4 分多钟的平均，要一两分钟才反映出变化。积分器看不到自己的效果，就一直积到钳位。
- 手算核对：方案推 5 dB、增益 25 秒爬到位，这期间平均值一直落后，G_trim 60 秒到 +3 dB——和 T-097 报告第 79 行的追踪逐项吻合（`docs/validation/2026-10-11-T097-guards/REPORT.md:79-81`）。默认 35 % 按同一模型估约 +1 dB 过冲。
- 建议（都在 `GlazeController` / `OutputLevelTracker`，只在 GLAZE > 0 生效，不加延迟，GLAZE 0 逐位不变）：
  1. **误差按增益归一**：每个主段多记「这一段的平均自动总增益」，算主段电平时把旧段折到当前增益。更干净的做法是直接估偏差：用 T-097 已有的入口 / 出口 100 ms 配对子块，算主段「实测净增益 − 方案净增益」，G_trim 以 ≤ 0.05 dB/s 走过去，不再盲积。
  2. **只在此刻是主段、且有新读数时才动**；breakdown、前奏、尾奏里保持。
  3. **改了 GLAZE / 风格 / 交付 / 手动 Gain 时历史跟着折算**，不只是冻 1 秒。
- 存档：`OUTPUT_LEVEL` 的段结构要加字段，按 T-097 的节点内兼容写法。
