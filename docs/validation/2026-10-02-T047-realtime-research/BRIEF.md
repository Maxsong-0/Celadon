# T-047 共享背景（主进程 2026-10-02 写，三个调研代理共用；只读这份，不要各自重读大文件）

## 0. 目标与硬约束（Max 2026-10-02 原话的要点）

Celadon 是 Max 自用、不商用的 VST3 / AU 母带插件（JUCE 9.0.2，C++，Mac / Windows）。要**重新定义**它：

1. **彻底取消「聆听」和「锁定」**：没有学习期、没有「已提交画像 / 方案」、没有锁定后的校准轮。**所有计算都按实时频谱**（与实时响度 / 动态读数）
   持续进行，全程跟着音频走。
2. **CPU 预算 15 % → 20 %**：口径 = 整插件在**单个音频线程**上「处理耗时 ÷ 这一块音频的播放时长」（自动测试拦回归的门槛，见第 4 节）。
3. **更好的效果、更低的延迟**：现在 48 kHz 下 1384 样本 ≈ 28.8 ms（见第 3 节）。
4. **保留曲风层**（第 5 节），并给**多种曲风**逐类优化。
5. 不放松的工程约束：音频线程 0 分配 0 锁；同一段音频任意宿主块长切分，结果逐位相同；浮点不用 fast-math、不依赖 FMA（ADR-013）。

## 1. 信号链（固定顺序，ADR-001）

`输入 → Balance → Clay（修坯）→ Color（Tone / Glue / Heat）→ Limit（Gain → Clip → 前瞻真峰值限幅）→ 输出`

- **Balance**（`Source/dsp/BalanceModule.*`）：Gullfoss 式**动态频谱平衡，本身就是实时的**。每 hop 约 10 ms：两声道功率谱 → 27 个 1/3 倍频程段 →
  快跟踪 → 参考轮廓（形状抹平 + 慢平滑 + 共同电平）→ 偏差 → 死区 ±1 dB → Tame（压局部峰）/ Recover（提被掩蔽段），带谐波与起音保护。
- **Clay**（`ClayModule.*`）：① 低切（4 阶 Butterworth IIR 高通）② **线性相位收单**（S 声道的低频按 4 个滑动平均级联的线性相位低通减掉，
  群延迟 D）③ 加宽（S 的 2 kHz 高架）④ **峰值守护**（前瞻 G：保证 ①② 不把峰值抬过界，x + g·(y − x)）。
- **Color**（`ColorModule.*`）：Tone（100 Hz 低搁架 / 8 kHz 高搁架反向）→ Glue（前馈总线压缩 2:1、侧链 100 Hz 高通、攻击 20 ms、释放 50 ～ 500 ms
  自适应、自动补偿，低 / 高两侧分频增益）→ Heat（8× 过采样 Tube 非线性残差并联，原声延迟 64 样本）。
- **Limit**（`LimiterModule.*`）：× Gain → Clip（4× 过采样软削波）→ 前瞻真峰值限幅（8× 检测、1× 施加，自适应释放 100 ～ 800 ms；T-038 House 档
  释放按一拍 ÷ 3 封顶）→ Ceiling 硬钳。

## 2. GLAZE 今天怎么做决定（要被取消 / 改造的部分）

一个旋钮 GLAZE（0 ～ 100）+ 风格（自动 / 温润 / 冲击 / 通透）。流程是 **学习 → 锁定 → 校准 → 保护**：

- `MusicAnalyzer`（4036 行）：学习期把整段的特征累计成**画像**：I（积分响度）、LRA、PLR、真峰值、27 段长期电平、谱斜率、低 / 高频占比、起音密度 /
  强度、立体声（低频相关度、S/M）、次声占比，以及「先试后用」——把 Clay 候选（低切 / 收单 / 加宽）离线跑一遍量峰值代价。听够 15 ～ 30 s 才「提交」。
- `GlazePlanner`（2074 行）：画像 → **方案**：风格权重（自动风格按画像混合温润 / 冲击 / 通透）、目标响度（风格偏好 −8.5 / −9 / −10 LUFS，按 LRA 修正、
  按交付档钳位）、各模块增量（Balance 的 Recover / Tame 量、Tone dB、Glue / Heat / Clip 量、Limit Gain 的 5 折点折线），用**前向链模型**预测各模块 GR，
  逐项核对**风格预算**（Glue / Clip / Limit 的均值 / P95 / 峰值 GR 上限，T-045 刚放宽为温润 2 / 4.5 / 7、冲击 1.8 / 4 / 6、通透 2.5 / 5.5 / 9 dB）。
- `GlazeController`（4056 行）：状态机。锁定后方案按 3 s 过渡生效；**校准器**（`GlazeCalibrator`）在锁定后量「实际净增益 − 方案预测」的偏差、
  一次性补偿前馈误差；**保护层**（`GlazeGuard`）实时测 GR，持续超预算就以 1 dB/s 退让（−3 dB 封底），安全 5 s 后恢复；**约束反馈**把卡住的退让并进方案。
  另有「画像失配」：实时读数与画像差很多时提示重新聆听。
- **已经是实时的部分**：Balance 整个模块；Tone 的「实时跟随」（`updateLiveTone`，按实时谱斜率在方案值附近微调）；立体声 / 反相提示与 Clay 守护的实时部分；
  保护层。**依赖锁定的部分**：风格权重、目标响度与 Limit Gain、Glue / Heat / Clip 的量、Clay 的三项自动值、先试后用、校准。
- 状态行今天有「未学习 / 聆听中 x / y s / 已锁定 · 待校准 / 校准中 / 已锁定」等，**新设计里这些都没了**。

## 3. 延迟构成（48 kHz，`设计规格-总体`「延迟」节）

总延迟 1384 样本 ≈ 28.8 ms = Clay D 574（线性相位收单，D = 2(L_max − 1)）+ Clay G 528（峰值守护前瞻 round(0.008 fs) + round(0.003 fs)）
+ Color 64（Heat 过采样）+ Limit 218（Clip 4× 过采样 60 + Lookahead 默认 2 ms 96 + 62）。v0.1.6.2 没有 Clay 时只有 282 样本 ≈ 5.9 ms。
宿主按上报延迟补偿；Lookahead 参数停稳 0.3 s 后才生效。

## 4. CPU 口径与现状

- 门槛：单音频线程「处理耗时 ÷ 块播放时长」的回归门槛 15 %（官网 `site/src/content/algorithms/zh/verification.md`，0.1.8.6 起由 10 % 放宽）→ 目标 20 %。
- 实测（M2 Pro，v0.1.6.2 时）：48 kHz / 512 平均 1.17 %、p99.9 1.69 %；48 kHz / 32 平均 1.28 %、最慢块 13 %；192 kHz / 32 平均 5.1 %、最慢块 51 %。
  0.1.7.2 后 x86 虚拟机 48 / 96 / 192 kHz 均值 3.3 / 6.4 / 13.0 %。小缓冲的「最慢块」主要来自每 hop 的分析与偶发的重算。
- 分析器学习期每 512 块约 56 µs（≈ 0.52 % 单核），不学习约 5 µs；House 段落账一次满账本重算约 62 µs。
- 新设计取消学习后，「学习期」的离线式开销（先试后用、整段直方图）要么去掉，要么变成**实时**开销——这正是要研究的预算分配。

## 5. 曲风层（T-038，2026-10-01；要保留）

- 「曲风」：通用 / Deep House / Tech House / Melodic-Progressive；「交付」：标准 / 流媒体（−10 LUFS、真峰值 ≤ −2 dBTP）/ 俱乐部（−7 LUFS）。
- 曲风只管音色与学习方式：Tone 参考斜率（Jamendo 45 首标定为三类 −2.25 dB/oct）、Tone 往亮上限 +0.4 dB、目标频谱形状、低切目标 25 Hz、不自动加宽、
  限幅释放跟拍（一拍 ÷ 3，需宿主 BPM）、低频反相提示；House 的「门控画像」（只用满编段、听满 64 小节且 8 小节满编才锁定）——**锁定这部分在新设计里要取消**，
  但「只让主段落决定目标、breakdown 不拉低方案」的需求还在，要改成实时的办法。
- 交付档管响度与真峰值；风格管怎么花动态预算。

## 6. 要研究出的东西

- 每个模块 / 每类决策怎样**实时**算（输入、时间常数、平滑与迟滞、防止抽吸 / 漂移 / 来回拉锯、开机即用不需要学习）。
- 怎样让增益 / 响度控制实时而不「骑」音乐（breakdown → drop 的对比要保住，T-038 门槛：breakdown → drop 落差处理后最多少 1.2 LU，俱乐部 1.5 LU）。
- 延迟怎么降：Clay 线性相位收单与峰值守护前瞻、限幅前瞻、过采样的替代与取舍；目标给出一个具体数（例如 ≤ 10 ms）与代价。
- CPU 怎么在 20 % 内分配（48 kHz / 32 最慢块也要守住）。
- 多曲风：哪些曲风、每类的实时目标与参数。
