## 结论（先看这 6 条）

1. **能做，而且不需要任何学习期。** 真正难的只有一件事：不锁定时，目标响度按什么定。同类音乐插件里没有先例（Ozone、sonible 全是先学后固定，见 A 结论 1），
   但三份报告**各自独立**得出同一个办法：常在线的「主段电平」统计（按主段加权的直方图取上分位）+ 非主段冻结 + 慢速率限制 + 按实测 GR 收增益。
   T-038 的段落账本本来就是这种相对门，要拿掉的只是「定稿 / 锁定 / 校准」状态机（C §4.1）。
2. **breakdown → drop 的对比能保住，第一个 drop 有固有代价。** 冻结 + 分位数把「骑增益」整项消掉：B 的玩具仿真里 30 s breakdown 内增益漂移 0 dB，
   朴素慢 AGC 是 +7.7 dB（B §2）。剩下的落差损失等于 drop 比 breakdown 多压的那部分 GR，用「落差守门」直接闭环在 T-038 的 1.2 / 1.5 LU 门槛上。
   因果系统听到第一个 drop 之前不知道它多响，所以开头怎么起步要你定（第 9 节问题 2）。
3. **延迟能从 28.8 ms 降到 5～13 ms，大头是 Clay 的收单。** 收单低通的长度由手动收单旋钮的最低分频点决定（40 Hz → 574 样本）。
   自动收单自 ADR-015 起恒为中性，默认设置下收单根本不动，这 12 ms 却人人在付；改最小相位收单（D = 0）或抬高手动旋钮下限都能大幅降延迟（第 4 节，问题 1）。
4. **CPU 不是问题，最慢块才是。** 新的实时控制层合计 < 0.2 % 单核（A、B、C 三方估算一致），取消学习期反而省约 0.5 %。
   20 % 预算真正要守的是 48 kHz / 32 样本的最慢块（每块 667 µs 的 20 % = 133 µs）和高采样率；段落账本现在一次满账本重算 62 µs，必须改成增量（第 5 节）。
5. **曲风建议从 4 项扩到 13 项，按 6 个处理原型共用常数，分三期做。** 曲风只换「目标 + 预算 + 主段判定方式」，不换「压多狠」；
   全频斜率不按曲风分（T-038 已证伪「Deep 暗 / Tech 亮」），曲风差异放在频谱两端的宽容度（C §2）。一期只做 4/4 电子（问题 3）。
6. **代价**：所有新参数都是起点值，要在服务器上用 T-038 的 45 首 Jamendo 标签 + 合成曲做「因果重放」标定；旧工程打开后声音会变（没有锁定方案可恢复）。

## 1 新架构：按时间尺度分五层（A 建议 8，B / C 同构）

| 层 | 时间尺度 | 管什么 | 现有对应 |
|---|---|---|---|
| L0 | 样本～5 ms | 真峰值前瞻限幅的瞬态级、Clay 峰值守护、Clip | 不变 |
| L1 | 10 ms～1 s | Balance 每段增益、Glue 释放、限幅释放（House 一拍 ÷ 3） | Balance 本来就实时，不变 |
| L2 | 1～10 s | 预算环（GlazeGuard 升级）、落差守门、Glue / Heat / Clip 的量、Clay 三项自动值 | 原来锁定后才定 → 改实时 servo |
| L3 | 10～90 s | 主段电平 L_ref → 目标增益；Tone 跟随 | 原来靠画像 + 方案 + 校准 → 改实时 |
| L4 | ≥ 60 s | 自动风格权重（曲风先验 + 慢证据） | 原来锁定时算一次 → 改慢变 |

外环比内环慢一个量级以上，且受内环约束：g = min(g_响度, g_预算)，预算是硬约束、响度是软目标（A 结论 4，与 smart:limit「以动态为目标、响度是结果」同向，已抽查原文）。

## 2 核心：主段电平与增益【合并】

### 2.1 三份报告的方案对照

| 项 | A | B | C | 合并取 |
|---|---|---|---|---|
| 统计量 | 3 s 短期响度 S 的直方图 | 同 A | 按小节的段响度（无拍点退回 2 s 段，同 T-038） | **C**：账本与门限 T-038 已标定（画像与 drop 差中位 0.15 LU） |
| 谁进账 | 比 L_prog 低 > 8 LU 的不进 | 门深 6 LU、迟滞 1.5 LU | 主段度 m = 响度门 × 底鼓门 × 密度门（软与） | **C**（4/4 曲风）；非 4/4 只用响度门 |
| 分位 | P75～P90 | P80 | P95（非 4/4 取 P90） | **C**：P95 是 T-038 标定值 |
| 遗忘 | 墙钟 τ 60～90 s | 按「进账帧」计，τ ≈ 45 s | 全局衰减 τ ≈ 93 s @124 BPM | **B 的计法**（见下）+ C 的时长 |
| 长时间无主段 | — | 门闭 45 s 后以 0.05 dB/s 泄漏 | 60 s 内无对比 → 退回只看响度 | 两条都要 |
| 置信度 | c = 1 − exp(−T_门内 / 6～8 s) | 证据少时上行减半 | c = 1 − exp(−M / 8 小节) | C |

遗忘为什么按「进账」而不是按墙钟：按墙钟衰减时，长 breakdown 里有效质量 M 会掉（60 s 掉一半），置信度跟着掉，增益就往保守先验收，
drop 回来还得重新爬。按进账计时，breakdown 里 L_ref 和置信度都不动【主进程推断】。Omnia 的现场问答正好是反例：AGC 只冻结、不回零，
响歌接轻前奏时前奏被压在 −22 dB 听不见，靠「回零（RTZ）」解决（已抽查原文）——所以泄漏 / 退路必须有。

### 2.2 合并后的控制律

1. **主段电平估计器**（SegmentLedger 常在线化）：每段算 L_seg、lowShare、底鼓起伏 K（40～130 Hz 包络 P90 − P10）、中高频密度 D（300 Hz～8 kHz）；
   m = s_L · s_K · s_D（各 s 是固定宽度的斜坡，ΔG 3 LU、低频门 0.6 沿用 T-038）；0.1 LU 一格的直方图按 m × 时长进账，读 P95 = L_ref。
2. **新曲识别只看音频**：静音 ≥ 0.5 s，或 |S − L_ref| > 10 LU 持续 20 s → 进账质量 × 0.2～0.5。**不用宿主走带信息**（块起点的播放位置随切块变，破坏逐位相同，B §2）。
3. **增益 = 前馈 + 慢修正**【合并】：G_ff = 交付×曲风目标 − L_ref（输入侧），按置信度在保守先验（现有 `unlearnedInputLufs` −14 / `unlearnedStrength` 0.35）与 G_ff 之间插值；
   输出侧再测一次主段电平，与目标的差以 ≤ 0.05 dB/s 积分成 G_trim（钳 ±3 dB，受预算限制时冻结 = 抗饱和），**取代 GlazeCalibrator 的一次性补偿**【主进程推断】。
4. **速率与棘轮**：上行 0.2 dB/s、下行 1 dB/s，迟滞死区进 0.3 / 出 0.1 dB（B）；**m < 0.5 时只降不升**（C 的棘轮），所以前奏和 build 不会把增益抬起来。
5. **预算环**（GlazeGuard 升级）：退让按超出量 0.3～6 dB/s（现为固定 1 dB/s）、回升 0.15～0.3 dB/s，进 105 % / 出 90 % 迟滞；T-045 的三种风格预算原样当上限。
6. **落差守门**：输入、输出各一份 S 直方图，(P90 − P25)_输入 − (P90 − P25)_输出 > 1.2 LU（俱乐部 1.5）→ 预算环以 ≤ 0.1 dB/s 回收（B）。
7. **PSR 保护**：3 s PSR 实测 < 下限 − 0.5 持续 3 s → 0.5 dB/s 退让（C；下限按交付 × 曲风，流媒体 8、俱乐部约 6.5）。

## 4 延迟（48 kHz；现在 1384 样本 = 28.8 ms）

拆账（B §1，库内常数已核对）：Clay 收单 D 574 + Clay 守护 G 528 + Heat 过采样 64 + Clip 过采样 60 + 限幅前瞻 96 + 真峰值保持 62。

- **D**：D = 2(round(0.24·fs / fc_min) − 1)，fc_min 是允许的最低收单分频点：40 Hz → 574、60 → 382、80 → 286、120 → 190；最小相位收单 → 0。
- **G**：「不抬过界」的保证与窗长无关，窗只决定守护多常出手；W 8 → 2～3 ms、A 3 → 1 ms → 144～192，代价是守护更常出手（混合损失变大，要复跑压力格）。
- **一档「只改常数」**（G 缩短 + 前瞻默认 2 → 1 ms，过采样和保持不动）：D 以外合计 378～426。
- **二档「+ 过采样重做」**（Clip / Heat 改「只对非线性残差做 ADAA + 2× 短滤波」、保持 63 → 约 15）：D 以外合计 219～267。会改混叠特性，还和「表与限幅器用同一个真峰值检测器」（ADR-004）冲突。

| 收单方式 | 一档 | 二档 | 对手动收单旋钮（现 40～300 Hz、默认 120；自动收单 ADR-015 起不动作）的影响 |
|---|---|---|---|
| 线性相位，下限 60 Hz | 15.8～16.8 ms | 12.5～13.5 ms | 40～60 Hz 不能选 |
| 线性相位，下限 80 Hz | 13.8～14.8 ms | 10.5～11.5 ms | 40～80 Hz 不能选 |
| 线性相位，下限 120 Hz | 11.8～12.8 ms | 8.5～9.5 ms | 40～120 Hz 不能选；默认 120 不变 |
| 最小相位（S 路 2 阶高通，M 不动） | 7.9～8.9 ms | 4.6～5.6 ms | 范围不变；这是 v0.1.7.0 初版的做法，ADR-012 因峰值换成线性相位。现在有峰值守护（ADR-014）兜峰值，代价是守护更常出手（收单效果打折） |

不能用的：「1 − 最小相位低通」互补式在分频点凸起 +1.8 dB（2 阶）/ +4.7 dB（4 阶）；M 路也过全通会改底鼓与高频的对齐（B §5）。
分区卷积只省块延迟、省不掉线性相位的群延迟（B 结论 1）。前瞻和真峰值改短都要实测，现有 2 ms 前瞻保留成可选档。

## 5 CPU 20 %

- 新增实时控制层（两份直方图、斜率回归、servo、落差守门）< 10 µs / 100 ms ≈ 0.01 %；取消学习期 −56 µs / 512 块（−0.52 %）（B §8）。
- 目标（B 建议）：48 kHz / 512 平均 ≤ 6 %、48 kHz / 32 最慢块 ≤ 15 %（给 20 % 留 5 点）、96 kHz / 64 最慢块 ≤ 20 %。
- 规则：每个 hop 最多一片、每片 ≤ 15 µs、按绝对样本位置调度；禁止「按历史重算」——**段落账本现在一次满账本重算 62 µs**（48 kHz / 32 的一块里占 9 %），要改成增量直方图。
- 192 kHz / 32 的最慢块现在 51 %，B 推测是分析路径随采样率放大，要先量；办法是分析路径抽取到 48 kHz 等效、过采样倍率随采样率降。
- 多出来的 5 点留给小缓冲最慢块和高采样率；若「看守护混合损失」不够当 Clay 在线代价，再考虑轮流影子试算【主进程推断】。

## 9 需要你拍板

1. **延迟目标与收单取舍**（第 4 节表）。建议：目标 ≤ 10 ms——先试最小相位收单（过压力格则约 5～9 ms、分频点不受限），不过关退回线性相位下限 80 Hz（约 10.5～11.5 ms）。
2. **开头怎么起步**。建议：保守先验 + 棘轮——开头偏轻、首个 drop 不过冲；一上来就是 drop 的曲子（很多 Techno）头 10～20 s 偏轻。
   另一选项：直接按目标起步，开头即到位，首个 drop 头 1～2 s 可能多压 1～3 dB（靠预算环兜底）。
3. **曲风扩展范围**。建议：一期只做 4/4 电子（通用 + 现有 3 类 House + Techno + EDM / Trance + DnB / Bass，共 7 项），非电子以后再说。

以后再定（不急）：流媒体档默认要不要从 −10 改到 −11～−12（Spotify 归一到 −14，−10 没有响度收益，C 结论 6）；状态行版式；ADR-004 同源让不让步；这次重定义的版本号。
