# T-093 · R5 GLAZE 控制层与评估方法（自动决策、参考学习、怎么证明「好听」）

> **一句话结论**：「实时画像 → 纯函数决策器 → 速率限制 / 棘轮 → 守护族」这套结构不用换成 ML 或在线优化器。真正的短板有两处。一是没有可执行的「好听」验收：阶段 2 的规格验收至今没跑完，「不拉锯」的阈值也从没定过。二是守护族有实测得到的结构缺陷：G_trim 和落差 / PSR 两个守门的积分互相顶，PSR 守门读的是输入，属于开环。先建客观指标和盲测管线，再用它修守护族和第一个 drop，最后用曲库数据替代手调的风格常数。
>
> **前 5 条一览**（全表按价值排序，见文末结构化清单）：
> 1. **R5-01** 「好听」客观评估管线：十组指标 + 相对冻结基线的「不退步」门槛，补上规格第 7.5 节从没定过的「不拉锯」阈值（工具，M，P0）
> 2. **R5-03** 守护族统一成「按灵敏度算上限 → 取最小 → 条件积分」的增益调度，一并修 G_trim 积分饱和、PSR 测点、落差回差三个缺陷（控制层，M，P0）
> 3. **R5-02** Max 一个人也能出统计结论的盲测协议与工具：ABX 和偏好两段，等响、随机，事先登记决策规则（工具，S～M，P0）
> 4. **R5-04** 第一个 drop：加主段电平的「上行快通道」，低频参考改取上层段；不动 T-048 已拍板的常数（控制层，M，P1）
> 5. **R5-05** 置信度不再随回看重判回落。这是规格写明留到阶段 2、但阶段 2 没做的结构改法（控制层，S，P1）

## 0. 七个问题的逐项判断（细节在第 1 节各提案）

**① 决策结构**

- **长处**【推断，依据源码】：
  - 每个自动量都能追溯到「画像特征 × 常数」。决策器是纯函数，约 1 µs（`GlazePlanner.h:69`）。
  - 可以按性质做测试，逐位确定，GLAZE 0 的保证也容易守。
  - 时间尺度已经分层：L0～L4（`设计规格-实时GLAZE.md` 第 3 节）。
- **短处**：
  1. 风格 = 三套手写常数的凸组合（`GlazePlanner.cpp:1421-1462`），只能落在三角形内部。数据标定过的只有 Tone 斜率，T-038 用 45 首把它从 −3.5 / −3.0 改成了 −2.25（`2026-10-01-T038-calibration/REPORT.md` 第 1 节）。
  2. 目标是标量，不是「中位 + 容差」的分布。
  3. 前向模型误差全靠 G_trim 加三个各自独立的继电器式守门吸收，而这几者之间有缺陷（R5-03）。
- **同类对照**【一手】：
  - Ozone Master Assistant：曲风目标来自榜单曲；参考文件只学最响的 8 s；目标分成音色 / 人声 / 宽度 / 动态 / 响度五个子目标；分析一次，Relearn 才重算。
  - Tonal Balance Control：目标是「典型变化范围」组成的隧道，可以用一个文件夹建目标。
  - smart:limit：以 PSR 中位数为学习目标，并明说学习时忽略交付响度（「响度是动态的结果」）。
  - Mastering The Mix REFERENCE：参考建成曲库，自动推荐最匹配的参考，自动循环最响的一段。
  - Matchering 源码：只取 RMS ≥ 平均值的「最响片段」；M / S 分别求平均谱，比值在对数频率上做 LOWESS 平滑后生成 FIR；RMS 迭代 4 次；最后过限幅器；没有容差，连每个频率的宽度都照抄。
  - 学术方案三类：
    - DeepAFx-ST：编码器预测参数 EQ 和压缩器的参数，参数可解释。
    - Martínez-Ramírez 2021 用黑盒效果器做自动母带；Koo 2022 直接输出波形。
    - ST-ITO 和 ITO-Master 在推理时优化：用 CMA-ES 搜效果器参数或参考嵌入。
  - Diff-MST 的风格损失用的是可解释特征：RMS、crest、Bark 谱、宽度、左右不平衡。
- **结论**：
  - **运行时不换**。
  - **离线换**：用曲库学出目标向量，交给现有决策器（R5-07）；用离线约束优化替代手调常数（R5-09）。
  - 运行时引入 ML 不值得，理由四条：
    1. CPU：DeepAFx-ST 的 TCN 在 16 核 Xeon 上 CPU 推理 RTF 0.13，而且是离线逐步计时。
    2. 逐位契约：ADR-013 禁 FMA，需要自写标量推理。
    3. 可解释性会丢：Koo 2022 那类直接出波形的方法没有参数可看。
    4. 数据：Max 的曲库是几十首量级，够做分位数统计，不够训深模型。

**② 参考 / 曲库学习**

- 实时化以后，整首预分析（T-038 的 D）对「参考曲」价值更高：目标可以离线、完整地算，不受因果限制。
- 目标应包含：
  - 27 段形状，加 P25～P75 容差；
  - 主段 PSR 的中位和 P10～P90；
  - LRA；
  - 低频占比和低频 crest；
  - 4 段 S/M 比与相关度；
  - 斜率。
- 绝对响度不进目标（T-038 结论 5）。
- 和实时画像的结合方式：
  - 目标替代 Tone 参考斜率和 Balance 的目标形状；
  - 隧道半宽当死区；
  - PSR 的 P10 当 PSR 守门的下限。
- 侧链参考也应改成按主段门控（R5-08）。
- 对「本曲」做整首预分析，等于一键热启动（R5-11，待拍板）。

**③ 段落感知**

- 不建议让 Glue 阈值或 Heat 底量跟着段落走。那等于按段补偿响度 / 质感，违背 Max 的原则。Glue 在 breakdown 里自然少压，本来就在保对比。
- 现有的段内跟随量（Tone 实时偏移、Heat / Glue 实时减量、live Tame）都不看主段度。风险在「drop 入口滞后」，这一点先量再改（R5-10）。
- Recover × (0.4 + 0.6·m) 只做实验。

**④ 冷启动与第一个 drop**

- 实测：
  - 第一个 drop 时 c 中位已到 0.8 以上：c 到 0.8 的中位是 31 s，第一个 drop 一般在 16～32 小节，也就是 31～62 s。
  - 所以曲风先验的权重 ≤ 0.2，不是能用的杠杆。
- 有效的改法是两条结构性改动：
  - 「大幅超出走快记忆」（AC-3 的非对称时间常数，R5-04）；
  - 置信度与重判解耦（R5-05）。
- 再加一条：导出提示改看「收敛」，不只看 c（R5-06）。

**⑤ 守护族与预算**

- 「最大化增益，使每个单调约束不超上限」线性化以后，解就是各约束算出的上限取最小。所以统一成一个多目标优化不需要求解器，也不需要 MPC。
- 要做的是三件事：
  - 把三个固定速率的继电器积分器换成「按灵敏度算出的上限」；
  - 只留一个共同速率限制；
  - G_trim 改成条件积分（R5-03）。
- 现有实现有三个缺陷（见「范围外发现」第 1～3 条），统一调度能一并消掉。

**⑥ 评估方法**

- 客观指标十组，见 R5-01。
- 感知类指标的适用性：
  - PEAQ 和 ViSQOL 是为编解码损伤设计的全参考指标，Torcoli 等 2021 证明这类指标有明显的领域依赖。母带处理是「有意改变」，越像原输入得分越高，方向是反的。
  - FAD 是分布级指标：依赖嵌入的选择，有样本量偏差（Gui 等 2024），对单首歌 ±0.5 dB 量级的母带微差不可靠【推断】。
  - 结论：用可解释的特征距离做主指标。
- 主观协议：BS.1116-3 的会话纪律，加 ABX / 2AFC 二项检验（R5-02）。
- 每次算法改动必须过的最小指标集，见 R5-01「最小集」。

**⑦ 可解释性**

- 只补 T-086 没列的：目标响度分解、失真频谱、交付体检单、参考匹配度、收敛度（R5-12）。

## 1. 提案（按价值排序）

### R5-01 「好听」客观评估管线：十组指标 + 不退步门槛（P0 · 工具 · M）

- **问题 / 现状**
  - `gate_check.py:4-22` 只判五样：Clay 门槛、同决策重放、反相提示、c ≥ 0.5、真峰值。
  - `house_gate.py:3-13` 判 drop 预算、落差、目标 ±1 LU。
  - `metrics.csv` 只有 LUFS / 真峰值 / PLR / 限幅 GR 均值和最大值（`tools/render/README.md:139-143`）。
  - 规格「实时GLAZE-主段与增益」第 7 节第 5 条「不拉锯：增益每分钟总变差与变号次数有上限（阈值阶段 1 按 22 首定）」（vault 该文件:136）从没定过阈值：全仓库检索「总变差 / 变号」只在 T-047 调研里出现。
  - 阶段 2 验收也没跑：`REPORT-P2-INTEGRATE-SPARK.md` §0 写着「22 首 `gate_check.py` 未跑」，真编排器因果重放和合成曲落差也不在那次范围内。
  - BRIEF 第 5 节：「好听没有客观验收」。
- **提案**
  - 新建 `tools/render/quality_metrics.py`（纯 Python，只读输入 wav、成品 wav、`--trace`、`--segments-csv` 和段落标签）。每首 × 每组设置输出一行 `quality.csv`。十组指标：
    1. **L 响度**：主段输出电平与方案目标之差（热启动 ≤ 0.3 LU，规格第 7.4 条）；drop ±1 LU（沿用 house_gate ⑤）。
    2. **P 微动态**：PSR 按 AES e-Brief 373 的口径（3 s 窗内真峰值最大值 − S）。报主段的中位与 P10，以及输出 − 输入的差。
    3. **R 宏动态**：LRA 按 EBU Tech 3342（P10～P95）报输入 / 输出；落差损失沿用 house_gate ③。
    4. **S 频谱距离**：主段长期 1/3 倍频程谱，用 200 Hz～1.2 kHz 锚区归一（与电平无关）。距离 = √(mean_b w_b · max(0, |x_b − t_b| − tol_b)²)，单位 dB。t / tol 取自 R5-07 的目标；没有目标时只报「输出 − 输入」的形状变化。
    5. **U 泵感**：
       - 主读数：`limit_gr_db` 的块率（512 / 48 k 约 94 Hz）轨迹 → 2～10 Hz 带通 → 主段 RMS（dB）。
       - 辅读数：七个倍频程带（63 Hz～8 kHz）的包络，在 0.5～16 Hz 上算「调制传递比 = 输出 / 输入」。借的是 STI 的 MTF 口径；> 1 表示加了泵感，< 1 表示瞬态被压平。
    6. **T 瞬态保留**：以输入检出的起音为锚。低频（40～130 Hz）和高频（2～8 kHz）带各算「5 ms 峰值 / 50 ms RMS」，取输出 / 输入比的中位（dB）。
    7. **D 非线性**：
       - 多音：31 个对数间隔的音，留出空 bin，按 drop 的响度过整条链，量空 bin 的能量比。
       - SMPTE 双音（60 Hz + 7 kHz，4:1）与 CCIF 双音（19 + 20 kHz）。
       - 真歌：40 ms 分帧，逐带求输入—输出相干，非相干功率比 = 1 − γ²。限幅器的时变增益也会降相干，这正是要抓的调制失真。
    8. **W 立体声**：三个带（< 120 Hz、120 Hz～2 kHz、> 2 kHz）的相关度与 S/M 比，报输出 − 输入。
    9. **C 编码后真峰值**：沿用 `codec_tp_check.py`（T-085）。
    10. **K 控制质量**：稳定段里 Gain 每分钟的总变差与变号次数（补规格 7.5）；drop 入口跟踪误差 M4；breakdown 漂移 M3；守门介入的时间占比与原因直方图；G_trim 的范围；±6 LU / 20 s 阶跃的响应。
  - 新建 `quality_gate.py`：和**冻结基线**逐首比较（「不退步」），外加绝对安全门。
  - 渲染工具 `--trace` 加列：`g_trim_db`、`relief_budget / contrast / psr`、`current_mainness`、`glue_gr_db`。`RenderMain.cpp:2053` 的注释本来就写着阶段 2 要把校准列换成这些。这只改工具，插件出声不变。
  - 可选：用开源结构分析器 all-in-one（Kim & Nam，输出拍点 / 小节 / 段落边界）给 Max 自己的曲库批量出段落边界，减少人工标注。它的功能标签偏流行乐结构，只取边界，drop / breakdown 仍由 Celadon 自己的 m 判。
  - **最小集（每次算法改动必过）**：
    - ① 真峰值 ≤ Ceiling + 0.01；流媒体档另加编码后真峰值。
    - ② drop 目标 ±1 LU；热启动主段电平 ≤ 0.3 LU。
    - ③ 落差损失 ≤ 1.2 / 1.5 LU。
    - ④ 主段 PSR 中位 ≥ 该档下限 − 0.5。
    - ⑤ 泵感指数相对基线增加 ≤ 基线分布的 P90 差。
    - ⑥ 低频瞬态保留 ≥ 基线 − 0.3 dB。
    - ⑦ 低频相关度 ≥ 输入 − 0.05。
    - ⑧ 非相干功率比 ≤ 基线 + 1 dB。
    - ⑨ 控制质量：总变差 / 变号 ≤ 基线 P90；M4 过线首数 ≥ 基线。
    - ⑩ 有目标时，频谱距离不劣于基线。
    - 这些数值都是起点，相对基线定；绝对的「好听」阈值等 R5-02 的盲测结果来校准。
- **依据**
  - ITU-R BS.1770、EBU Tech 3341 / 3342（响度、LRA）【一手】。
  - AES 2017 e-Brief 373（Shepherd 等「Standardizing PSR」）【一手】；smart:limit 手册用「所有 PSR 的中位」度量动态，并称它比 PLR 更能反映短时动态【一手】。
  - IEC 60268-16（STI 用 0.63～12.5 Hz 的调制传递）【一手，借口径】。
  - SMPTE RP 120、IEC 60268-3（双音互调）【一手】。
  - Bendat & Piersol《Random Data》（相干函数衡量线性关系）【一手】。
  - Tan 等 2004（JAES 52:699，Rnonlin）只作参照：后续研究报告它在真实换能器上与评分的相关性差，不作主指标【一手】。
  - Diff-MST 的 AF loss 用 RMS / crest / Bark 谱 / 宽度 / 不平衡做「制作风格」距离【一手】。
  - Hjortkjær & Walther-Hansen 2014：同一材料重复呈现时，听者的评分一致性很低，说明光靠一人试听不够【一手】。
- **对硬约束与 ADR 的影响**：只加工具和渲染追踪列，插件出声、逐位契约、延迟、CPU 都不受影响。`metrics.csv` 不动，新指标另写 `quality.csv`，旧表的输出逐字节不变（沿用 README 第 272 行「给了新选项才追加」的约定）。
- **代价与风险**：M。指标脚本约 600 行，RenderMain 补追踪列，再在 DGX 上把 22 首 + 45 首基线跑一遍。风险：泵感 / 失真指标与听感的对应关系要靠 R5-02 校准；起初只能做「不退步」，不能做「更好听」。
- **怎么验**（主会话在 DGX 上跑）：
  - 合成自检：已知调制深度的 AM 信号，泵感读数误差 ≤ 0.1 dB；纯削波下，多音空 bin 读数随削波深度单调；输入 = 输出时，所有「输出 − 输入」项为 0。
  - 跑出 22 + 45 首的基线分布。
  - 和 R5-02 的盲测结果做秩相关。
- **对 Max 口味的核对**：不改声音；House 落差、俱乐部 / 流媒体两版都覆盖；不涉及自动收单和加宽。

### R5-03 守护族统一调度：按灵敏度算上限 → 取最小 → 条件积分（P0 · 控制层 · M）

- **问题 / 现状**
  - `applyLimitExtras`（`GlazeController.cpp:835-867`）的做法：Limit Gain = 手动 + 增量 + G_trim + min(预算, 落差, PSR)。
  - 三个守门都是固定速率的继电器积分器：预算 0.3～6 dB/s，落差 0.1 dB/s（`ContrastGuard.h:43`），PSR 0.5 dB/s。
  - G_trim 只在预算环退让时冻结（`GlazeController.cpp:1293`）。规格要求的是「**任一**守门在退让、或 1 s 内改过参数」都冻结（vault 规格:77）。
  - 后果（推导自源码）：落差守门以 0.1 dB/s 退时，G_trim 以 0.05 dB/s 往回推。约 30 s 后落差守门到底（−3 dB）；再过约 30 s，G_trim 推满 +3 dB，守门的效果被完全抵消。等守门放开，G_trim 还停在 +3，输出要再过约 60 s 才回到目标——典型的积分饱和。
  - PSR 守门读的是 `analyzer.getShortTermView().psr3sDb`（`GlazeController.cpp:1287`），这是**链入口**的 PSR（`MusicAnalyzer.cpp:1249-1252`；`analyzeInput` 在各模块之前，见 `CeladonChain.cpp:439`）。退增益改变不了输入 PSR，所以它是开环的：输入 PSR 低于 7.5 / 6.5 / 5.5 dB（标准 / 流媒体 / 俱乐部，`PsrGuard.cpp:7-15` 减 0.5）就一路退到 −3 dB。
  - 落差守门的实现：12.8 s 环形窗、满 8 笔（0.8 s）即判（`ContrastGuard.cpp:65`），超限就退、不超就以同速回（`ContrastGuard.cpp:118-121`）。规格里写的「持续 10 s 才退、低于门槛 0.3 LU 持续 30 s 才以 0.05 dB/s 回、两份直方图满 60 s 且输入 P90 − P25 ≥ 3 LU 才判」（规格:80-82）都没实现。
  - 两个守门对所有曲风常开（`GlazeController.cpp:1286-1288`，没有曲风条件）。规格写的是「落差 4/4 型开、其余先关；PSR 通用与 House 默认关」（规格:80、83；BRIEF 第 3 节也这么写）。
  - 测试只覆盖了合同模型 `phase2::TrimIntegrator` 的「预算退让冻结」（`tests/Phase2OrchestratorTests.cpp:92-103`），没有真守门的闭环用例。
- **提案**
  - 数学：最大化 g，使每个约束 c_i(g) ≤ cap_i，且 c_i 随 g 单调。在当前工作点线性化：c_i(g) ≈ c_i,测 + s_i·(g − g_now)，于是 g_i* = g_now + (cap_i − c_i,测)/s_i，最优解 g* = min(g_plan + T, g_b*, g_c*, g_p*)。单个决策变量的线性规划，解就是上限取最小，**不需要求解器**；所以「显式多目标优化」和「选择器」在这里是同一件事。
  - 实现：
    - 每个守门在自己的网格上（预算 10 ms 时隙，落差 / PSR 100 ms）输出一个「总自动增益上限」。
    - 输出 g = min(…)，只过一个共同速率限制：下 1 dB/s、上 0.2 dB/s，就是现有的增益速率，不改常数。
    - 只有「方案分支」被选中时 T（G_trim）才积分（条件积分）；否则保持。
    - 没被选中的守门，上限跟踪当前输出 g（g + 小余量），防饱和，切换时无冲击。
    - 每个约束加回差和驻留时间（按规格第 4 条的数字）。
  - 灵敏度：
    - 预算：dGR/dGain，在限幅区约等于 1，取限幅器统计并钳在 [0.5, 1.5]。
    - 落差：从最近两个工作点估计 drop 与 breakdown 的 GR 差对增益的斜率，没有估计时用保守值 0.5。
    - PSR：**改读输出**的 3 s PSR，灵敏度约 1 − GR 份额。
    - 灵敏度无效时退回现行的继电器。
  - 收敛与振荡分析【推断】：
    - 继电器加测量时延会形成极限环，峰峰值约等于 2 × 速率 × 时延。落差守门的时延约 8 s（3 s 短期窗加 12.8 s 环的分位滞后），估计峰峰 ≈ 1.6 dB、周期约 30 s，只在工作点贴着门槛时出现。PSR 改读输出后，若仍用 0.5 dB/s 的继电器，过冲约 0.75～1.5 dB。
    - 换成按模型算上限之后，若灵敏度估得不低于真值（偏保守），每一步都不过冲，单调收敛。若估低了，过冲在退让一侧，也就是更安全的方向。
- **依据**
  - 规格「实时GLAZE-主段与增益」第 4 节第 3、4 条（vault:77-83）【一手】。
  - Åström & Hägglund《Advanced PID Control》（ISA 2006）选择器 / 超驰控制与跟踪式抗饱和；Åström & Murray《Feedback Systems》PID 一章「积分饱和」【一手】。

  - A/85 的多级串联、AC-3 DRC 的非对称时间常数（T-047 REPORT-A §2.2 已核对原文）【一手】。
  - smart:limit：「响度是目标动态的结果」【一手】。

### R5-05 置信度不随回看重判回落（P1 · 控制层 · S）

- **问题 / 现状**

  - T-038 calibration：数据驱动改常数的先例【一手（项目）】。
- **对硬约束与 ADR 的影响**：只改常数值。但阶段 2 的 Q11 已经不再把常数快照写进工程，所以**改出厂常数会改变旧工程的声音**，需要 Max 认可，或者恢复版本快照。
- **代价与风险**：L（算力和时间）。风险：对指标过拟合（指标 ≠ 耳朵），由盲测把关。
- **怎么验**：候选常数在留出曲上指标改善；盲测偏好 ≥ 65 % 且 p < 0.05；22 首门槛全过。
- **对 Max 口味的核对**：风格差异由数据和 Max 的耳朵共同决定；不违背「大旋钮不是把所有旋钮调大」。

### R5-06 导出提示改看「收敛」，不只看 c（P1 · 控制层 + 状态行 · S）

- **问题 / 现状**：`status.coldExport = offline && c < 0.5`（`GlazeController.cpp:907`）。没跟上的 10 首里，c 早在第一个 drop 之前就超过 0.5 了（c 到 0.8 的中位 31 s），提示不会亮。规格第 6 节的本意是「第一个 drop 可能偏轻时提醒」。
- **提案**：加「主段电平仍在变」这条判据：最近 8 段已发布 I 的极差 > 1 LU，或 G_trim 的误差 |e| > 1 LU 持续 > 8 s → 琥珀提示「主段电平还在变（近 8 小节 +x LU），导出前先从头播一遍」。只在离线导出、且处于前 1/3 时长内时亮。文案并入现行状态行的体系。
- **依据**：smart:limit 的「置信区：每次重新测量或改参数都会扩散」【一手】；项目规格第 6 节【一手】；实测【统计】。
- **对硬约束与 ADR 的影响**：只动状态行，不改声音；Status 加字段，参数 ID 不动。
- **代价与风险**：S。风险：歌本身后段变响时误亮。
- **怎么验**：45 首离线导出：10 首没跟上的里 ≥ 8 首提示亮；28 首已跟上的里误亮 ≤ 3 首。
- **对 Max 口味的核对**：全自动不变，只多一句提醒。

### R5-10 段落一致性：先测现有跟随量，再让 Tone 跟随按主段度降速；Recover 的 m 门控只做实验（P2 · 控制层 · S）

- **问题 / 现状**
  - 现有的段内跟随量都不看主段度：
    - Tone 实时偏移，0.15 dB/s（`GlazeController.cpp:762`）；
    - Heat / Glue 实时减量（`:801-802`）；
    - live Tame（`:1195-1208`）。
  - 32 小节的 breakdown 约 62 s，足够让 Tone 偏移走满 −0.75 ～ +0.4 dB × 强度（实时斜率与参考用同一组「在场频段」回归，`MusicAnalyzer.cpp:2175-2206`，已经消掉了「缺低音变亮」这种假漂移，但仍会跟着 breakdown 的音色走）。drop 进来后按 0.15 dB/s 回，要 3～5 s【推断，需测】。
  - T-047 报告 C 的 Recover × (0.4 + 0.6·m) 没做。
  - Glue 阈值 / Heat 底量跟段落走：不建议。Glue 在 breakdown 里因为电平低而自然少压，这本来就在保对比；改成按段跟随，等于做段落响度和质感补偿。
- **提案**
  1. R5-01 加「段落一致性」指标：drop 入口滞后（Tone / Heat / Glue / Balance 各段增益到达 drop 稳态 90 % 的时间）；breakdown 内的参数漂移；段落边界 ±1 小节内的参数跳变。
  2. 主段度 m′ < 0.5 时，Tone 跟随速率 × 0.25。不冻结，免得在长段落里卡住。
  3. Recover 的 m 门控做 A/B 实验：只有 R5-01 显示 breakdown 低频补提 > 2 dB、并且盲测偏好时，才改成默认。
- **依据**：Dolby 专利 US 8,144,881——同一听觉事件内增益近似恒定，变化集中在事件边界（T-047 REPORT-A §2.5 已核对）【一手】；Max 原则「不做段落响度补偿」（T-038 REPORT 第 1.3 节）【一手（项目）】；推导【推断】。
- **对硬约束与 ADR 的影响**：② 会改 breakdown 里 Tone 的声音；块长无关；GLAZE 0 不变；CPU 无影响。
- **代价与风险**：S。风险：主段外 Tone 跟不上本该修的偏差——但 breakdown 里本来就不该大修。
- **怎么验**：合成曲 + 45 首标签：drop 入口的 Tone 滞后 ≤ 1.5 s；breakdown 内 Tone 漂移 ≤ 0.2 dB；M2 / M4 不退。
- **对 Max 口味的核对**：维持「不做段落补偿」，减少「自动化感」。

### R5-08 侧链参考学习改成「主段门控 + 容差」（P2 · Balance 目标频谱 · S～M）

- **问题 / 现状**：`ReferenceSpectrum` 学的是「至少 10 s 有效非静音音频」（`ReferenceSpectrum.h:24`；0.1.9 设计:22），不挑段——参考曲从开头播，就学到了前奏。输出是单条 27 段形状（`Snapshot::relativeDb`），没有容差。
- **提案**
  - 侧链上另起一份同口径门控（段响度 + 低频门，复用 SegmentLedger 的逻辑），学到「≥ 8 小节或 16 s 主段」为止，只计主段帧。
  - 同时累计各段之间的方差，作为容差，与 R5-07 的文件目标同一格式。
  - 界面写「已学主段 x / 16 s」。
  - 参考很短或者没有主段时，退回现行的 10 s。
- **依据**：Ozone 参考学「最响 8 s」；MTM 自动循环最响段；Matchering 只取最响片段【一手】；Ozone 8 文档警告「在安静段学习，响段可能失真」（T-038 REPORT 结论 1 已核对）【一手】。
- **对硬约束与 ADR 的影响**：侧链分析不在主输出路径上；存档加容差字段，旧档缺省 = 现行死区，行为不变；CPU 只多一些加法。
- **代价与风险**：S～M。风险：参考曲的拍点未知时用 2 s 段。
- **怎么验**：45 首里挑 15 首有长前奏的，从第 1 小节送侧链。学到的形状与「只用 drop」形状的 dB RMS 差 ≤ 0.5 dB，并报告现行做法的差值作对照。
- **对 Max 口味的核对**：只改参考的学法。

### R5-11 拖入本曲文件做整首预分析 = 一键热启动（P2 · 控制层 · M · 需 Max 拍板）

- **问题 / 现状**：热启动现在要「先播一遍」（规格第 5、6 节）；冷启动在第一个 drop 有固有代价（10/38）。T-038 把 D 列为「以后」；T-047 定了不做 ARA 和两遍渲染。
- **提案**
  - 界面拖入当前曲的 WAV（或 mixdown）→ 后台线程用**同一套**实时代码路径（MusicAnalyzer + LiveProfile，块长无关）跑完 → 得到「已播一遍」的 LIVE 统计。置信度封顶 0.9，标记「来自文件」。之后实时音频照常更新。
  - 防错配：实时输入的前 30 s 与文件画像差 > 1.5 LU 或斜率差 > 0.5 dB/oct，就丢弃文件统计。
  - 这不是两遍渲染（不用导出两次），也不是 ARA。
- **依据**：Logic Mastering Assistant 分析整个工程；在线母带服务处理整个文件（T-038 REPORT 结论 2）【一手】；规格「随工程保存」的意义（规格第 5 节）【一手（项目）】。
- **对硬约束与 ADR 的影响**：语义上等价于「先播一遍」，但触及 ADR-030「一切自动量由此刻之前的音频算出」的字面——**需要 Max 认可**。分析在后台线程（可以分配）；LIVE 格式不变。
- **代价与风险**：M。风险：各宿主的拖放兼容性要逐个验（T-038 已提）；文件和实际输入可能不一致，靠上面的防错配条件处理。
- **怎么验**：45 首：「拖入后从第 1 小节离线导出」与「先播一遍再导出」逐行对比 metrics，主段输出响度差 ≤ 0.1 LU；M4 = 38/38。
- **对 Max 口味的核对**：全自动、没有聆听按钮，只是可选的拖放；是否接受由 Max 定。

### R5-12 可解释性补充（只列 T-086 没列的，P3 · 界面 · S～M）

- **目标响度分解**：交付基准 + 风格偏移 − LRA 修正 − 置信度收拢 − 约束。决策器本来就逐项算了（`GlazePlanner.h:59-66`）。
- **失真频谱**：把已有的「试听差值」信号按 1/3 倍频程画成能量条。smart:limit 的 Distortion Monitoring 按频段显示失真，并给出「太红就减限幅、加长释放、减饱和」的指引【一手】。
- **交付体检单**：编码后真峰值估计（T-085）、主段 PSR 对下限、LRA、低频相关度、目标偏差，用红黄绿灯显示。参照 smart:limit 的 Quality Check 和 LEVELS 各项红灯，例如 LEVELS「LRA < 3 LU 超过 30 s 就标红」【一手】。

- **收敛度**：配合 R5-06。
- **离线逐段报告**：celadon_render 导出每个段落的输入 / 输出响度、GR、PSR 表，供 Max 比较各次导出。
- 影响：只动界面，主线程按 10 Hz 刷新（界面主线程 21 % 的老问题见 BRIEF 第 4 节）。验证：ui-snapshot 截图与文案检查。代价 S～M。

## 范围外发现（只报不改）

1. **G_trim 抗饱和条件与规格不符**：只在预算环退让时冻结（`GlazeController.cpp:1293`）。规格要求任一守门在退让、或 1 s 内改过参数时都冻结（vault `设计规格-实时GLAZE-主段与增益.md:77`）。接口草图第 4 节第 5 条写的是「预算环正在退让时冻结」，三份文档不一致。后果：G_trim 与落差 / PSR 守门对顶，约 60 s 后守门被抵消（推导见 R5-03）。
2. **PSR 守门读的是输入 PSR，开环**：`GlazeController.cpp:1287` 读 `MusicAnalyzer` 短期视图的 `psr3sDb`（`MusicAnalyzer.cpp:1249-1252`），分析器吃的是链入口原始样本（`CeladonChain.cpp:437-439`）。退让无法改变被测量。没有任何测试覆盖 `PsrGuard` / `ContrastGuard` 在真链上的闭环行为（tests 里只有合同模型）。
3. **两个守门的开关与参数和规格不符**：落差 / PSR 守门对所有曲风常开（`GlazeController.cpp:1286-1288`），规格是「落差 4/4 型开、其余先关；PSR 通用与 House 默认关」（vault 规格:80、83；BRIEF 第 3 节也这样写）。落差守门缺规格里的 10 s 持续、30 s 回差、0.05 dB/s 回程、60 s 和输入 ≥ 3 LU 的前提，实现是 12.8 s 环、8 笔即判（`ContrastGuard.h:42-45`、`ContrastGuard.cpp:65、118-121`）。
4. **阶段 2 验收没做完**：规格第 7.5 条「不拉锯」阈值从没定；第 8 节的真编排器因果重放、合成曲落差、22 首门槛在阶段 2 都没跑（`REPORT-P2-INTEGRATE-SPARK.md` §0）。TASKS 只记了 T-089 / T-090 的 22 首未跑，没有记「不拉锯」阈值和第 7.4 条的冷 / 热启动指标。
5. **渲染追踪仍是校准列占位**：`RenderMain.cpp:2053` 注释说要换成 `confidence, g_trim_db, protection_db, guard_cause`，还没换；也没有逐个守门的退让量和 Glue GR。这影响排查和评估。
6. **`GlazeController.h` 文件头过时**：第 5～100 行仍在详细描述已删除的聆听 / 锁定 / 校准状态机、约束反馈、House 锁定，而 `.cpp` 开头写的是「去掉聆听 / 锁定 / 校准状态机」。BRIEF 说「.h 文件头是最可靠的现状说明」，这一份恰好不可靠，容易误导后来的代理。
