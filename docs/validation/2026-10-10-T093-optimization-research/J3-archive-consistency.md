# J3 · 对抗式复核：档案一致性与查重（T-093）

日期 2026-10-10 · 角色 J3（档案管理员视角）· 只读复核，唯一写入是本文件 · 本机没编译、没跑测试与渲染工具；所有「怎么验」交主会话在 DGX 或项目规定的测试机上跑。
> **总体判断**：58 条里 7 条可直接立项（采纳）、30 条方向对但要改范围或先量（采纳但改）、12 条存疑、3 条否决、6 条与已有项或兄弟提案重复。六份报告的源码引用我抽查了 60 余处，行号和数字绝大多数对得上；真正的问题不在引用，在于**档案一致性**：多条提案要 Max 反转或修订已采纳的 ADR 条款，且没有一份报告把这笔账算清。
> **最被否决 / 存疑的类别**：①「新增或改写会出声的处理级」——R4-01 微动态级、R4-04 三支路 Heat、R1-07 分频限幅、R1-10 虚拟低音（均无真歌证据，唯一依据是玩具模型或专利背景，且碰 Max 对「假」的明确厌恶）；②「碰已定条款的提案」——R5-11 整首预分析（落在规格明写的「不做：前瞻整首」，否决）、R6-02 往下增益（反转 ADR-008 第 3 条的语义）、R6-06 第 1 步学响度（与 ADR-020 第 4 条「不复制响度」相反）、R4-02（撤销 T-079 勘误）；③「无听感证据的调参」——R3-10 Bark 斜率（否决）。
> **最集中的重复**：「一把尺子」被五份报告各提一遍（R5-01 = R1-01 = R2-01 = R3-04 = R4-07 的子集）；「倾斜只留一个参考」被三份各提一遍（R6-01 = R4-03 = R3-05 的 A 部分）；「监听」七条提案互相不协调（R1-03/05/09、R6-04/06、R2-09b、R5-12）。**建议主会话合并时以 R5-01、R6-01、R6-04 为各自的主提案，其余并入。**
> **最该先修的现状错误**：R6-02 的数据表早于 T-089（#76，`1a0e26a`，2026-10-10 16:22 PDT）且全文未提 T-089，结论要在现行 main 上重跑才能用；R5-05 不是新提案，是 Max 2026-10-04 已批准「留到阶段 2」的老债；R5-02 没提仓库里现成的盲听流程（`tools/render/README.md:556-584`）。

## 1. 裁决口径

| 裁决 | 含义 |
|---|---|
| 采纳 | 证据已核对、无 ADR / 非目标冲突、代价与收益匹配，可直接立项（仍按各自「怎么验」在 DGX 上验） |
| 采纳但改 | 方向成立，但必须缩范围、拆阶段、先量后做、或并入另一条；改法写在理由里 |
| 存疑 | 证据不足（只有玩具模型 / 推断）、要 Max 拍板才能判断、或依赖尚未落地的前置项 |
| 否决 | 落在非目标 / 已定的「不做」，或前提被档案证伪，或无证据且碰已试听行为 |
| 重复或已有（编号） | 与 BRIEF §4 / TASKS / 老 ADR 已有项，或本轮另一份报告的主提案重复；括号里写并入谁 |

复核口径五条：① 对照 BRIEF §4 与 vault 待认领查重；② 对照 ADR-001～032 的「决定」节与规格「非目标 / 留到以后」；③ 对照 Max 已表态（ADR-015 不自动收单、ADR-030 全程实时、House 加宽 0、不做段落响度补偿、预设、硬件建模）；④ 每份报告至少抽查 5 处「现状」断言（第 6 节）；⑤ 跨报告术语与数字一致性（第 7 节）。我是复核者不是作者：不新增提案，所有理由给出可核查的行号、档案节或外部出处。

## 7. 跨报告术语与数字不一致

1. **编号撞号（T-093 对 T-032）**：两套编号都叫 R1-04、R2-04、R3-01…，正文里不带前缀就串了。实例：R2 第 2 节第 5 项的「R1-04（存疑）」指 T-032 的抛物线顶点修正，不是本轮 R1-04；R3-05 / R3-06 / R3-08 里的「R2-04」指 T-032 的低段长窗，不是本轮 R2-04；R4-07 里的「R3-01 的跟进方案（LR4 + 全通）」指 T-032 的 Glue 分频，不是本轮 R3-01；R4-04 里的「R3-03 的过采样」指 T-032 的 Heat 过采样；R6-03 的「T-032 R6-01」指算法 8，不是本轮 R6-01。**综合稿一律写 `T093-R2-04` / `T032-R2-04`。**
2. **目标斜率**：三份算出的数字一致（约 +0.5 dB），但三份把冲突描述成三种性质——R3 说「规格与代码矛盾」，R4 说「两套中性斜率打架」，R6 说「用同一个真源」。实际是两份规格互相矛盾，代码跟的是 `曲风与交付 §3.1`（第 6 节 R3-⑤）。
3. **低频冲击度量三套口径**：R1-01 / R1-08 的 LCF（M 声道 4 阶 120 Hz 低通，3 s 窗峰值 / RMS；R1 G2 要求出口 − 入口 ≥ −1.5 dB，R1-08 守门起点却是 3 dB）；R3-04 的 MD / CF_LF（40～120 Hz 带通，10 ms 包络，每小节 P95 − P10，判据 ΔMD < −1.5 dB）；R5-01 T 组（40～130 Hz 与 2～8 kHz，5 ms 峰 / 50 ms RMS，输出 / 输入比，门槛 ≥ 基线 −0.3 dB）。同一个现象三个量、三个阈值。
4. **PSR 下限数字**：代码 8 / 7 / 6（标准 / 流媒体 / 俱乐部）；`设计规格-实时GLAZE-曲风.md:60-62` 的 Techno 8.5 / 8 / 6.5，B / C 类 8.5 / 8 / 6；T-047 REPORT-C 流媒体 F = 8；R1 在 G3 用 8 / 7 / 6、在 G10 用 8 / 6.5；R5 的触发线 7.5 / 6.5 / 5.5 是代码值减 0.5。规格值与代码值至今没对齐。
5. **监听模式数量**：R6-04 合成 5 种（母带、等响、原声、差值、预听），R6-06 加第 6 种（参考），R1-03 再加 3 种（单声道、侧声道、小音箱），R1-05 要求「原声 + 预听」可叠加——互斥语义与总数没有一份统一。
6. **「低频进限幅」三种互不兼容的结构**：R2-03 的 `y = x + (a − 1)·LP(x)`（零延迟 IIR，+1 ms 前瞻）；R1-07 的分频最小相位限幅；R6-05 的「放进 Limit 检测侧、按带施压」。评估指标也不同（高频 P_slow ≥ 1 dB / 占比 ≥ 50 %，对 HMD 降 ≥ 1.5 dB）。
7. **抖动**：R1 第 6 节「噪声整形抖动——收益近零」，R6-07 与 R6 第 3 节 f1 却说「做一个可选档」。
8. **「守护」一词两义**：R3-03 / R3-09 的守护是 Clay 的峰值守护（`ClayGuard`），R1-08 / R5-03 的守护是 GLAZE 守护族（预算环 / 落差 / PSR）。R3-09 提议的「Limit → Clay 慢反馈」还跨了这两个体系。
9. **符号 κ 撞用**：R3-03 / ADR-032 的 κ 是守护保留比 Σ(g·d)²/Σd²；R5-05 与 `GlazePlanner.cpp` 的 κ 是置信度打折 0.35 + 0.65·min(1, c/0.8)。两处都叫 κ。
10. **新工具脚本**：R1-02 `delivery_check.py`、R2-02 往 `codec_tp_check.py` 加代理、R5-01 `quality_metrics.py` + `quality_gate.py`、R5-02 `tools/listen/ab_blind.py`、R5-07 `tools/reference/build_target.py`。现有 `tools/render/` 已有 `gate_check.py`、`house_gate.py`、`codec_tp_check.py`；新增两个顶层目录前应先合并。
11. **Heat 量级措辞**：R4 说 Heat 100 在 0 dBTP 入口动 −0.017 dB（百分之一量级）；R6-03 说「千分之一 dB 量级」——对默认 Heat 4.2 成立，对 Heat 100 偏小一个数量级。
12. **过时术语残留**：R3-06 / R3 待拍板 6 的「GLAZE 校准」；R5 的 `--trace` 校准列；`tools/render/README.md` 仍写「第一遍聆听」「校准状态」（见范围外发现）。ADR-030 之后这些词只剩渲染工具的诊断含义。
