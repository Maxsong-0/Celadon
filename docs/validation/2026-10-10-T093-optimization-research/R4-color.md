## 0. 提案依赖的现状事实（带出处，不复述其余现状）

- **F1 Color 不降峰均比**：Heat 换算表（`GlazeConstants.h:297-311`）在 +0 dBTP 入口、Heat 100 时响度只变 −0.017 dB，真峰值 +0.001 dB；出厂残差 Heat 的「削峰能力」不到 0.00023 dB（`GlazeConstants.h:340-346`）。Glue 是「真峰值下降比响度下降少，平均 GR 大时 PLR 反升 0.3～0.9 dB」（`GlazeConstants.h:262-265`）。但规格写的目的是「饱和把尖峰削圆、压缩把动态收紧，后面的 Limit 就能推得更响」（`设计规格-Color.md:8`）。
- **F2 自动 Heat 实际听不见**：自动 Heat = 风格底量 12 × 强度（`GlazeConstants.cpp:21-25`），默认 GLAZE 35 % 约为 Heat 4.2。按现行曲线算，满幅 1 kHz 的 THD 约 0.02～0.05 %，GLAZE 100（Heat 12）约 0.07～0.16 %【推断：模型，附录 A1】。
- **F3 Heat 在母带电平下以 3 次谐波为主**：Mid 曲线 `tanh(d·x+b)`，d = 1+h，b = 0.04h（`ColorModule.cpp:383-387`）。小信号近似下 H2/H3 ≈ 6b/(d·A)。Heat 100 时，H2 比 H3 低 6.7 dB（−12 dBFS）/ 13.5 dB（−6 dBFS）/ 20 dB（−1 dBFS）【推断：模型，A1】。这与修订说明「Mid 保留温和偶次谐波」（`设计规格-Color.md:124-126`）的意图不一致。
- **F4 Glue 的量跟着超限估计走**：GR 目标 = `glueShare × E`（`GlazePlanner.cpp:686-708`、`:892`），E 随交付目标与 Ceiling 变。ADR-026 决定 4 原文是「两版母带的音色决策一致」，T-079 的勘误改成了「Glue / Heat / Clip 随目标响度重分摊」。
- **F5 两套「中性斜率」同一口径**：Tone 参考斜率 House 三类都是 −2.25 dB/oct（`GlazeConstants.h:96`，45 首 Jamendo 中位数标定）。目标频谱「自动」在 House 档取 Deep −1.5、Tech −0.75、Melodic −1.25（`CeladonChain.cpp:31-43`，「起点值，待试听」）。两者都是「27 段 1/3 倍频程电平对 log₂ 频率的斜率，粉噪 = 0」（`LiveProfile.cpp:2242-2265`、`BalanceModule.cpp:1768`、`设计规格-曲风与交付.md:32-34`）。目标频谱新实例默认就是「自动」35 %（`ParameterDefaults.h:70-71`）。
- **F6 Max 对 Heat 的已表态**：0.1.6.2 试听反馈「高频刺耳、砂砾感和挤压」（`docs/heat-and-balance-revision.md:3`），之后才改成残差 + 高频预算。

## 1. 提案

### R4-01 微动态级：双包络「相对上压」，正向加密度、反向加冲击（P1 · L）

- **问题 / 现状**：链里没有「不抬峰值、只抬平均电平」的一级（F1）。现代响度常规的那一级，即波形整形或向上压缩，Celadon 没有。Color 的 Glue 和 Heat 都不降 PLR，Clip / Limit 只能从峰值那头削。任务第 5 项的瞬态整形也缺。
- **提案**：在 Color 的 Glue 之后、Heat 之前加一级 `Micro`，具体放哪交 R6 定。算法如下，全部是因果、逐样本的：
  1. 检测：用左右联动的 `max(|L|,|R|)`，先过 30 Hz 二阶高通，次声不进检测。
  2. 两条包络（dB）：快包络 `Lf` 瞬时起音、释放 τf = 30 ms；参考包络 `Lr` 是峰值保持 + 释放，保持取 1/8 音符（无拍点时 120 ms），释放 τr = 350 ms。
  3. 密度方向（α > 0）：`g = clamp(α·(Lr − Lf), 0, Gmax)`，Gmax ≤ 4 dB。增益在局部峰值处自动回到 0，所以峰值不动，鼓点间的身体被抬起来。
  4. 冲击方向（β > 0）沿用 SPL DET 的思路：另设一条慢起音包络 `Ls`（起音 15 ms），`g = clamp(β·(Lf − Ls), −Gmax, Gmax)`，只在起音区加减。
  5. 增益平滑：下降立即生效（零延迟版），上升走 25 ms 一阶。
  6. 静音门：`Lr < −50 dBFS` 时不抬，避免把底噪和混响尾巴抬起来。
  7. 全带同一个增益，不分频，避免全通相移（见 R4-07）。
  8. GLAZE 接法：规划器按画像 PLR / PSR 与风格的密度目标定 α 或 β。温润偏密度，冲击偏 β，通透轻。像 Heat 原来那样用实测换算表（ΔPLR 对 α）接进「超限分摊」，成为一个真正能削峰均比的份额。
- **依据**：
  - Ozone Impact 官方帮助：Impact 正值扩展微动态（更冲），负值压缩微动态（更密）；最多 4 段；Envelope 可按速度同步；每段按 RMS 自动补偿【一手】。
  - SPL Transient Designer 用两条起音快慢不同的包络之差控制 VCA，与电平无关、不需要阈值【一手（厂商描述 + 评测转述）】。
  - Waves MV2 手册：Low Level 是向上压缩，抬低电平、高电平不动【一手（手册摘录）】。
  - Oxford Inflator 手册第 1、2.2、2.5 节：思路是改变样本幅度分布、不用压缩所以不泵。直通模式下输出峰值不超过输入峰值；分频模式为避免互调而设，但输出会超过输入峰值【一手】。
  - 模型（附录 A2，House 合成循环 PLR 14.5 dB）：本提案 α = 0.5 / Gmax 4 dB 时，等真峰值下响度 +1.95 dB；稳态正弦 THD 1 kHz ≈ 0 %、60 Hz 0.17 %；60 Hz + 6 kHz 互调 0.16 %；真峰值不变（+0.02 dB）。breakdown → drop 的段落落差只变 +0.21 dB，因为参考包络只跟 350 ms 内的局部峰值。零延迟、下降立即生效的版本峰值过冲 0.00 dB，1 kHz 音头串的频谱溅射与原样相同（−27.2 dB）。而下降若加 0.5 ms 平滑又不加前瞻，过冲 +1.56 dB【推断：模型】。
  - 对照：Inflator 型固定参考三次整形（k = 0.3）等真峰值 +1.48 dB，但 −1 dBFS 正弦 THD 5.3 %、60 Hz + 6 kHz 互调 14.6 %，正是 Heat 改版时去掉的那类互调【推断：模型】。
- **对硬约束与 ADR 的影响**：
  - 量为 0 时增益精确为 1 并跳过乘法，GLAZE 0 逐位不变。
  - 状态全是逐样本的，任意切块逐位一致；不分配内存；只用 log10 / exp，不融合乘加（ADR-013）。跨平台 libm 末位本来就不逐位，同 V3 的说法。
  - 零延迟版不加延迟。
  - CPU 估计每样本 2 条包络 + 1 次 log + 1 次 exp，约 20～30 ns，48 kHz 下约 0.1～0.15 %。
  - 旧工程：旧快照按算法版本门控，自动量为 0。
  - ADR-001 的 C1 写的是「Tone → Glue → Heat → Mix」，加级要补一份新 ADR；若做成独立模块，则与固定链冲突，交 R6 / Max。
  - 与 ContrastGuard / PsrGuard 的配合（PSR 已低于风格下限时收回密度）交 R5。
- **代价与风险**：L（DSP + 换算表 + 规划器份额 + 测试 + 试听）。风险有三：
  1. 尾巴、混响和底噪被抬起来，是向上压缩的通病（MV2 指南也这么提醒）。
  2. 「同 PLR 下，抬身体是否比削峰更好听」没有客观答案，只能等响盲听。
  3. 正向和 Glue 的 20 ms 起音（放过瞬态）方向相反，需要按风格互斥或者配比。
- **怎么验**：
  - ColorTests 新增：
    - 稳态 60 Hz / 1 kHz 在 −1 与 −12 dBFS 下 THD < 0.25 %；
    - 60 Hz + 6 kHz 互调 < 0.3 %；
    - 1 kHz 音头串真峰值过冲 ≤ +0.05 dB；
    - 输入整体 −20 dB 时增益轨迹相同，误差 < 0.01 dB（与电平无关）；
    - breakdown / drop 合成素材的段落落差变化 ≤ 0.3 dB；
    - 量为 0 逐位直通；块长 {1, 7, 32, 64, 480, 512, 4096} 逐位一致；零分配。
  - 22 首门槛曲：同交付目标闭环渲染，对比 Limit GR 均值 / p95 / 峰值、Clip 活动占比、PLR、PSR，预期 Limit GR p95 少 1～2 dB。
  - Max 等响盲听：开 / 关，及正向 / 反向。
- **对 Max 口味的核对**：全自动，由画像定量，不是「把旋钮调大」。电平无关，不会把 breakdown 抬平，House 的段落落差保住。「冲击」方向正好补上 House 俱乐部版的 kick 冲击。它不碰低频收单 / 宽度，没有「假」的那类空间变化；但抬尾巴可能被听成「糊」，必须先过 Max 试听。

### R4-02 Glue 按画像与风格定量，与「超限 E / 交付」解耦（P1 · S～M）

- **问题 / 现状**：Glue 的 GR 目标 = `glueShare × E`（F4）。E 越大（要更响），Glue 越多。但 Glue 实测会抬 PLR（F1），结果更多 Glue 反而要更多限幅，逻辑方向反了。同一首歌的俱乐部版 / 流媒体版因 E 不同，Glue GR 不同。按 F4 的公式粗算【推断】：入口 −14 LUFS / −1 dBTP，俱乐部档假设 Ceiling −1 dBTP，则 E ≈ 7 dB；流媒体档 Ceiling −2 dBTP，E ≈ 5 dB。温润风格（shareGlue 0.30）的 Glue GR 就是 2.1 vs 1.5 dB，两版音色不一致。这与 ADR-026 决定 4 原文「两版母带的音色决策一致」相背。
- **提案**：`glueForExcess` 改成 `glueForProfile`，GR 目标 = 风格「粘合量」× 画像因子。画像因子用低 LRA / 低 PLR 时少给（素材已紧）、PSR 高且有起音时多给，仍受现有 GR 两个上限与 `glueLowRiskScale` 约束。交付只改 Limit Gain / Clip（以及 R4-01 的密度份额，它真能降 PLR）。Heat 底量同样与 E 无关。`liveGlueReduction`（`GlazeController.cpp:766-803`）照旧。按算法版本门控。
- **依据**：
  - `GlazeConstants.h:262-265`（Glue 不降 PLR）、`GlazePlanner.cpp:16-17`（「每 dB 超限给多少 dB GR」的设计意图）、ADR-026 决定 4 及其勘误【一手：仓库 / 档案】。
  - Giannoulis 2012 的分析：前馈压缩的起音时间决定瞬态是否放过；20 ms 起音放过鼓点，平均电平降、峰值几乎不降，PLR 因此上升【一手（论文摘要与 MathWorks 实现文档）+ 推断】。
- **对硬约束与 ADR 的影响**：GLAZE 0 不受影响。旧快照走旧分支，逐位不变（同 T-032 R6-01 的门控做法）。要改 ADR-026 勘误的口径，等于恢复原文本意，需 Max 定。CPU 与延迟无影响。
- **代价与风险**：S～M。风险在于 Glue 不再随响度目标缩放，「输入已够响」的素材也会拿到风格粘合量。`glueForMakeup` 那条「补偿 ≤ 满强度增益」的退让规则要保留。
- **怎么验**：
  - GlazePlannerTests：同一画像下，俱乐部 / 流媒体 / 标准三档的 `color.glue` 与 `color.heat` 自动增量逐位相同，Limit Gain / Clip 不同。
  - 22 首门槛曲：两版渲染各自归一到同 LUFS 后，长时 27 段频谱差 ≤ 0.3 dB；Glue GR 均值差 ≈ 0。
  - Max 试听两版：只应差在响度与压缩感，不差在音色。
- **对 Max 口味的核对**：Max 的两版交付（俱乐部 / 流媒体）工作流需要同一种「混音性格」，本提案正对这一点。

### R4-03 统一三套倾斜参考（P1 · S；「三个倾斜合并成一个」的可行性交 R6）

- **问题 / 现状**：同一个量（27 段斜率，粉噪 = 0）有两个「中性点」，见 F5。House 中位曲是 −2.2：Tone 认为它中性、不动；目标频谱（Tech 档 −0.75）却要把它往亮推。
  - Balance 的修正 = `clamp(±2.5, 0.35 × (误差 − 1 dB 死区)) × 强度`（`BalanceModule.cpp:1819-1823`）。中心外 11 段（约 80 Hz / 12.5 kHz）误差约 ±5.5 dB，GLAZE 100、强度 35 % 时两端约 ±0.55 dB。
  - 曲子是 −1.5 时，Tone 往暗推 0.2 dB × GLAZE（死区 0.35，`GlazeConstants.h:39`），Tech 目标却往亮推：方向相反、互相抵消。
  - 第三套是 Balance 的 Brighten（每十倍频程 3 dB × Brighten，手动），叠在两者上。
- **提案（立即可做的 S）**：House 档「目标频谱 = 自动」的形状斜率改用与 Tone 同一标定源。也就是三类都以 −2.25 为中性，子类差异只在 ±0.25 内表达，或者先置为与 Tone 相同。通用档的风格斜率（−1.5 / −0.75 / 0）同样换算到同一中性点。
- **可行性评估（给 R6）**：三者都是「dB / oct × 频率」的倾斜，在 dB 域线性相加；最小相位搁架与峰值滤波器级联可以直接合成。合并方案：一个「目标斜率误差」e = s_target − s_measured（长时画像），静态部分给 Tone（两个搁架，相位平滑、便宜），时变 / 形状部分给 Balance 的目标频谱，Brighten 留作用户偏移。前提是只有一个 s_target 来源（曲风 × 风格）。能合，代价 M。
- **依据**：`GlazeConstants.h:96`、`CeladonChain.cpp:31-43`、`LiveProfile.cpp:2242-2265`、`BalanceModule.cpp:1768,1819-1823`、`ParameterDefaults.h:70-71`、`设计规格-曲风与交付.md:32-34,44`（−2.25 的标定数据：Deep −2.21 / Tech −2.19 / Melodic −2.24，三类没有明暗差别）【一手：仓库 / 档案】。
- **对硬约束与 ADR 的影响**：House 目标斜率是链内常数，不进快照（`设计规格-曲风与交付.md:48`），改它旧 House 工程的声音跟着变，需 Max 定。GLAZE 0 不受影响（自动 = 强度 × GLAZE）。本条深化 ADR-020 的待复核项，不重提「默认开不开」那一问。
- **代价与风险**：S。风险在于子类的亮度差异会消失；但标定数据本来就显示三类没有亮度差（同上第 44 行）。
- **怎么验**：GlazePlanner / Balance 单测：斜率 −2.25 的画像下 Tone 增量 = 0，且目标频谱修正 ≈ 0（|每段| < 0.05 dB）。45 首标定集：统计「Tone 增量与目标频谱倾斜符号相反」的首数，现在预计多数 Tech 曲为反向，改后应为 0。
- **对 Max 口味的核对**：−2.25 是 Max 亲自选定的值；本提案让另一套机制服从他的选择。

### R4-04 Heat 改三支路残差：低支路偶次为主、中支路以奇为主、高支路只奇（P2 · M～L）

- **问题 / 现状**：
  - 150 Hz 高通把 House 的厚度来源（kick / bass 的 2、3 次谐波）完全排除在染色外：模型里 50 Hz 的 H2 是 −84 dB。
  - 母带电平下是 3 次主导（F3）。
  - 高频支路两个高频音的差频互调（7 kHz + 8 kHz → 1 kHz）是 −49 dBc，落在中频，没有掩蔽。
  - 现行 2 阶高通把 60 Hz 衰减不够，60 Hz + 6 kHz 旁带 −55 dBc。
- **提案**：保持「原声不动 + 只加残差」的拓扑，只把**残差的输入**用 LR4 拆成三路。原声不经分频，所以全通相位不碰主信号，这是残差拓扑独有的好处。
  - **低 < 150 Hz（只 Mid）**：r = cL·ln(cosh(g·x))/g + kL·odd(x)，偶次为主。残差过 4 阶 40 Hz 高通（压掉 kick / bass 之间的次声差频）和 700 Hz 低通（谐波不外溢成中频毛刺）。1× 即可，残差已低通。
  - **中 150 Hz～4 kHz**：以现行奇曲线为主，偶次 cM ≤ 0.12，把 1 kHz 处 H2 调到约等于 H3，同时把中频差频（1 kHz + 1.2 kHz → 200 Hz）控制在 ≤ −41 dBc。2× 过采样够用：7 次谐波 28 kHz 在 96 kHz 内不折返。
  - **高 > 4 kHz**：只奇次（现行 Tube），保留现有 4 kHz 高频预算与 8×。
  - Side 维持奇对称 ×0.75。Heat 旋钮同时驱动三路，比例由风格定：温润低支路多，通透低支路少。
  - 规划器不再用「底量 12」，改按 R4-06 口径重测的换算表定量。
- **依据**：
  - 模型（附录 A3）：三支路（LR4、cM = 0.12）对现行 Heat 100——
    - 50 Hz H2 −31.5 dB，现行 −84（低频有厚度）；
    - 1 kHz −6 dBFS 下 H2 −43.6 / H3 −43.2，现行 −50.5 / −36.9；
    - 7k + 8k → 1k 差频 −91.5 dBc，现行 −49.4；
    - 60 Hz + 6 kHz 旁带 −82.2 dBc，现行 −54.7（低频和高频不再进同一个非线性）；
    - 50 + 62 Hz → 12 Hz 次声积 −45.8 dBc（用 2 阶 35 Hz 时；改 4 阶 40 Hz 预计约 −64）【推断：模型】。
  - 反例：中支路偶次给到 cM = 0.35，或全带偶次主导，中频差频会升到 −31～−34 dBc（现行 −49），和 F6「砂砾感」同类。所以偶次只放在低支路和少量中频。
  - 外部：
    - Hamm 1973（JAES 21(4)）：过载时三极管以 2 次为主，晶体管 / 五极管以 3 次为主，听感差异来自谐波权重【一手（转载全文）】；
    - Inflator 手册 2.5 节：Curve 0 时「高阶谐波最少」、低频区更暖【一手】；
    - Black Box HG-2 手册：并联饱和有低 / 全频 / 高三档频段选择，只饱和低中与超低是公开用法【一手】；
    - FabFilter Saturn 2：最多 6 段、分频斜率 6～48 dB/oct、可线性相位【一手】；
    - Larsen & Aarts 2002（JAES 50(3):147-164）：给低频生成谐波，靠虚拟音高在小音箱上保住低音感【一手（摘要）】；
    - Le Brun 1979（JAES 27(4):250-266）：Chebyshev 多项式只对满幅单正弦「精确生成第 k 次谐波」【一手】。所以对节目素材，「控谐波」实际就是控多项式阶次，本提案用低阶偶 / 奇两项来做。
- **对硬约束与 ADR 的影响**：
  - Heat 声音变，旧工程会受影响。按 0.1.6.2 的先例，用 Heat 模型版本号门控：旧快照保留旧 Heat，自动方案按新模型重算。
  - 延迟维持 64：三路用整数延迟对齐（49 / 60 / 64，近似链已有补齐先例）。
  - CPU：低路 1× 很便宜，中路 2× 约为现在 8× 链的 20～30 %，高路同现在，合计约 +30～50 % 的 Heat 开销。
  - 空闲跳过、预热、近似链要覆盖新支路。这是 V3 警告过的契约最密的状态机，需全套逐位用例。
  - 若采纳低阶多项式核，T-047 3c / R3-03 的过采样问题对中低支路自然降为 1× / 2×。本条依赖并深化它们，不另提。
- **代价与风险**：M～L。风险：
  1. 低频谐波过量会让 100～300 Hz 发糊，且可能被听成「假低音」，与 Max 嫌自动收单「假」是同类风险；
  2. 中低支路偶次在密集 House 低中频上的差频可能「浑」；
  3. 门控与重标定的工作量。
- **怎么验**：
  - ColorTests 新增 / 改：
    - 50 Hz −6 dBFS 下 H2、H3 落在设定窗口；
    - 1 kHz −12 / −6 dBFS 下 H2 − H3 ≥ −1 dB；
    - 7k + 8k → 1k ≤ −70 dBc；1k + 1.2k → 200 ≤ −40 dBc；60 + 6k 旁带 ≤ −65 dBc（收紧现 `:724` / `:799` 门槛）；50 + 62 → 12 Hz ≤ −60 dBc；
    - 现有混叠（`:591`）、THD < 4 %（`:688`）、低频基波（`:851`）、纯 Side（`:878`）、空闲跳过 9 场景用例全过。
  - 22 首门槛曲：等响后 100～300 Hz 段能量变化、PLR 不变（Heat 本不承担削峰）。
  - Max 在大音箱和手机 / 笔记本上做等响 A/B。
- **对 Max 口味的核对**：直接回应「高频刺耳、砂砾感」：高频差频比现在低 40 dB。低频厚度是 House 的核心，但「假」的风险要靠 Max 试听来定低支路的上限。可以先出「低支路 0 / 中 / 高」三档试听包。

### R4-05 Glue 释放按拍速封顶（P2 · S）

- **问题 / 现状**：Glue 释放 50～500 ms，按近 500 ms 平均 GR 自适应（`ColorModule.cpp:1318-1319`）。GLAZE 常用区平均 GR 约 1.3 dB，释放约 150 ms。124 BPM 一拍 484 ms，GR 在一拍内回到约 0，下一个 kick 再压下去，泵的周期与小节没有锁定关系。Limit 在 House 档已经有「一拍 ÷ 3」的释放上限（`CeladonChain.cpp` `beatReleaseCapFor`），Glue 没有。
- **提案**：House 曲风、宿主拍速有效时，Glue 的释放时间常数封顶为「拍长 ÷ kG」，kG 待试听，候选 2 或 4，下限仍 50 ms。拍速无效时与现在逐位相同。`ColorModule::Params` 加一个 `beatReleaseCapMs` 字段，由链填写，同 Limit。
- **依据**：Ozone Impact 帮助：包络时间可锁拍速（Sync）【一手】；Celadon 自己的 Limit 跟拍先例与 ADR-026「曲风管限幅跟拍」【一手：仓库 / 档案】。「释放跟着速度呼吸」能否更好听是【推断】，需试听。
- **对硬约束与 ADR 的影响**：通用曲风逐位不变；GLAZE 0 下手动 Glue 也受封顶。这和 Limit 跟拍对手动 Limit 的口径要一致，需 Max 定。无延迟 / CPU 变化。ADR-026 的「跟拍」范围要扩到 Glue。
- **代价与风险**：S。风险：封顶让 GR 回得更快，会提高泵的深度；所以封的是「慢的一侧」还是「快的一侧」要先用测量定（见下）。
- **怎么验**：用合成 House 循环（附录 A 的生成器即可移植进 tests）在 124 BPM、Glue 40 下，算 GR 轨迹在拍频及倍频处的能量（泵指数）和每拍 GR 回落比例，比较现行 / kG = 2 / kG = 4。22 首里有宿主拍速的曲做同样统计。最后由 Max 试听。
- **对 Max 口味的核对**：House 专属、由宿主拍速自动决定，属于「根据音乐状态」。

### R4-06 非线性级的补偿与换算表统一用 K 加权响度（P2 · S）

- **问题 / 现状**：Heat 的 −18 dBFS 正弦 RMS 补偿表在残差拓扑下只把残差乘 1.004～1.016（Heat 0～100），几乎等于没有【推断：模型 A1】。规划器的 Heat 表则用响度测（`GlazeConstants.h:290-296`），两套口径并存。新增的 R4-01 / R4-04 会产生 2～8 kHz 的谐波和起音变化，K 加权在约 1.5 kHz 以上加约 +4 dB，按 RMS 补偿会系统性低估响度增量。
- **提案**：
  1. 新的非线性级不做静态正弦补偿表，自身保持「单位增益 + 无补偿」，响度变化全部进规划器换算表。
  2. 换算表按 BS.1770 K 加权整合响度 + 8× 真峰值，在**两种素材**上测：现有低频主导类音乐，加一份中高频密集素材（附录 A 的 House 合成循环）。现有表的注释承认「该低频主导素材未触发高频保护」，单一素材不够。
  3. 删除或注明 Heat 的 −18 dB 表只是兼容项；改动就会改输出位，要门控。
- **依据**：ITU-R BS.1770-5（2023-11，现行）的 K 加权由高搁架预滤波与 RLB 高通组成【一手】；`GlazeConstants.h:290-311` 的测法注释【一手：仓库】。
- **对硬约束与 ADR 的影响**：只改标定方法与表，不改 DSP。若删 −18 dB 表，Heat 开时每个样本改末位，按版本门控。
- **代价与风险**：S；风险低。
- **怎么验**：GlazeBehaviourReport 增加第二素材，输出两张表的差。若同一 Heat 值在两种素材上 ΔLUFS 差 > 0.2 dB，说明单素材表不可用。ColorTests：粉噪与 House 循环在 R4-01 / R4-04 满量下，K 加权电平变化落在表预测 ±0.3 LU 内。
- **对 Max 口味的核对**：等响 A/B 的公平性（T-086 A/B 快照）依赖这一口径，Max 判断「好不好听」时不被响度骗。

### R4-07 验证方法：凡分频方案，必须带「只分频不处理」的全通对照组（P2 · S）

- **问题 / 现状**：模型里，150 Hz 的 LR4 分频后直接相加（全通、不做任何处理），就让 House 合成循环在等真峰值下响度 +2.40 dB。原因是合成 kick 的音高滑过分频点，相位被打散，峰值下降。「分频后只整形低段」得到的 +2.98 dB 里有约 2.4 dB 来自全通本身【推断：模型 A2】。R3-01 的跟进方案（LR4 + 全通）、R4-04、任何多段限幅评估都会踩到这个混淆。
- **提案**：把「分频 → 相加、不处理」作为必带对照，写进验证规范：ColorTests / render 报告的每个分频方案都同时报「对照组 Δ」与「方案 − 对照组」。相位旋转本身能否作为低失真降峰手段，交 R2 评估；真实歌曲上效果可正可负，广播处理器有相位旋转的先例，本报告不展开。
- **依据**：附录 A2 数字【推断：模型】；Inflator 手册 2.2 节也指出直通模式能更好地保住谐波相位，分频模式输出会超出输入峰值【一手】。
- **对硬约束与 ADR 的影响**：无（只是验证方法）。
- **代价与风险**：S。
- **怎么验**：在 22 首门槛曲上跑一次 LR4@150 全通对照，记下 PLR 变化的分布，作为后续分频方案的基线。
- **对 Max 口味的核对**：防止把「相位效应」误当成「算法收益」端给 Max 试听。

## 2. 任务清单逐项结论（含评估后不建议做的）

1. **残差法 vs 全带饱和**：残差法的好处是实测的：低频驱动高频的互调降 26 dB（`docs/colour-and-render-revision.md:41`），且原声电平不动。代价有三：不削峰（F1）、低频无染色、高电平 3 次主导（F3）。全带饱和只在要它承担削峰时才有理由，而那件事 R4-01 用无谐波的方法做得更干净（附录 A2：全带三次整形在 ΔPLR 1.5～2.2 dB 时 THD 5～8 %、IMD 15～23 %；相对上压同量级 ΔPLR 下 THD < 0.2 %）。**结论：保留残差拓扑，按 R4-04 分支化。**「瞬态圆化」：残差 Heat 峰值几乎不变，本来就不圆化，圆化交给 Clip（R2）。
2. **150 Hz 高通对 House**：对中高频支路是对的，防互调。把低频彻底排除是缺口，R4-04 的低支路补上，而且由于不同非线性之间相互隔离，60 Hz + 6 kHz 互调反而更低。不建议全带回到单一非线性。
3. **曲线族**：
   - 软膝多项式 / 低阶偶奇两项：采纳（R4-04），还能让中低支路的过采样降到 1×～2×。
   - Chebyshev：对节目素材没有「精确控谐波」的性质（Le Brun 1979 的前提是满幅单正弦），不单列。
   - 磁带型带滞回：属于有记忆的非线性，和 ADAA / 预热 / 空闲跳过契约冲突，CPU 高，又贴近「硬件建模」非目标。**不建议**。
4. **Glue 拓扑**：
   - 反馈型：SSL G 型被评测为反馈型，检测取自辅助 VCA 输出（Bonedo 评测）；API 2500 的 Old = 反馈、New = 前馈（API 官方页）。Giannoulis 2012 推荐前馈（稳定、可预测）。在 2:1、GR 1～2.5 dB 的粘合量下，反馈 / 前馈的差别主要是拐点自然变软，前馈改软拐点宽度就能做到。**不建议加反馈模式**：多一个闭环，与分频 Δ、自动补偿交织，验证成本高，自动化又说不清该选哪种。
   - RMS / 混合检测：现行是「瞬时峰值 + 对数域平滑」，正是 Giannoulis / MathWorks 的推荐写法；R3 实测纹波 THD ≤ 0.08 %，检测器不是瓶颈。**不建议改 RMS**。
   - Thrust / K 加权侧链：会提高对踩镲 / 拍手的敏感度，House 素材上有「被镲压」的风险，现有高带 Δ 只能少压不能免压。**不建议**，若要试只作对照。
   - 程序自适应起音：Glue 的职责是粘合、不是响度（F1），收益不明。**不建议**，先做 R4-02 / R4-05。
   - Glue 在母带里的真实收益与副作用：收益是「粘合」，主观、测不出。可测的副作用有三项：PLR 升 0.3～0.9 dB（F1），拍频泵（R4-05 的泵指数），分频 Δ ≠ 0 时的相位凹陷（R3-01，待拍板）。可测方案：等响下的 PLR 变化 + 泵指数 + Glue 开 / 关的盲听。
   - 起音口径附注：「攻击 20 ms」是一阶 τ（10～90 % 约 44 ms），和硬件手册、MathWorks 的 log 9 口径不可直接比，别按手册数字去对齐。
5. **密度级放哪**：算法见 R4-01。它与电平无关，所以放在 Color 可以。Inflator 型「固定参考」整形必须以 Ceiling 为 1.0，天然属于 Limit 的 Gain 之后、Clip 之前，那是 R2 / R6 的地盘。对限幅器的影响：ΔPLR 约 −1.2～−2 dB，目标响度固定时 Limit 峰值 GR 约少同量（一阶近似）。
6. **Tone 动态倾斜**：已有。运行中 Tone 按短时斜率 0.15 dB/s 跟随（`GlazeController.cpp:743-764`），与 Balance 的 10 ms 帧动态重复。不再加动态 tilt，问题在参考不统一（R4-03）。
7. **补偿与分摊**：补偿见 R4-06，分摊见 R4-02。Heat 的分摊在算法 8 起已只认「真能削的份额」，残差 Heat 下恒为底量（F2），所以 Heat 的问题在于「量化标准」，不在分摊。

1. **加不加微动态级（R4-01）**，加在 Color 里还是独立工序（触及 ADR-001 的 C1 / 固定链，R6 给位置）。是否给手动旋钮（新参数 ID，只许追加），还是只做自动内部量。延迟取零延迟版还是 1 ms 前瞻版（与 ≤ 10 ms 目标、T-088 相关）。
2. **两版交付是否必须「只差响度」（R4-02）**：要不要恢复 ADR-026 决定 4 的原文口径，撤回 T-079 勘误所描述的行为。
3. **斜率的唯一权威来源（R4-03）**：Tone 的 −2.25（Max 标定）与目标频谱子类斜率谁服从谁；改动会让旧 House 工程声音变化（链内常数不进快照）。
4. **Heat 低频谐波是否可接受（R4-04）**：上限多少、是否只在某些风格开；Heat 声音变化按模型版本门控的口径。
5. **Glue 跟拍是否也约束手动 Glue（R4-05）**，与 Limit 跟拍对手动值的口径要一致；kG 取值。
6. 「好听」的完成标准：以上 R4-01 / 04 / 05 都只能靠 Max 等响盲听验收，需要定试听包的形式与通过标准。

## 范围外发现（只报不改）

1. `Source/dsp/ColorModule.h` 文件头没有写 Heat 的高频残差预算（4 kHz 一阶拆分、预算 3.5 %、最低 0.35 倍、15 / 250 ms，`ColorModule.cpp:1720-1761`），只有 vault 规格有。`ColorModule.h:113-115` 与 `protectHeatResidual` 的注释是英文，与项目「注释用中文」的规则不一致。
2. Heat 的 −18 dBFS 补偿表（`ColorModule.cpp:389-445`）在残差拓扑下只把残差乘 1.004～1.016，实际无作用。头文件与规格「轻微残差 makeup」的说法容易误导（见 R4-06）。
3. 规格与代码把 Glue 写成「攻击 20 ms」，实为一阶 τ（10～90 % 约 44 ms），和行业 / MathWorks 的口径不同，建议在规格里注明。
4. ADR-026 决定 4 正文（「两版音色决策一致」）与括号里的 T-079 勘误相互矛盾，同一条决定有两种口径（R4-02 的前提）。
