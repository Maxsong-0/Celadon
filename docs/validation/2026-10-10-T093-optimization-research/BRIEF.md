## 1. 这是什么插件、给谁用

- **Celadon**：自用母带插件（VST3 / AU，Mac 通用二进制 + Windows x64），JUCE 9.0.2，C++。非商用，用户是 Max 和朋友。官网 celadonaudio.com，当前版本 0.1.8.10（发版中）。
- **一句话**：一个大旋钮 GLAZE（0～100 %）= 「一插总轨就好听」的全自动母带；三合一链 Balance（Gullfoss 式动态频谱平衡）→ Clay（修坯：低切 / 收单 / 加宽）→ Color（The God Particle 式染色：Tone / Glue / Heat）→ Limit（Invisible Limiter 式透明限幅 + Clip）。每个模块有手动旋钮与 Bypass；GLAZE = 0 时实际参数逐位等于手动值。
- **Max 的口味与已表态的事**（必须尊重）：
  - 主要写 **House**（Deep / Tech / Melodic-Progressive），两版交付：俱乐部版（DJ / 下载店）与流媒体版。
  - 目标是**全自动**：「大旋钮不能是把所有旋钮调大，要根据音乐的整体状态全自动通过算法实现效果以及提高音量」（2026-09-25）。
  - 2026-09-27 试听自动低频收单：「不自然、有点假」→ 自动收单永久去掉（ADR-015），只留手动收单与反相提示；2026-10-01 再次确认不按曲风重开。
  - 宽度：「窄的歌才适度加宽」，母带不拉宽；House 档自动加宽系数 0。
  - 2026-10-02 拍板「全程实时处理」：**完全取消聆听 / 锁定 / 校准**，一切自动量由此刻之前的音频连续算出（ADR-030）；CPU 预算 15 % → 20 %；延迟目标 ≤ 10 ms。
  - 明确不做（设计规格-总体「非目标」）：商用发布与授权、AAX、**硬件建模（SSL / 磁带）**、真·听觉遮蔽模型、**多段限幅（写的是「v0.3 试听后再评估」，可以重新评估）**、**预设系统**（v1 靠 DAW 存状态）。「留到以后」：Width（M/S 宽度）、Balance 的 Bias、Learn 静态匹配（0.1.9.0 做了一版「参考」目标频谱）。
  - ARA、两遍渲染、按宿主走带判断换歌：T-047 定为不做。

## 2. 现行信号链与各级算法（源码 `Source/dsp/`，每个 .h 文件头都有完整说明，**请直接读**）

```
输入 ─┬→ Balance → Clay → Color → Limit → [OUT 表] → GLAZE 出口 → Listen（等响）→ 试听差值 → 归一化预听 + TPDF 抖动 → 输出
      └→ IN 表（真峰值 + LUFS 100 ms 子块）+ Balance 分析帧 + 原始样本 → 实时画像 LiveProfile → 决策器 GlazePlanner → 守护族
```

## 3. GLAZE 控制层（实时版，T-047 / T-048，0.1.8.9 起）

- **实时画像 LiveProfile**：按段记账（宿主给拍点时一段 = 一小节，否则 2 s）；「回看重判」——保留最近的段（环形缓冲），每来一段按此刻的参考 S_ref（段响度 P95）/ lowRef（低频占比 P95）重算每段的主段度 m（4/4 型 = 响度门 × 低频门软与；响度型只响度门；被动型恒 1），主段加权合并出画像（I、LRA、真峰值 / PLR、27 段频谱与 Tame / Recover 证据、斜率、起音、立体声、次声占比、实时试算代价）；按进账遗忘（W_mem ≈ 1.5 × 32 小节）；置信度 c = 1 − exp(−M/M0)，M0 = 6 小节；长时间无主段衰减；换歌软遗忘（内容判定，不看走带）。
- **决策器 GlazePlanner**（纯函数）：画像 × 风格（自动 / 温润 / 冲击 / 通透，权重混合三套常数）× 曲风（通用 / Deep / Tech / Melodic；只换 Tone 参考斜率 −2.25 dB/oct、低切目标 25 Hz、加宽系数 0、往亮上限）× 交付（标准 / 流媒体 −10 LUFS −2 dBTP / 俱乐部 −7 LUFS）→ 方案：Limit Gain 增量、Balance Recover / Tame 自动份额、Tone、Glue / Heat / Clip 量（按「真峰值 + 增益 − Ceiling」的超限估计分摊，受风格预算封顶；算法 8 起自动 Heat 只承担换算表里真能削掉的峰均比份额）、Clay 自动值（低切按次声占比 × 代价系数，加宽按高频侧中比 × 相关度上限）。标准档「输入已够响仍可请求 +3 dB」；流媒体 / 俱乐部档 T-089 起不超交付目标。
- **增益链**：每 1 s 重算目标 → 速率限制（上 0.2 / 下 1 dB/s）+ 棘轮（主段度 < 0.5 只降不升）→ 自动增量；Limit Gain = 手动 + 增量 + G_trim（输出侧主段电平闭环，≤ 0.05 dB/s，±3 dB）+ g_守护。
- **守护族**：预算环 `GlazeGuard`（Glue / Limit GR 均值 p95 峰、Clip 活动与深度，3 s 窗超出满 1 s → 1 dB/s 退，−3 dB 封底）；落差守门 `ContrastGuard`（输入 / 输出 (P90 − P25) 短期响度差 > 1.2 / 1.5 LU → 0.1 dB/s 退）；PSR 守门 `PsrGuard`（3 s PSR < 下限 − 0.5 持续 3 s → 0.5 dB/s 退；现有四项默认关）；`ClayGuard`（反相提示、宽度保护）；压力反馈（守护回收过多就减低切）。
- **状态行**七条（跟随 / 保持·本段较轻 / 起步 / 受限·预算 / 交付峰值 / 保对比 / 受手动设置限制）；`LIVE` 存档节点随工程保存；重复导出不保证逐位相同（T-087 冻结开关在议）。
- 关键源码：`GlazeController.{h,cpp}`（1686 行）、`GlazePlanner.{h,cpp}`（2082）、`LiveProfile.{h,cpp}`（3199）、`MusicAnalyzer.{h,cpp}`（3884）、`SegmentLedger.*`、`GlazeConstants.{h,cpp}`（全部出厂常数）、`GlazeGuard.*`、`ContrastGuard.*`、`PsrGuard.*`、`OutputLevelTracker.*`。
