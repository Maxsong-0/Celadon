> **总体判断**：6 份报告共 58 条提案，没有一条被硬约束直接挡死。裁决：采纳 20、采纳但改 22、存疑 12、重复 3、否决 1（R6-08，我同意 R6 自己「现在不做」的结论）。工具与指标类（不改声音）几乎全部可行，应合并成一条管线先做。

## 0. 怎么复核的

- **逐条核对四件事**：① 逐位契约（GLAZE ≤ 0 时交给模块的参数逐位等于手动值；块长无关；旧工程不改声音）；② 音频线程不分配、不加锁，不用 fast-math，不依赖 FMA（ADR-013）；③ 延迟（现 1384 样本，目标 ≤ 10 ms）与 CPU（48 k / 32 最慢块 ≤ 15 %，整插件 ≤ 20 %）；④ 接口改动面（Params、BlockStats、编排器、LIVE 存档、参数 ID 与选项只许末尾追加）。
- **判定怎么映射到结构化裁决**：可行 → 采纳；可行但代价要改 → 采纳但改（合并、拆步、改结构也归这一类）；存疑 → 存疑；被硬约束挡住 → 否决；和别的提案是同一件事 → 重复或已有。
- 现状的判断全部以源码为准，不信报告转述。每份报告我都抽查了至少 2 条技术断言，结果在第 3 节。

## 1. J2 横向发现（会影响多条提案的事实，按严重度排）

**J2-A　κ（守护保留比）不能直接进声音路径。**
- `ClayGuardKeepMonitor::update`（`ClayGuard.cpp:707-735`）每个切片做一次 `exp(−seconds/τ)` 衰减，再按 `E·τ(1−decay)/seconds` 折算。编排器每个切片调一次（`GlazeController.cpp:1316`），而切片会随宿主块长变（`CeladonChain.cpp:405-421`）。
- ADR-032:19 写的「结果与片长无关」只在数学上成立，浮点末位做不到逐位。
- 现在 κ 只进界面，没有问题。但 R3-03 要把它接进压力反馈（→ `scaleClayPlan` → 声音），那样块长 {1, 7, …, 4096} 下降档时刻可能差一个切片，违反「统计按固定网格、块长无关」（vault `设计规格-实时GLAZE.md:53-54`）。
- 修法：两份能量按 10 ms 守护时隙累计，在时隙边界再平滑（同 `GlazeGuard`）。

**J2-B　R2-03 阶段 2 的减法拆分不是频段增益。**
- 稳态传递函数 H = 1 − (1 − a)·LP。用 numpy 解析计算（fc = 120 Hz）：

| LP | a = −3 dB：最大抬升 / 50 Hz | a = −6 dB：最大抬升 / 50 Hz |
|---|---|---|
| 2 阶 Butterworth | +0.55 dB @177 Hz / −2.12 dB | +0.97 dB @169 Hz / −3.55 dB |
| 4 阶 Butterworth | +1.80 dB @108 Hz / −0.81 dB | +2.90 dB @107 Hz / −0.90 dB |
| LR4 | +1.41 dB @99 Hz / −0.48 dB | +2.31 dB @97 Hz / −0.37 dB |

- 逐样本在峰值处解 |HF + a·LF| ≤ c′，按构造仍然成立。问题出在 a 持续小于 1 的那 60～120 ms：真正的低频没降够，100～170 Hz 反被抬高，抬的正是底鼓「肉」那一段的峰，最后还得靠宽带级兜底。
- R2 的 S3「泵深 0.32 dB」是在理想分频上算的，不能外推到这个结构。
- 只有一阶 LP 时，H = (s + a)/(s + 1) 是没有鼓包的低搁架。另一条路是时变的最小相位低搁架。两种都要带 R4-07 的全通对照组。

**J2-C　交付封顶不看 GLAZE。**
- `CeladonChain.cpp:264-276` 先扣编码余量，流媒体档再封顶 −2 dBTP。这两步都在 `controller.beginBlock` 之前，GLAZE 0 照样生效：它们算「手动值」的一部分，所以编排器层面的 GLAZE 0 契约仍然成立。
- 回答 R1-02(b) 提的问题：俱乐部档的 −1.5 一旦写进链常数，GLAZE 0 的俱乐部工程 Ceiling 也会变。受影响的只有 T-038 之后选了俱乐部、且用户 Ceiling 高于 −1.5 的工程。

**J2-D　CPU 基线已经过时。**
- 仓库里最近一次「结构性最坏」实测是 T-021（2026-09-28，`modules-after-T020.log:17-36`），早于 T-047 / T-048 实时 GLAZE。
- 当时 48 k / 32 的结构最坏是 2.0～2.7 %（门槛 15 %，余量很大）；192 k / 32 是 15.9～18.4 %（REPORT 表里 17.4 → 19.4 %，门槛 20 %）。
- 所以凡写「+0.0x %」的提案（R3-01、R4-01、R4-04、R5-08、R6-06、R2-03），在 48 k 下都不成问题，真正卡的是 192 k / 32。另有一个 96 k / 32 单块 474 % 的尖峰至今没有归因（vault `TASKS.md:189`）。
- 先补一份含实时 GLAZE 的新基线，再给这几条放行（`scripts/perf-local.sh` 是 Mac 本机工具，见「待用户拍板」4）。

**J2-E　GLAZE > 0 时块长契约管到哪一层。**
- 代码注释写着「every slice uses the same executed settings … a newly computed correction becomes audible at the next setParams」（`CeladonChain.cpp:414-417`）。也就是说，统计按固定网格走，与块长无关；但校正什么时候生效跟着宿主块走，GLAZE > 0 时音频输出本身大概率不随切块逐位相同。
- 报告里写的「块长无关」应统一理解为「新控制量按固定网格推进」。是否属实，请主会话按第 5 节第 5 条验。

**J2-F　监听类提案有个共同前提。**
- Listen 是存进工程的参数（`PluginProcessor.cpp:92, 445`）。离线时它不关（`CeladonChain.cpp:367`），只有预听会关（`:166`、`:304`）。
- T-086 已认领「等响改为不进工程的监听状态」（vault `TASKS.md:22`）。
- R1-03 / R1-05 / R1-09 / R2-09b / R6-04 / R6-06 第 2 步改的都是同一段交接代码（`CeladonChain.cpp:305-336`）。应先由 T-086 把监听级重写好，再按「模式」往上加；否则每条都要在特例上再叠一层。

**J2-G　守护族与规格的偏差，R1 / R5 报的全部属实。**
- PSR 守门读的是链入口：`GlazeController.cpp:1287-1288` → `MusicAnalyzer.cpp:1248-1254`，而 `analyzeInput` 在各模块之前（`CeladonChain.cpp:437-439`）。
- G_trim 只在预算环退让时冻结（`:1293`），规格要求任一守门退让都冻结（vault 规格:77）。
- 落差守门的实现：128 笔环、满 8 笔就判、回程与退让同速（`ContrastGuard.h:42-45`，`.cpp:65、112-127`）。
- 两个守门对所有曲风常开（`GlazeController.cpp:1286-1288`），规格是按曲风开（vault 规格:80、83）。
- 补一条：落差守门每次 `process` 都把两份 128 笔拷贝出来做 `std::sort`（`ContrastGuard.cpp:71-80`）。不分配内存，但每块都是 O(n log n)，48 k / 32 下每秒约 1500 次 × 2。按规格改成直方图（R5-03a）可以顺带消掉。

**J2-H　重复与合并。**
- 倾斜参考统一：R6-01（主）= R3-05 A = R4-03。
- 指标管线：R5-01（主）⊇ R1-01、R2-01、R3-04、R4-07、R2-09a、R3-07 第一步、R2-03 阶段 1、R2-07 阶段 1、R2-08、R3-02 第一步、R3-09 诊断。
- 低频 / 多段限幅：R2-03（主）= R1-07。
- 参考：R5-07（主）⊇ R3-05 B；R5-08 ≈ R6-06 第 1 步；R1-09 = R6-06 第 2 步。
- 监听：T-086 ⊇ R6-04b；R1-03、R1-05、R1-09 排在它后面。
- 交付检查：R1-02a ≈ R2-02 (a)(b) ≈ R5-12「交付体检单」的离线版。

## 4. 最省改动面的落地顺序

原则：先做不改声音的事，再做只改 GLAZE > 0 的控制层，最后才动 DSP 级；每一阶段都用上一阶段的尺子来验收。

1. **只加工具，插件逐位不变（S～M）**：R5-01 统一指标管线（吸收 R1-01、R2-01 钩子、R3-04、R4-07 对照组、R2-09a 计数、R3-07 第一步、R2-03 / R2-07 阶段 1、R2-08 网格、R3-02 第一步、R3-09 诊断）；R5-02 盲测工具；交付检查（R1-02a + R2-02 a/b）；R6-03 对照实验（要给渲染工具补一个「重放时覆盖参数」的开关）；补一份含实时 GLAZE 的新 CPU 基线（J2-D）。
2. **按规格修缺陷（S，只影响 GLAZE > 0 与离线）**：R5-03a 修守护族三处缺陷（是按规格修还是追认现状，先拍板）；R6-04a 离线时强制关 Listen；R5-06 状态行提示。
3. **零延迟、零 CPU 的小改（S～M）**：R6-01 统一斜率来源；R6-02 往下的增益路径；按 R6-03 的 ABX 结果决定 Heat 底量。
4. **控制层（S～M）**：R5-05；R5-04；R3-03（κ 先改固定时隙）；R4-02；R5-10；R3-02（第一步过线才做）。
5. **监听级（M）**：在 T-086 里合并 MonitorStage（= R6-04b），再按模式追加 R1-03、R1-05、R1-09 / R6-06 第 2 步、R2-09b；R1-04 读数可以并行做。
6. **DSP 新级（L，每条先过「强度 0 逐位 + 块长 + 22 首 + 新 CPU 基线 + R5-02 盲测」）**：R3-01 共振层 → R2-03 阶段 2（先改结构，放独立原型分支）→ R4-04 / R4-01（看 R6-03 与盲测结果再说）。曲库目标（R5-07 + R3-05 B + R5-08 / R6-06 第 1 步）可以和第 6 阶段并行，但排在 R6-01 之后；R5-09 最后做。
