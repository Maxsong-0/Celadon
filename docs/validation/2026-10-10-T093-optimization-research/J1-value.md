# J1 · 对抗式复核：产品价值与母带师耳朵（T-093）

> **一句话结论**：6 份报告共 58 条提案，真正能让 Max 在等响 A/B 里**听出变好**的不多，集中在四件事：热混音的流媒体 / 俱乐部版**先调轻再限幅**（R6-02）、让等响 A/B 本身**不再藏起落差损失**（R2-09 b）、修好**互相顶牛的守护族**（R5-03 改）、去掉默认路径上**没人试听过的「往亮」**（R6-01）。其余大多是「先量再说」的尺子，或者 DSP 工程师觉得有意思、但找不到可闻收益证据的新算法。
> **总体判断**：采纳 8｜采纳但改 15｜存疑 21｜否决 11｜重复 3。**被否决和存疑最多的一类是「改声音的新算法 / 新工序」**：16 条全部判了存疑或否决（共振层、微动态级、Heat 三支路、M/S Balance、虚拟低音、Bark 掩蔽、ERB 合并、Glue 跟拍、IOI 跟拍等）。它们的共同问题是证据只有合成信号或 numpy 玩具模型，没有一条在 Max 的素材上证明过可闻收益，而且多数会给全自动链再加一层不好解释的自动量。第二多的是「再加一层控制」（8 条全部存疑或否决），其次是「监听 / 读数类功能」（7 条里 5 条）。
> **点名纠错 6 处（第 5 节），最要紧的 4 处**：① R3-03 重提了 ADR-028 已否决的备选（保留比当触发量），也没有回应 emotapes 这个反例；② R6-02 引用的 T-085 数据早于 T-089，旧规划器多推的那部分已经修掉，量要重渲；③ R4-01 的「透明」证据没量拍频调制，按它的公式，它会制造与限幅泵同型的相对调制；④ R2 把编码后的「浮点超限」当成比内部误差更紧迫的问题，而 T-085:51 明说这不等于可闻削波。

## 0. 裁决口径

- **可闻门槛**：判断标准是这东西做出来以后，Max 在**等响 A/B**下听不听得出变好。只有合成信号或玩具模型的数字、没有真歌或听感证据的，默认判存疑；拿可闻代价去换不可闻收益的，判否决。
- **自动化成本**：每多一个自动量、守门或常数，都会让「GLAZE 为什么这样做」更难解释（T-086 的方向）。证明不了收益的新自动层一律从严。
- **母带师会要 vs DSP 工程师觉得有意思**：职业做法有一手出处、而且对 House 两版交付有直接作用，才算前者。
- **口味**（BRIEF 第 1 节）：全自动、不假（ADR-015）、母带不拉宽、往亮要克制（House +0.4 dB）、不加预设、不追求功能多、不重开聆听（ADR-030）。
- 「采纳但改」都写明改成什么；「重复或已有」都写明并到哪条。

## 3. 本报告新增提案（研究代理漏掉、母带师真会要的）

### J1-01 混音总线限幅检测与一句提示（不改声音）

- **问题 / 现状**：Celadon 不判断输入是否已经过总线限幅。Max 的 22 首门槛曲里，至少 somggggg / emotapes / fule / woqu 这 4 首被记为「已经限过幅、带次声偏置」（`ClayModule.h:57`；T-044 REPORT:10），也正是守护常亮、低切大半被回收的那几首（ADR-032「后果」节）。T-085 的输入里有 4/9 首比 −10.5 LUFS 响，melodic_241941 入口真峰值 +2.38 dBTP（`render_target_-10.csv` 的 input 行）。面对这类输入，全链能做的很有限：Limit 只能在别人的限幅上再限一次，Clay 的低切被守护收回，Balance / Glue 在密谱上空转。现有七条状态行（BRIEF 第 3 节）没有一条告诉 Max「问题在输入」。
- **提案**：画像加一个只读特征「峰值贴顶度」= 主段 100 ms 子块里，真峰值落在本曲主段最大真峰值 0.5 dB 以内的比例（IN 表子块已经带真峰值，LiveProfile 的主段权重现成），配合入口 PSR₃ₛ 主段中位数一起判断。贴顶度 ≥ 40 % 且 PSR 中位 ≤ 8 dB 时，GLAZE 卡片气泡显示一行：「输入像已经过限幅（主段峰值贴顶 x %、PSR y dB）。若是自己的混音，关掉混音总线上的限幅器再导出，母带能还回更多冲击。」只提示，不改任何自动量（自动量的减法已经由 R6-02 和 `liveGlueReduction` 承担）。阈值先在 22 + 45 首上量出分布再定。
- **依据**：库内证据如上【一手-本库】。「交母带前关掉总线上的砖墙 / 响度限幅器、留 3～6 dB 峰值余量」是混音交付的通行要求（MasteringBOX、Splice 交付指南）【统计】。Apple Digital Masters 要求交付的母带不削波、留余量（R1 已引）【一手】。限幅器输出的峰值分布堆在 Ceiling 附近，是它的定义性特征【推断】。
- **对硬约束与 ADR**：只读特征加界面文字。音频逐位不变，GLAZE 0 不变，0 延迟，CPU 只是每 100 ms 一次比较。贴顶度直方图可以不进 LIVE（读档后重算），存的话格式要升号。参数 ID 不动。
- **代价与风险**：S。风险是误报，把本来就很密的 Tech House 混音当成已限幅。先量分布：对干净混音的误报率要 ≤ 10 %，文案用「像」。
- **怎么验**：DGX 上用 celadon_render 跑：22 首门槛曲；45 首 Jamendo（都是成品，应几乎全亮）；`make_synthetic_house.py` 的干净合成曲（应不亮）；同一合成曲过 −6 dB 限幅（应亮）。报告各组亮灯率，另做 ui-snapshot 检查中英文案。
- **对 Max 口味**：不改声音、不加旋钮、全自动。直接服务「一插就好听」：最大的可闻收益，往往来自把输入里那一级限幅拿掉。

### J1-02 验证语料分三层，处理行为的门槛按层报告

- **问题 / 现状**：45 首 Jamendo 是 MP3 成品（R1-02、R2-02 都承认）；22 首门槛曲里混着成品和 Max 带限幅的粗混（`ClayModule.h:57` 称其为「已经限过幅的成品」，T-032 `R4-clay.md:95` 又称「Max 自己的粗混」，两处说法不一致）。T-038 用成品标定**目标**，这是对的。但守护回收 60～80 %（ADR-028 背景、ADR-032）、R6-02 说的热输入、R2-02 的过冲相关性，都是在成品上量出来的**处理行为**，带有成品特有的偏差。R5-01 的「不退步」基线如果只在这批语料上冻结，就等于没验收「面对干净混音该怎么做」，而那恰恰是母带插件的本职。
- **提案**：R5-01 的基线和门槛分三层出表：**A** 商业 / Jamendo 成品（验目标、验「别帮倒忙」）；**B** 带总线限幅的粗混（Max 的现实用法之一）；**C** 干净混音（没有总线限幅，峰值余量 ≥ 3 dB），由 Max 从自己的工程导出 10～20 首 House mixdown，存放规矩同现有 22 首，不出 Spark。每条处理类门槛注明在哪一层判。
- **依据**：上面的库内事实【一手-本库】；T-047 REPORT-C:191「Jamendo ≠ 商业成品……只定音色与结构类常数」【一手-本库】；【推断】。
- **对硬约束与 ADR**：只改验证流程，不碰插件。
- **代价与风险**：S（工具按清单分组），外加 Max 导 mixdown 的时间。风险是 C 层样本少。
- **怎么验**：分层后重跑 R5-01 基线，比较三层的守护常亮率、平均 GR、PSR 损失。如果三层差异都小于门槛容差，说明不必分层；这个结论本身是可证伪的。
- **对 Max 口味**：不改声音，让「好听」的验收贴近 Max 真实的输入。

### 建议 Max 重新考虑：接口草图 Q3（旋钮改动走共用速率限制）

- **新证据**：Q3 拍板的是「旋钮本块重算目标，施加共用速率限制」（拍板档 2026-10-05：Max 回「可以」，Q1～Q12 全按默认）。代码里 GLAZE / 风格 / 曲风 / 交付改动后，增益和画像驱动的变化走同一条速率限制：上行 0.2 dB/s，主段度 < 0.5 时只降不升（`GlazeController.cpp:453-461`、`:606-625`、`:681-691`）。所以把 GLAZE 从 35 拧到 70、增益目标多 3 dB，要约 15 s 的主段时间才到位，在 breakdown 里则完全不升；换交付也一样（R6 范围外 3）。一个大旋钮产品「拧了听不到」，每次 A/B 都要等十几秒。草图 Q3 的写法没把这个后果写出来，而规格原文第 4 节第 1 条本来写的是「你改参数引起的目标变化立即生效（模块自己的 20 ms 平滑接住）」（`设计规格-实时GLAZE-主段与增益.md:72`）。
- **提案**：用户动作（GLAZE、风格、曲风、交付、手动旋钮）引起的目标变化，走 0.5～1 s 的固定斜坡，不受棘轮限制；画像驱动的变化照旧走 0.2 / 1 dB/s 加棘轮。斜坡期间冻结 G_trim（与 R5-03 一起做）。
- **对硬约束与 ADR**：GLAZE 0 不变；斜坡按样本推进，块长无关；会改变「拧旋钮之后那段过渡」的声音；不冲突 ADR-030；需要 Max 改 Q3。
- **代价与风险**：S～M。风险是实时拧旋钮时出现增益阶跃，1 s 斜坡足够平滑。
- **怎么验**：单元测试：GLAZE 35→70 阶跃后，自动增益 1 s 内到达新目标的 90 %；画像变化仍按 0.2 dB/s；块长 {1, 7, 32, 64, 480, 512, 4096} 逐位一致。最后请 Max 拧旋钮实听。
- **对 Max 口味**：一个大旋钮的产品，旋钮的手感就是产品本身。

## 5. 点名纠错

1. **R3-03 重提已否决备选**：ADR-028:37 已把「改动量保留比当触发量」列为放弃的方案，理由是开低切的歌会全部降档，包括净效果为正的 emotapes。T-044 REPORT:84 的十组保留比全在 −2.3～−6.7 dB，emotapes 入口峰值 −0.31～−0.39 dB。R3-03 没有引用这两处，也没有回应这个反例。
2. **R6-02 的数据早于 T-089**：T-085 数据提交于 `ecc45f9`（2026-10-09），T-089 合入于 `1a0e26a`（2026-10-10）。旧规划器对比目标响的输入，仍会按流媒体上限 −8 LUFS 推 min(3, −8 − I)（例如 deep_155923 输入 −9.34 时推 1.34 dB），所以表中 0.6～1.9 dB 的平均 GR 有一部分已被 T-089 消掉。剩下的部分来自输入真峰值对 −2 dBTP 封顶（melodic_241941 入口 +2.38 dBTP）。提案仍然成立，但量要在当前 main 上重渲；T-085 报告里「−14 组中位 −12.01」同理。
3. **R4-01 的透明证据不全**：附录 A2 只量了稳态 THD / IMD、宏观落差和过冲，没量拍频调制。按 g = α(Lr − Lf)，鼓间内容相对底鼓时刻会被抬高最多 Gmax = 4 dB，和限幅泵是同型的相对调制【推断】，必须先补量。
4. **R2 结论的优先级排法**：R2 说编码后过冲 1.2～7.4 dB「比内部误差大一个数量级，优先级应让给 R2-02」，这是把浮点超限当成了可闻损伤。T-085 REPORT:51 写明「未作盲听，浮点超限不是已经发生播放器硬削波的证明」；平台按 −14 归一化时，−9 LUFS 的母带会被调轻约 5 dB，解码峰值多数落回 0 dBFS 以下【推断】。
5. **R2-05 的前提**：「离线渲染还得手动给 `--bpm`」只适用于渲染工具。插件在宿主离线导出时 `hostPlaying = offline || …`（`CeladonChain.cpp:164`），宿主给了速度就照样封顶。
6. **R3-02 漏了量级**：新实例默认 GLAZE 35 时 h = 0.175，推响不刺最大只削 0.53 dB，R3 描述的「69 % 力度、8.3 Hz 调制」在默认路径上不到 ±0.26 dB。
