### 1.2 现状离目标最远的三处【综合判断】

1. **守护族没有按规格保护冲击与落差**（目标 #2）。证据最硬：R1、R5 独立发现，J1 / J2 / J3 逐行核实（`GlazeController.cpp:1286-1293`、`MusicAnalyzer.cpp:1248-1254`、`ContrastGuard.h:42`、`ContrastGuard.cpp:65, 112-127` 对 vault `设计规格-实时GLAZE-主段与增益.md:77-83`）；真链闭环没有任何测试（`tests/Phase2OrchestratorTests.cpp:92-103` 只测合同模型）。
2. **没有「好听」的尺子，等响 A/B 本身也有偏**（目标 #3、#4、#7）。BRIEF §5 原话「好听没有客观验收」；规格第 7.5 条「不拉锯」阈值从未定，阶段 2 的 22 首门槛与因果重放没跑完（R5 范围外 4）；Listen 1 s 窗藏起落差损失（R2-09b）。本轮 16 条改声音的新算法全被判存疑或否决（J1 第 2 节），都卡在这里。
3. **热混音没有「先调轻再限幅」的路径**（目标 #1）。三位复核都认机理（三处钳位源码核实），是唯一一条在默认路径上直接减少可闻过度限幅的改动（J1）；但 T-085 数据早于 T-089，量级要先在现行 main 重渲（J3 第 8 节 #4）。
- 候补：斜率参考打架（目标 #5）三份独立同结论，但默认 GLAZE 35 下量级只有 ±0.18 dB，收益主要在可解释性（J1）。

### 2.1 R6-02 交付档「往下」的增益路径

- **来源**：R6-02（J1 Top 1）；数据 T-085 `render_target_-10.csv` / `-14.csv`；R6 范围外 6。
- **类型 / 放哪**：优化控制层 · Limit 增益链（`GlazePlanner.cpp:1712` 的不衰减处理、`GlazeController.cpp:847-848, 864-866` 钳位与退让下限、`LimiterModule.cpp:110` 模块下限）；参数范围与 ID 不变。
- **为什么值**：流媒体 / 俱乐部档输入 I 高于交付目标 L_t 时，ΔG = −min(6 dB, I − L_t)，先调轻、少限幅。职业母带的基本动作是「混音比交付响就先调轻，绝不靠多限幅变轻」（J1）；melodic_241941 输入 −8.50 LUFS / +2.38 dBTP，−14 组输出 −9.75、GR 均值 1.68 dB（J2 核实）；Spotify 对响于 −14 的母带调轻、建议 TP 低于 −2（R6 引）。
- **三位复核**：J1 采纳（数据早于 T-089，量要重渲）｜J2 采纳（列全改点；会推翻 `testManualComesFirst`，`GlazeControllerTests.cpp:3368`）｜J3 采纳但改（先在现行 main 重跑；反转 ADR-008 第 3 条「绝不自动抵消手动修改」的语义）。
- **代价**：S～M。
- **风险与硬约束**：GLAZE 0 逐位不变（手动值 ≥ 0）；0 延迟 0 CPU；旧工程只在「GLAZE > 0 + 流媒体 / 俱乐部 + 输入比目标响」时变、方向是限幅更少；输入已压扁时调轻不能恢复 PSR；「GLAZE 只加不减」「手动增益是地板」两条隐含原则要 Max 拍板。
- **怎么验**：先在含 T-089（`1a0e26a`）的 main 上重渲 T-085 的 13 首 × 流媒体 −10 / −14 × 俱乐部 −7，确认问题剩多少；实现后 I > L_t 的曲输出在 L_t ± 0.5 LU、GR 均值下降（melodic_241941 −14 组 < 0.3 dB），I ≤ L_t 的曲同决策重放逐位不变，标准档 22 首逐位不变，TP ≤ Ceiling + 0.01，再跑 `codec_tp_check.py` 看编码后 TP 是否随之下降。
- **Max 口味**：直接服务两版交付与「按音乐状态自动」；标准档维持「已够响仍温和推响」。

## 6. 评估方法：每次算法改动必须过的清单

来源：R5-01「最小集」与 R5 第 0 节⑥的主观协议，按 J1（砍指标）、J2 第 5 节第 8 条（通用门）、J3 第 8 节（统一口径）、R4-07（全通对照）整理。数值都是起点，属完成标准，由 Max 定（第 7 节第 1、2 条）。

**A. 硬门（不过不合）**
1. 强度 0 / GLAZE 0 时逐位直通；块长 {1, 7, 32, 64, 480, 512, 4096} 逐位一致（GLAZE 0；GLAZE > 0 时管到哪一层待 J2-E 定口径）。
2. 真峰值 ≤ Ceiling + 0.01 dB；全部语料 `hardClipSamples == 0`（R2-09a）。
3. 22 首 `gate_check.py` + `house_gate.py` 0 失败；同决策重放（ADR-016）「不更轻、不抬峰」。
4. 音频线程 0 分配 0 锁、不用 fast-math、不依赖 FMA（ADR-013）；参数 ID 不改、选项只末尾追加。
5. CPU 在**新基线**上：48 kHz / 32 最慢块 ≤ 15 %、整插件 ≤ 20 %，并报 192 kHz / 32（J2-D）；上报延迟不变，否则单列。

**B. 不退步门（相对冻结基线，R5-01 最小集，J1 修剪后）**
1. drop 目标 ±1 LU；热启动主段电平误差 ≤ 0.3 LU。
2. 落差损失 ≤ 1.2 / 1.5 LU；出口 LRA 不低于入口 − 1 LU（EBU Tech 3342）。
3. 主段出口 PSR 中位 ≥ 该档下限 − 0.5（PSR 按 AES e-Brief 373 口径；下限规格值与代码值先对齐，J3 第 7 节 #4）。
4. 泵感（HMD / P_slow，统一命名）相对基线增加 ≤ 基线分布的 P90 差。
5. 低频瞬态保留 / 低频峰值因数 ≥ 基线 − 0.3 dB（三套口径先统一成一个，J3 第 7 节 #3）。
6. 限幅差值能量 / 出口能量（失真）≤ 基线 + 1 dB。
7. 低频相关度 ≥ 输入 − 0.05；逐段 S/M 出口 − 入口 ≤ 0.5 dB。
8. 净频谱改动（主段输出 − 输入的 1/3 倍频程 P95）与有目标时的频谱距离不劣于基线。
9. 控制质量：稳定段 Gain 每分钟总变差 / 变号 ≤ 基线 P90（补上规格 7.5 条）；守门介入时间占比与原因直方图。
10. 流媒体档另报编码后 TP（只报不判，直到 Max 定「流媒体安全」口径）。

**C. 验证纪律**
1. 凡含分频的方案，同时报「只分频、不处理」的全通对照组，结论写「方案 − 对照」（R4-07）。
2. 一次只改一个变量；同决策重放对照；指标排序与耳朵排序 Spearman ≥ 0.6 才把一个指标升格为门槛（R1）。
3. 语料至少区分「成品（Jamendo）」与「Max 的混音」两类报告（J1 范围外 5 指出门槛曲性质表述不一致）；J1-02 的三层分法未经交叉复核，作可选。

**D. 主观协议（R5-02，【综合判断】默认轻量、争议时 ABX）**
1. 等响 ≤ 0.1 LU，用整曲匹配（`--match-lufs`），不用 1 s 窗；随机改名；片段 8～16 小节且含 breakdown → drop。
2. 默认偏好 2AFC + 「无偏好」：≥ 6 首覆盖 Deep / Tech / Melodic × 流媒体 / 俱乐部，每首 3～4 片段，一组 16～20 次，排除「无偏好」后做符号检验（J1）。
3. 拿不准或要判「听不听得出」时上 ABX：40 次分 3 个会话，通过线 26/40（单侧 p = 0.040；真实正确率 0.7 时检出力 0.81，16 次只有 0.45）。分辨不出 → 判「听不出」，只看 B 组指标。
4. 会话 ≤ 20～30 min、10～15 试次，会话间休息不短于会话时长（ITU-R BS.1116-3）。
5. 事先登记决策规则：偏好 ≥ 65 % 且 p < 0.05，且 B 组不退步，才算通过；每批先做 A/A 自检。

**E. 不作门槛的**：PEAQ / ViSQOL（为编解码损伤设计，母带「有意改变」下方向相反，Torcoli 等 2021）；FAD（分布级、样本量偏差）；逐带相干、MTF、多音空 bin 留作排查工具（J1）。
