## 结论（先看这三条）

1. **Tone 参考斜率：45 首的中位数三个子类都约 −2.2 dB / oct**（Deep −2.21、Tech −2.19、Melodic −2.24；只算速度可信的三类都是 −2.29），
   与出厂 −3.5 / −2.5 / −3.0 差得多，三类之间也没有调研里「Deep 更暗、Tech 最亮」的差别。按出厂值，GLAZE 100 时 Deep 15 首里
   14 首会被往暗推（中位数 −0.47 dB，最多 −0.75 封顶），Melodic 13 首往暗（中位数 −0.21 dB）；改成本类中位数（三类都 −2.25）后
   三类的中位数都是 0，往暗的首数降到 6 / 5 / 4。**建议改成 −2.25**（三类相同），理由与风险见第 1 节。
2. **门控阈值：维持出厂 ΔG 3 LU、低频门系数 0.6。** 规格写的「前奏 ≥ 95 % 挡住、drop ≥ 95 % 通过」在这批曲子上**任何组合都做不到**
   （出厂值前奏挡住 60 %、drop 通过 85 %、breakdown 挡住 80 %）——很多 DJ 前奏底鼓、低音都齐，只比 drop 轻 1～3 LU，逐小节看响度和
   低频占比本来就分不开。但门控真正要保的是**画像代表 drop**：出厂值下画像响度与人工标的 drop 响度之差中位数 0.15 LU、第 90 百分位
   0.60、最大 0.92 LU（不门控是 0.75 / 1.40 / 3.07），出厂值已在最好的一档。**建议把规格里的验收口径改成「画像代表性」**（第 2 节）。
3. **64 / 8 小节与锁定后重开「3 LU × 4 小节」：数据支持现值。** 45 首离线都在第 64～66 小节锁定；渲染里只有 tech 0268597
   （第 64 小节才进 drop，锁定时画像比整首 drop 轻 2.95 LU）重开了 1 次，重开后画像差 −0.08 LU——设计里「锁在前奏上、drop 来了重开」
   这条路按预期工作；其余可用的 37 首都没有误重开（第 3 节）。

## 方法

- **参考曲**：Jamendo 45 首（每类 15 首；清单与挑选规则 `../2026-10-01-T038-reference/`）。独立音乐人作品、母带水平参差，**不是商业成品**。
  deep 0155923 与 0395474 是同一位制作人（Ant on Wax，一首带 feat. 所以艺人号不同）同一套编排，「每位艺人只取 1 首」在这里漏了。
- **流程**（`tools/render/calibrate_house.py`，在 109 上跑）：
  1. `prep`：mp3 → wav；按起音包络折叠估速度（100～140 BPM，0.002 BPM 细搜）与拍相位，起点裁到估出的小节线（`tempo-manifest.tsv`）。
     折叠峰 < 5 或贴搜索边界的 8 首记为**速度低置信**（小节线可能漂），各项统计另给「只算速度可信的」。
  2. `render`：`celadon_render --glaze 100 --style auto --clay auto --genre <本类> --delivery standard --bpm <本首> --segments-csv`，
     出 House 门控画像（含新加的 `profile_slope_db_per_oct` 列）、锁定 / 重开状态与逐小节段响度、低频占比。
  3. `label`：用与门控**无关**的三个读数（每拍底鼓起伏、拍间 40～130 Hz 低音底、300 Hz～8 kHz 密度）先按频谱新颖度分段落、再按段分类，
     出 15 张图（`figures/`）。主进程逐张看图核对，改标写在 `labels-override.tsv`（16 首改标或部分小节不计，7 首整首不计：4 首速度低置信且
     小节线漂、3 首看不出前奏与主段落）。**标签是看图得出的，没有听**，Max 可抽查。
  4. `analyze`：结果全文 `analysis.md`。门控口径同 SegmentLedger（已听小节的段响度第 95 百分位 = S_ref，过响度门的小节低频占比
     第 95 百分位 = 低频参考）；段落交界前后各 1 小节不计。

## 1 Tone 参考斜率

| 子类 | 中位数 | 四分位 | 出厂 | 出厂下 Tone（中位 / 往暗首数） | 改 −2.25 后 Tone（中位 / 往暗首数） |
|---|---|---|---|---|---|
| Deep | −2.21 | −2.70 ～ −1.64 | −3.5 | −0.47 dB / 14 首 | 0 / 6 首 |
| Tech | −2.19 | −2.76 ～ −1.62 | −2.5 | 0 / 7 首 | 0 / 5 首 |
| Melodic | −2.24 | −2.41 ～ −1.92 | −3.0 | −0.21 dB / 13 首 | 0 / 4 首 |

（Tone = 参考 − 曲子斜率超出死区 0.35 的部分 × 0.5 dB，钳在 −0.75 ～ +0.4；GLAZE 100、读数全可信时的满量。）

- **建议**：三类都改 −2.25。出厂的 −3.5 / −3.0 让 Celadon 把几乎每首 Deep / Melodic 都往暗推——如果 Max 自己的 House 和这批独立制作的
  曲子更像而不是和商业榜单曲更像，出厂值就是系统性偏暗。
- **风险**：这批不是商业成品；调研（`../2026-10-01-T038-genre-mastering-research/REPORT.md`）的「Deep 比 Tech 暗」来自另一批数据。
  改成三类相同，子类在 Tone 上就不再有差别（仍各自有目标频谱形状、往亮上限 +0.4 dB、学习方式）。
- **另一个选择**：维持出厂值，等 Max 试听时按耳朵调；或折中（例如 Deep −2.75、Tech −2.25、Melodic −2.5，保留相对次序）。

## 2 门控阈值

逐小节挡住率（全部可用曲目，前奏挡住 % / drop 通过 %）：ΔG 越小、系数越大挡得越多，drop 也掉得越多；没有一格同时 ≥ 95 / 95
（最接近的是 ΔG 1.5 / 系数 0.9 的 88 / 32、ΔG 5 / 系数 0.3 的 38 / 95）。分子类看，Melodic 在 ΔG 1.5 时前奏挡住 92～94 %，但 drop 只过 36～69 %。

画像代表性（|门控画像响度 − drop 响度|，中位数 / 第 90 百分位 / 最大，LU）：

| ΔG \ 系数 | 0.5 | 0.6 | 0.7 |
|---|---|---|---|
| 2.5 | 0.19 / 0.45 / 1.72 | 0.19 / 0.45 / 1.20 | 0.19 / 0.68 / 1.20 |
| **3.0** | 0.16 / 0.56 / 0.92 | **0.15 / 0.60 / 0.92** | 0.18 / 0.73 / 1.21 |
| 3.5 | 0.14 / 0.54 / 1.19 | 0.17 / 0.58 / 1.19 | 0.22 / 0.78 / 2.96 |
| 不门控 | 0.75 / 1.40 / 3.07 | | |

- **建议**：维持 3 LU / 0.6；规格第 6 节的验收口径从「前奏 ≥ 95 % 挡住、drop ≥ 95 % 通过」改成「画像响度与 drop 的差：中位数 ≤ 0.3 LU、
  最大 ≤ 1 LU」（出厂值在这批曲子上满足），挡住率只作参考。
- **分不开的**（规格要求单独回报）：前奏里有不比 drop 最轻小节轻 0.5 LU 以上的小节的曲目有 29 首（`analysis.md` 第 4 节）——多数是
  drop 里偶有很轻的小节（break 拍、渐弱），不是整段前奏都响；真正「整段前奏带低音、只比 drop 轻约 1～3 LU」的典型是 deep 0889219、
  tech 0200569、melodic 0241941。画像偏差最大的三首：tech 0200569（−2.01 LU：86 小节里 drop 只有最后 21 小节）、melodic 1033705
  （−1.74）、deep 1086373（−1.53；这两首的标签本身也不太有把握）。

## 3 锁定与重开

- 离线逐小节并入：45 首全部在第 64～66 小节锁定（「满编 ≥ 8」从来不是瓶颈）。渲染里第一遍末全部已锁定（锁定待定 0）。
- 锁定时画像与整首 drop 的差和最终画像几乎相同（大多 ±1 LU 内），只有 **tech 0268597** 例外：锁定时 −2.95 LU（第 64 小节才进 drop），
  渲染里重开 1 次，最终 −0.08 LU。melodic 0706729（不计入统计的一首）也重开 1 次。其余曲目重开条件一次都没满足。
- 结论：64 / 8 与「3 LU × 4 小节」不用改。第一段 drop 在第 56 小节以后才来的曲子（这批有 deep 0889219 第 67、tech 0200569 第 59、
  tech 0268597 第 64）靠重开兜底；0200569 的 drop 太晚太短（21 小节），重开条件没满足（drop 只比锁定时的画像响约 2 LU，不到 3 LU），画像偏轻 2 LU。

## 没做 / 局限

- 没听：段落标签看图得出，16 首改标或部分不计、7 首整首不计；真实验收要 Max 试听（规格：每个子类 1 晚）。
- 速度是估的（小节线可能差几拍；交界 ±1 小节不计只能挡一部分）；宿主给真实拍点时结果会更干净。
- 只用了 Jamendo；Max 的曲子按他的要求没用来定任何数。
- 目标频谱「自动」的子类形状（`houseTargetSlopeFor` −1.5 / −0.75 / −1.25）规格说「Max 试听后再调」，这里没动、没测。

## House 低切目标 25 Hz 与 T-043 混合损失的外推（T-043 建议的对照，2026-10-01 22:3x）

混合损失只在 10 / 20 Hz 两点测，House 档低切目标 25 Hz 处靠外推（幂律 L₁₀·2.5^q）。临时副本把候选改成 { 25, 20 } 编变体，45 首按 House 档各渲一遍
（脚本 109 `/tmp/t038-blend25.sh`，不进仓库），变体的 L(25) 是实测：

- |实测 − 外推| 中位 0.021 dB、最大 0.104 dB，≤ 0.01 dB 的只有 15 首——**没达到 T-043 的「≤ 0.01 dB」口径**；外推 37 / 45 首偏高（预测损失偏大 = 封得偏保守）。
- 但封顶判断（0.09 dB 门槛）45 首全一致：42 首 L(20) 已超门槛（封顶点在 10～20 Hz 插值段，与外推无关），2 首（tech 0130611、deep 1086373）封顶点落在
  20～25 Hz 外推段、外推与实测都超门槛，1 首到 25 Hz 也不超。
- 阳性对照：变体的 L(20) 与正式版 45 首逐字相同。
- **建议**：维持两点（10 / 20 Hz），不加第三个候选（学习期约 +15 µs）；落在 20～25 Hz 的封顶点会略偏低（偏保守）。待 Max 定。
