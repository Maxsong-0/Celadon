## 新检查是怎么做的

**S9 / S9b / S11 / 播放**：沿用 T-058 的 `DirtyRun`（增量重画与整帧重画逐字节比，×1 与 ×2 两种脏区口径）。T-070 给它加了重建计数、第一个曲线帧的位置记录、可选容差；
场景表 `dirtyScenarios` 新增 S9b（斜率 0 / 4.5）、S11，S9 与「播放」加了悬停。

**S12（与全新视图对照 + 绝对探针）**：不建编辑器。一个计算器 + 一个长期运行的视图（`SpectrumTimeline`，**构造时先画一次**，与真窗口一开窗就画过一样），
每个比较时刻现起一个全新视图（同开关、同斜率、同悬停；读数框 0.27 s 才刷新一次且选斜率会把计时清零，所以对 `setSpectrum` 连推 20 次）整帧画一张，长期运行的视图必须与它一致：

| 检查 | 时间轴 | 容差 |
|---|---|---|
| S12a ×2（PEAK 关 / 开） | 6 kHz 正弦 2 s → 静音；停播 4 / 5 / 6 s 与换斜率 0 → 4.5 的每一刻，悬停在 6 kHz，15 个时刻 | 0 |
| S12b ×2（PEAK 关 / 开） | IN 开、稳态 10 s 后斜率 0 → 3 → 4.5，12 个时刻（只比换斜率那一刻起；稳态那一刻不比，见下） | 0 |
| S12c | 白噪声 2 s → 静音、PEAK 关、斜率 4.5，8 个时刻，只比读数框以下 | 24 级 |
| S12d ×2（斜率 0 / 4.5） | 6 kHz 正弦稳态、PEAK 关，4 个时刻（OUT 一直在动，「少比 OUT」会让视图从没重建过） | 24 级 |
| 探针 ×6 | OUT 填充、平均线（白噪声停播后 OUT 已落出面板、平均线还在）、峰值线、IN 虚线、悬停读数 ×2 斜率 | 像素数下限 / 文字等于计算器的值 |

**容差各有来由**（不是为了让检查变绿放宽的）：

- 视图只在累计漂移超过 0.1 px 才重建，画出来的与此刻的值最多差 0.1 px，是**合法的**。实线沿 0.1 px 的 AA 差十几级，所以曲线还在慢慢动的 S12c / d 容差 24 级；
  变体 N7、N8、N11 在这个容差下照样被抓到，说明它不松。
- **虚线**（IN）的相位沿路径累计，0.1 px 的滞后到尖峰处放大成半个像素的相位差（实测 134 个像素差 40 级以上）：稳态那一刻不能逐字节比，只比换斜率那一刻（整组按此刻的值重建，逐位相同）。
- 悬停场景（S9 ×2、播放）放 **1 级**：悬停之后光标列的左边缘（clip 边界）在面板最上、最下一行各有一个像素差 1 级，是 JUCE 软件渲染器裁剪边界的取整；真残影差几十级以上。其余场景零容差。
- 宽带噪声每帧都不同，读数框合法地不同，所以 S12c 只比读数框以下；纯音的平均线沿频率平滑后在面板外（−107 dB，面板底边 −84 dB），测平均线要用白噪声。

与「全新视图」对照更是**抓不到它**（全新视图里两者相等；变体里长期视图的圆点也取此刻的值，反而与全新视图更一致）。要杀它得加一个逐点圆点位置探针，换来的只是 0.1 px——不做；评审那条的另一半（读数取错来源）由 N12 / N13 守住了。

**N8 的来历（值得记）**：N8「少比 OUT」第一、二轮都幸存。原因在测试台，不在检查的想法：长期运行的视图一开始没画过，第一次 `paint` 才用「此刻」的值建路径，把之后「OUT 从没更新过」整个掩盖了。
改成**时间轴构造时先画一次**之后，N8 被 S12d ×2 与 OUT 填充探针抓到。教训记进了 vault 的踩坑档（`踩坑-视图对自己比较抓不到两边一起错`）。

红绿表的最后一行「没有任何变体能打红的检查（V0 除外）：无」——25 条检查都有变体能把它打红，没有空转的。

## 没做 / 限制

- 本机是 aarch64 Linux 软件渲染器；macOS（×1 包围盒口径、CoreGraphics）与 Windows（Direct2D 矩形列表）没有实跑，用同一套检查按各自的脏区口径覆盖，真机结果要到 Mac / Windows 上看。
- F9（`PluginEditor::advanceForSnapshot` 的墙钟补推）与 SV-2（PEAK 关时峰值线仍算进脏区）都**没动**，理由见上表，记进了 TASKS「待认领」；SV-2 要 Max 拍板。
- N15 是等价变体、V2 是已记载的第二道保险；两个幸存者都不是检查的缺口。
- 容差（1 级 / 24 级）是在 Spark 的软件渲染器上量出来的；换渲染器（Mac）可能需要重量，检查失败信息里带第一个差异的位置与最大差，好重新定。
