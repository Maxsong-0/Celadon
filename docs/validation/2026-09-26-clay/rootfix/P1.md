## 2. 实现要点与关键取舍

1. **低通对齐不另开延迟线**：「S_low = LP(S) 再延迟 D − 2(L − 1)」等价实现为「LP 的输入取 S 历史环里 D − 2(L − 1) 个样本之前的值」（LTI，数学相同）。好处：不需要随 L 变长的第二条延迟线，两套低通淡化时各按自己的 L 对齐；预热也从同一个历史环读。历史环长 2D + 1：S_d 读 D 之前，预热最早读 D + 2(L − 1) ≤ 2D 之前。
2. **滑动和存「和」不存「平均」**：`sum += x − oldest; y = sum · (1/L)`（头文件写的是平均的递推，数学相同）。减与加分两步写，对输入取负精确对称（Clay 的左右互换逐位对称依赖它）。无乘加可融合（没有 a·b + c 形式）。
3. **重算网格**：每个低通从自己的 reset 起每 65536 样本按历史环重新求和；分频点切换时新低通在切换点 reset，它的网格从那里起——仍是「参数改变的样本位置 + 固定规则」，与块长无关。附带效果：静音后残差在 ≤ 4 个网格周期内精确归零（测试第 5 条验了）。
4. **输入清洗（规格没写，我加的）**：`process` 里非有限值当 0、|x| > 1e4（+80 dBFS）钳到 ±1e4。理由：一个 NaN / Inf 进了滑动和会留到它离开窗口后的下一个网格点（最长 1.4 s）；1e30 这种值会让和在大数离开窗口后丢掉其间的小信号（输出带一个 DC 误差直到下个网格点）。正常音频不受影响；Clay 的 S_d / M_d 直通路径不清洗（NaN 照样 D 样本后出去交给链的 NaN 保护）。分析器候选共用同一个实现，一并受益。
5. **逐位纯延迟**：逐样本判断「延迟后的这个样本没经过低切（标记环记着每个输入样本的 cutMix 是否 > 0）、a 此刻为 0、高架此刻逐位直通且无余振」→ 直接取 float 纯延迟线（不做 M/S 往返）；完全旁通也取它。标记用精确的每样本标记（不是保守计数），所以低切开 / 关时纯延迟正好延续到淡化样本到达输出为止。
6. **时刻**：①低切在延迟之前，它的开关淡化晚 D 个样本到输出；a、加宽、旁通淡化作用在输出时刻。（规格结构使然：低通要看「未来」的 S，所以 S 必须在输入时刻就低切过。）
7. **分频点切换**（规格原文实现）：只在 64 样本网格点开始 / 收尾；不在淡化中且目标 L ≠ 当前 L → 另一套 `reset(L_new)` + 从历史环喂最近 4(L_new − 1) 个输入（按它自己的偏移），此后它的输出精确（与一直在跑的同长度低通只差舍入）；两套 20 ms 线性淡化，最后一个淡化样本直接取新的（端点逐位）；淡化中的新目标等淡化走完后的网格点再处理。
8. **单声道**：①选择后的值存进 M 延迟线，输出 = 它延迟 D（未低切时取 float 纯延迟线）；与立体声 L = R 数值相同。

## 3. 与规格的偏差 / 需要主进程知悉的口径

1. **「GLAZE 0 且抽屉默认：整链输出与改动前的输出平移 D 个样本后逐位相同」只在 Color / Limit 为纯延迟时字面成立。** Glue 的释放时间（`ColorModule.cpp:1001`）与限幅器的自动释放（`LimiterModule.cpp:946`）每 32 样本、从 reset 起的固定网格按信号重算；输入整体晚 D 个样本（48 kHz 的 574 ≡ 30 mod 32）后网格与信号的相对位置变了，非中性的 Color / Limit 输出就不再是旧输出的逐位平移。与 Clay 无关、听感上也无差别（宿主延迟补偿后对齐），但逐位断言会失败。我的测试因此用两条：①任意 Color / Limit 设置：整链 = 「旧链在 Clay 的位置插一段 D 样本 float 纯延迟」逐位相同（这才是 Clay 的真实契约）；②Color / Limit 中性（Balance 照样在工作）：整链 = 旧链输出平移 D 逐位相同。**如果要让字面口径对任意设置成立**，一个办法是把 D 向上取整到 64 的倍数（48 / 96 / 192 kHz 只多 2 个样本，44.1 kHz 多 48 个）——见第 6 节接口变更请求 3，要主进程拍板，我没做。
2. **isPassThrough() 把「完全旁通（静止）」算作纯延迟**（按任务书「此刻输出 = 输入逐位延迟 D」的新语义；旧语义不算）。只有 ClayTests 用它。
3. **分频点切换的 CPU 尖峰**：规格定的「一次 O(4·L_max)」预热在一块里做完：192 kHz、40 Hz 时 4604 次 `process`（每次 4 级），估计 15 ～ 45 µs；192 kHz / 32 样本块（167 µs）里那一块会多约 10 ～ 25 个百分点。均值开销可忽略。只在分频点变化时发生（拖旋钮、方案过渡、收单比例离开 0 时从中性 80 Hz 换到方案值），20 ms 至多一次。原规格性能预算「192k / 32 最坏块增加 ≤ 0.5 个百分点」若把切换算进去会超——见第 6 节接口变更请求 2（摊薄的两种做法）。
4. 规格第 4 节第 3 条「|h[D+k] − h[D−k]| ≤ 1e-9」我在测试里用 2⁻⁶ 幅度的冲激测：输出是 float，对称的两个 double 偶尔会落在 float 舍入边界两侧差一个 ulp，单位幅度时 L = 35 的一个 ulp 约 2e-9，会误报；2⁻⁶ 时 < 4e-11。

## 4. 不确定点 / 可能编不过的地方（我逐行查过，以下是剩余风险）

1. `LinearPhaseLowpass.h` 冻结部分的 `static int groupDelayFor (int length) { return 2 * (length - 1); }` 参数名与数据成员 `length` 同名。GCC 的 -Wshadow 只在有 `this` 的成员函数里报「shadows a member」（`nonlambda_method_basetype()` 在静态成员函数里为空），clang 的 -Wshadow 不管参数遮蔽字段，所以应该不报；若真报了，改私有成员名要连带改公共的 `getLength()` 内联体（冻结部分），请主进程处理。
2. `ClayModule.cpp` 命名空间作用域的 `static_assert (static_cast<double> (ClayModule::minMonoHz) == LinearPhaseLowpass::minCutoffHz, ...)`：浮点常量比较，-Wfloat-equal 不在 -Wall/-Wextra 里。
3. `processStereo` 里的 lambda `historyAt`（按值捕获指针与长度，返回 double）；`std::array<LinearPhaseLowpass, 2>`（默认构造）。
4. 测试：`ChainTests` 的 `runModules` 新增 `ClayPosition::delayOnly` 分支；`ClayTests` 新 helper 全部有用到（没有未用函数）；局部变量避开了 `name / category / runner / isRunningTestCase`。
5. 运行时间：`LinearPhaseLowpass` 的朴素卷积对照（L = 1152 时 9000 个输出 × 4605 抽头 × 2 份系数 ≈ 8e7 次乘加）与精确系数（整数卷积约 8e6 次）在 Release 下都是亚秒级。
6. 所有逐位期望都用 Python 逐行移植（第 8 节）核过，但移植不是被测代码本身；C++ 与移植之间的差异只能靠编译后跑测试确认。
