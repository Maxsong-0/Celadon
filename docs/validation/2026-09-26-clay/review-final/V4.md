### V4-01 · low · 规格第 2 节末条「GLAZE 0 且抽屉默认：整链输出与改动前的输出平移 D 个样本后逐位相同」只在 Color / Limit 为纯延迟时成立，实现与测试已按「旧链在 Clay 位置插一段 D 样本纯延迟」交付，规格文字没有跟着改

- **文件:行**：`Source/dsp/LimiterModule.cpp:39`（`adaptIntervalSamples = 32`，`:946` 每 32 样本从 reset 起重算慢段释放）、`Source/dsp/ColorModule.cpp:49`（`glueAdaptIntervalSamples = 32`）；`Source/dsp/ClayModule.cpp:227-228`（D = 2(L_max − 1)：574 ≡ 30 (mod 32)）；`tests/ChainTests.cpp:1096-1108` 与 `tests/ClayGlazeTests.cpp:1285-1290`（参考链改成 `ClayPosition::delayOnly` / `PreClayChain (busy, clayDelay)`，字面「平移 D」只在 Color / Limit 中性、素材压低时另验）；`Source/dsp/CeladonChain.h:28-29`（头文件已把条件写清）；规格 `设计规格-Clay-根治修订.md` 第 2 节末条（无条件的字面）。
- **现象**：Glue 与限幅器的自适应释放在从 reset 起每 32 样本的固定网格上按信号重算，输入整体晚 D 个样本后网格与信号的相对位置变了，所以 Color / Limit 在工作时（例如手动 Glue 25 / Limit Gain +6 / Clip 20，GLAZE 0）整链输出不是旧输出的逐位平移；Clay 自身的契约（三项为 0 → 逐位纯延迟 D）成立，DAW 延迟补偿后对齐不变，听感无差别。P1 报告第 3 节第 1 条、P4 报告第 3 节第 3 条都写明了，主进程集成时没有回写规格。
- **证据**：上面两个测试文件的注释与断言结构；`ChainTests::testNeutralClayIsBitExactAtGlazeZero` 第二段只在 `makeNeutralParams` + Balance 60/60 + 素材 × 0.25 下断言字面平移。
- **建议修法**：二选一并回写规格：(a) 规格改成「整链 = 改动前的链在 Clay 位置插一段 D 样本纯延迟，逐位相同；Color / Limit 为纯延迟时即旧输出平移 D」（零代码改动，与现状一致）；(b) 若要字面口径对任意手动设置成立，把 D 向上取整到 64 的倍数（576 / 576 / 1152 / 2304，44.1 kHz 多 48 样本 ≈ 1.1 ms），要改冻结常数表、`getLatencySamples` 期望值与档案——需 Max 拍板。

- **现象**：音乐段落开始的头 ~18 ms（输出还是延迟线里的静音、GR ≈ 0）会被当成有效音乐记进保护层与 Color 监视器的统计；段落结束后的 ~18 ms（输出还带着音乐、GR 可能正大）则整块丢掉。修订前偏差 ≈ 6 ms（半个时隙），本来就是设计上的近似；D 加进去后是原来的 3 倍。对 3 s 统计窗的影响 < 1 %，只在频繁停顿的素材上才可能累积；`ClayGuard` 那条时间轴（`claySeconds`）与它读的实时视图同在入口时刻，是一致的，不在此列。校准器、Listen、`restartWithFadeIn` 都按 `getLatencySamples()` 对齐，已核对无问题。
- **证据**：只有静态论证，没有量化（未坐实）。
- **建议修法**：若要根治，把每个切片的 `view.musicActive` 存进一条长 `getLatencySamples()` 的标志环，门模块统计时读延迟后的标志（0 分配、每切片 O(1)）；或在 GlazeGuard.h 注明这个近似及其量级（D 后约 2 个时隙）。是否值得改请主进程按真歌门槛的结果定。

### V4-04 · low · 三处口径 / 文档小项（不影响行为）

1. 验收第 4 节第 3 条「冲激响应以 D 为中心对称（逐样本 |h[D+k] − h[D−k]| ≤ 1e-9）」按**单位**冲激在 ClayModule 的 float 输出上不保证：内部 double 对称到 1e-17（`LinearPhaseLowpass` 测试对精确核 ≤ 1e-12），但对称的两个 double 落到 float 时可能差 1 ulp，L = 35（44.1 kHz / 300 Hz）时约 2e-9。`tests/ClayTests.cpp:858` 因此用 2⁻⁶ 幅度的冲激（asymmetry 实测 ≤ 4e-11）。建议规格写成「double 内部对称 ≤ 1e-12，模块 float 输出按幅度相对 1e-7」，免得以后按单位冲激重验时误报。
2. `Source/dsp/MusicAnalyzer.cpp:274`（第「五」节）与 `:2542` 注释「P99 = 线性插值的百分位（同 numpy.percentile 默认）」：定义相同、不逐位相同（验证 6：14 / 3072 组末位不同，numpy 的 lerp 在 t ≥ 0.5 时写成 `b − (b − a)(1 − t)`）；规格里的口径（与 nth_element 逐位）成立，建议注释把「同 numpy」改成「定义同 numpy，逐位口径以 nth_element 为准」。
3. `Source/dsp/LinearPhaseLowpass.h:12` 公共注释写的是「y[n] = y[n−1] + (x[n] − x[n−L]) / L」，实现存的是和（`sum += x − oldest; y = sum · (1/L)`，`LinearPhaseLowpass.cpp:84-85`，数学相同、对取负精确对称），且公共部分没提「非有限当 0、|x| > 1e4 钳位」的输入清洗（只在私有注释与 .cpp）；P1 报告第 6 节第 1 条已请求，建议补一行。

## 已核对无问题的项（按任务书六个重点）

**1. 线性相位收单（LinearPhaseLowpass、ClayModule ②）**
- 冲激对称：4 级长 L 矩形窗级联，支撑 4(L − 1) + 1、中心 2(L − 1)；测试对精确核（整数卷积 / L⁴）≤ 1e-12、对称 ≤ 1e-12、直流 1 ± 1e-12（L = 2 / 35 / 88 / 288 / 1152）。
- 延迟对齐：`processStereo` 里 S_d 读历史环 D 之前（`ClayModule.cpp:586`）；低通输入取 S 延迟 D − 2(L − 1)（`:528, :587`），LTI 下与「LP 之后再延迟」相同；预热读到最早 D + 2(L − 1) ≤ 2D，历史环长 2D + 1（`:239-247`）——边界逐条算过（`sideHistoryIndex` 的 samplesBack ∈ [1, 2D]，`historyAt` 负下标只回绕一次且 |index| ≤ D）。
- 分频点切换：只在 64 样本网格点开始 / 收尾（`updateCoefficients → updateLowpassSwitch`），预热 4(L − 1) 个样本后新低通的第 4 级输出完整（各级窗口在 m0 + k(L − 1) 后填满，推导核过）；淡化最后一个样本直接取新低通、下一网格点转正，端点逐位；44.1 kHz 淡化 882 与 88.2 kHz 1764 不是 64 的倍数也不影响（验证 5 逐位）。`testCrossoverChangeCrossfadesLowpasses`（48k 150 → 60、44.1k 300 → 40、192k 80 → 160）与拖旋钮无咔哒用例带阳性对照。
- 逐位纯延迟：条件按**每个输出样本**判（延迟后的样本未经低切的标记环 + 此刻 a = 0 + 高架逐位直通且余振为 0，`:617`），完全旁通同样取 float 纯延迟线；三级不作用时不做 M/S 往返；低切开 / 关的淡化通过标记环精确延续到走出延迟线；`cutSamplesInDelay` 计数与标记环一致（`reset → clearDelayLines` 归零）。
