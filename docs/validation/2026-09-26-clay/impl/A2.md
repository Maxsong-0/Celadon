## 2. 关键设计取舍

1. **状态唯一真源 = `ClayGuardState`（float）**：每块读成 double 推进、末尾取回 float。于是「某块末尾存执行快照 → 恢复 → 继续」与一路跑下去逐位相同（测试 10 核对）；代价是不同块长只在 float 舍入内一致（每块 ≤ 半 ulp，估算最坏累计 < 7e-4；测试按 2e-3 核对）。与编排器 liveToneOffsetDb 等实时量、rendercheck「换块长只比容差」同口径。
2. **反相保护**：条件 = `liveLowCorrelation.valid && value < clayGuardPhaseCorrelation`。成立：phaseFloor 以 1/attack 每秒线性升向 1，保持期重置为 hold；不成立：先耗保持期，同一块里剩下的时间才用于以 1/release 每秒释放（块长无关的关键）。输出 `monoAmount = max(方案, phaseFloor)`，分频点用方案 monoHz（方案不收单时是默认 80 Hz）。
3. **宽度保护（任务书要求「选一种并写明」）**：选**每秒 dB 线性速率**，不用一阶平滑——一阶平滑从哨兵值 100 dB 出发要很久才降到方案附近且永远只逼近。速率 = 此刻方案加宽量 P = max(0, 方案 widthDb) / attack（收回）或 / release（放开）：整段方案加宽在 0.2 s 内收完、2 s 内放回，与方案大小无关。上限高于 P 的部分对输出不可见，所以运动只在 [0, P] 里走：下降从 min(上限, P) 起步（一触发输出就开始收）；回升到达 P 即置成 w_allow（静止形态「上限 = 允许值」，P_S = 0 时 = 100 dB 不限）。允许值 `w_allow = 10·log10(k·P_M/P_S)`、k = (1−ρmin)/(1+ρmin)（0.25 → 0.6），与 A5 决策器 `clayWidthCapDb` 同一公式；比值 ≤ 1 → 0（从不收窄），P_S = 0 → 不限。
4. **冻结分两路**：seconds ≤ 0 / 非有限 → 整体冻结；低频相关度无效（或 NaN）→ 只冻反相一路（保持期也不走）；高频 `liveHighValid = false` 或功率非有限 / 为负 → 只冻宽度一路。理由：「不知道就不改」，例如间奏没有低频时反相保护停在原处，低频回来若仍反相不必再攻击一次。
5. **标志是推导量**：`phaseActive = phaseFloor > 方案 || 保持期 > 0`、`widthActive = 上限 < 方案`，冻结块里也按当前状态与此刻方案重算（停播时拧 GLAZE，琥珀灯仍只在真改输出 / 保持期时亮）。
6. **常数清洗**：非有限值一律按 0 读（= 旧快照缺字段口径）：时长 0 = 立即、阈值 0、ρmin 0 → k = 1；时长钳 [0, 1e6] s；ρmin 钳 [−0.99, 1]（防除零；1 → k = 0 不许自动加宽）。测试 12 核对 NaN / ±∞ / 负时长与全 0 逐位同轨迹。
7. **方案值非有限**（不该出现）：monoAmount / widthDb 按中性，保护照常工作、输出有限；lowCutHz / monoHz 原样透传。`active = false` 时原样返回 planned（连 NaN 位型都不动）。
8. **setState**：NaN 回中性，其余钳到合法范围（phaseFloor 0～1、hold 0～1e6 s、widthCapDb 0～100）；再去掉与数值矛盾的标志（无下限且无保持期 → phaseActive 假；上限不限 → widthActive 假）。
9. **resolveClayParams**：三态按 ClayGuard.h 文件头；另两条（见第 3 节偏差 1）：合成后收单比例为 0 时 monoHz 一律交中性 80 Hz；monoAmount / widthDb 的 −0 归 +0。钳制：非有限 → 中性；低切 ≤ 0 = 关（保持 0），否则 10～60 Hz；其余按 ClayModule min/max。未知枚举值落不进 switch → 该项中性。

## 3. 与规格 / 任务书的偏差及理由

1. **收单比例为 0 时 monoHz 交 80 Hz（不取 autoValues.monoHz）**。任务书：「GLAZE ≤ 0 时中性……monoHz 保持 autoValues 的值无妨」，自动态写「自动 → autoValues」。我扩大为「合成后比例 = 0（自动 GLAZE ≤ 0、关、或自动比例本身 = 0）→ 80 Hz」。理由：ClayPlan 自己的约定就是「monoAmount = 0 时 monoHz 保持默认 80」（A5 决策器也照此给值）；这样某项不处理时交给 ClayModule 的参数是固定常数，不会因为方案过渡里一个用不上的 monoHz 在变、或旧快照缺字段让决策器给出 0 Hz 被钳成 40 Hz，而让模块离开「逐位直通」静止态（若 A1 把分频点平滑算进静止判据）。比例离开 0 时分频点与比例一起按 20 ms 平滑、比例从 0 起步，听不出。自动比例 > 0 时照用 autoValues.monoHz。
2. **「视图无效 → 冻结」按两路分别冻**（任务书未说整体还是分路）：两路都无效 = 整体冻结，与任务书字面一致；只一路无效时另一路照常。
3. **宽度速率与方案加宽量成比例**（任务书允许「每秒 dB 速率或一阶平滑，选一种并写明」）：见第 2 节第 3 条。
4. setState 额外去掉与数值矛盾的标志、hold 上限 1e6 s（防坏快照）；不按当前常数的 hold 截断（setState 与 setConstants 的调用顺序不定，截断会依赖顺序）。

## 4. 不确定点 / 需要其他线注意

1. **【需主进程裁决】端到端「100 ms 内 a = 1」可能达不到**（验收 §6 第 5 条「歌曲中途插入 2 s 反相低频，100 ms 内 a = 1」）。ClayGuard 的 100 ms 是从「实时视图判定反相」起算。分析器 `liveLowCorrelation` 是 X 与 P 各自 300 ms 功率平滑后相除（规格 1.4）：从 ρ = +0.9 切到同响度 ρ = −0.9，若 300 ms 是一阶时间常数，X̃ 过零要 τ·ln2 ≈ 0.21 s；再加编排器「本块用上一块的秒数与视图」的一块延迟。从插入时刻算，a 到 1 约 0.3 s。A10 整链测试若按插入时刻计 100 ms 会失败。可选：验收口径改为「从实时相关度过阈值起 100 ms」，或 A4 对反相检测用更短平滑（如 50 ms，或下降方向快平滑）。本单元不改。
2. **旧工程必须不启用保护**：反相保护不依赖画像（方案 monoAmount = 0 也会拉到 1），旧工程若照常 update 会在反相低频处改变声音。已核对 A6 当前 `GlazeController::updateClay`：方案源不支持 Clay（格式 1 画像 / 旧算法方案 / 无画像）时 `clayGuard.reset()` 且自动值中性——满足。另 A6 的 Status 已按三态与保护标志相与、有效音乐秒数只在 musicActive && 未旁通 && 在播时累计——与本实现的冻结口径一致。
3. 块长无关的边界：同一视图序列下只差 float 舍入；但真实链里视图每 hop 更新、编排器每宿主块取一次，不同宿主块长采样到的视图时刻不同——这是所有块量化自适应量的共性（rendercheck 换块长只比容差）。
4. `phaseActive` 在方案本来就全收单（monoAmount ≥ 1）、检测到反相时也为真（保持期 > 0）→ 琥珀灯亮但输出不变。按任务书定义实现；若界面想只在「真在改输出」时亮，可让 A6 写 Status 时改用 `phaseFloor > 方案`。
5. 宽度预测把 γ² 乘在 2～16 kHz 全部 P_S 上，而实际 2 kHz 高架在 2 kHz 处只有一半 dB 增益 → 预测偏保守（多收一点），可接受；与决策器同口径。
6. 测试 13 断言出厂 7 个保护常数 = 规格数字（0 / 0.1 / 2 / 2 / 0.2 / 2 / 0.25）；将来标定改数时要同步改 `specConstants` 与该条。

## 6. 可能编不过的地方（逐行自查后）

未发现确定的问题。低风险点：
- `ClayGuard.h`：`Tuning tuning = makeTuning (Constants{});` 在类内默认成员初始化里调本类静态函数（完整类上下文，合法）；每次构造会在栈上建一个 `Constants` 临时对象（约 1 KB，不分配）。

- 已避开 JUCE `String << unsigned int` 无重载（位型比较用 `expect`）、`String << bool` 被删除（布尔一律 `expect`）。
- 局部名已避开 `nan` / `inf` / `index` 等可能与全局内建函数同名的标识符（-Wshadow）。
