## 2. 关键设计取舍

1. **动态气泡不需要扩展气泡机制**：JUCE 的 `TooltipWindow` 每 123 ms 调一次鼠标下组件的 `TooltipClient::getTooltip()`（已读 JUCE 9.0.2 `juce_TooltipWindow.cpp`），气泡显示中文字一变就原位更新。所以指示灯直接实现 `getTooltip()`，没改 TooltipWindow / LookAndFeel。唯一要补的：文字一变 TooltipWindow 就把「悬停 0.5 s 才出现」重新计时（`tipChanged → lastCompChangeTime = now`），方案过渡 / 保护攻击释放时数值连续变，气泡会一直出不来。`ClayLiveTooltip` 让文字两次更换至少隔 1 s（换字后稳 ≥ 877 ms，TooltipWindow 最迟第 5 次询问 ≈ 615 ms 就能出气泡）；文字只在悬停时按需拼，定时器里只存几个整数。
2. **判定与文字放在 HelpText（无头文件）**：`CELADON_HEADLESS_UI_SOURCES` 只有 GlazeStatusText.cpp 与 HelpText.cpp，我名下能进无头测试的只有 HelpText。把「量化读数 → 灯的颜色类别 → 第 2 行文字 → 整个气泡」做成纯函数放这里，才能有自动测试（与 GlazeStatusText 把状态行的判定和颜色类别放在无头文件同一做法）；组件只管「什么时候重画 / 重拼」。
3. **量化读数（ClayReadout）是唯一的比较口径**：Hz 取整、收单比例取整 %、加宽 0.1 dB；实际值非 0 时显示至少 1 个单位（灯亮着，文字不写「0%」「+0.0 dB」）；旁通时全清零；收单比例为 0 时分频点清零。两份相等 = 灯与气泡一个像素都不变。抽屉的标记用同一份读数判断「该级在处理」，位置用快照里未量化的实际值。
4. **保护灯只算「自动」态的项**：界面按 `clay_*_mode` 再过滤一次（ADR-009 第 4 条）。A6 在 GlazeController.cpp 第 2303～2304 行已按模式过滤，这里是双保险；旁通按规格由界面读 `clay_bypass`（A6 注释也写明「旁通与否由界面自己读参数」）。
5. **抽屉的旋钮复用 Knob，不复制实现**：每项一行放不下 80 px 高的 Knob（三行 240 > 232），又不能改 Knob.*。`KnobWindow` 把整个 Knob 放进 48 px 高的窗口、上移 16，名字 / 数值两个标签落在窗外被父组件裁掉（绘制与鼠标都裁），露出的正好是 48 px 滑条区（本体 34 + 弧 + 小圆点出血）；手感、双击回默认、⌘ 精调、滚轮、提示、实际值标记都是 Knob 原样。数值改在右边标签显示，补上参数单位（A7 的参数文字「25」「+0.8」不带单位，标签是 Hz / dB；文字本身已带单位时不重复）。
6. **三态胶囊横排是新的小类 `ModeCapsules`**：CapsuleSelector 只能竖排且带小标题（76 px 高，三行 228），又不能改它。新类用同一种胶囊画法（LookAndFeel::drawToggleButton）、同一个胶囊高与间距（直接引用 `CapsuleSelector::capsuleHeight / capsuleGap`）、同一套 ParameterAttachment 双向同步与「只有被点亮那次才写参数」逻辑（约 40 行，与 CapsuleSelector::bind 对应）。
7. **淡入淡出不用 ComponentAnimator**：它淡出时换成组件快照（ProxyComponent）再拉伸贴回，界面缩放不是整数倍时重采样发虚（PluginEditor 的 PixelAlignedImageCache 一节避免的正是这个），且没有逐组件的「淡完了」回调。自己的计时器按真实经过时间算 alpha（半路反向从当前 alpha 起、按剩下的比例缩短），淡入到位回调 `onCoverageChanged (true)`。
8. **盖住期间藏起被盖住的三块面板与指示灯**：抽屉圆角外要露出画布开片纹，不能声明不透明；不藏的话抽屉里旋钮一重画，macOS 合成的外接矩形会把下面三块面板再画一遍。淡入到位后 `setModulesCovered (true)` 藏起来，开始收起时先亮回（淡出时从底下透出来）。藏起期间定时器照常喂它们（不可见组件 repaint 是空操作）。抽屉开着时主线程只画一块抽屉而不是三块面板，不增加负担。
9. **只在变化时重画**：指示灯比三盏灯的颜色类别；抽屉标记走 `Knob::setEffectiveProportion` 的阈值；旧工程琥珀小字只在出现 / 消失时重画那一块；抽屉收起（不可见）时不更新标记，打开第一帧补一次；三态没变时 `setAlpha` 是空操作。
10. **Clay 状态来源**：用编辑器已有的状态源（处理器在 createEditor 注入的 `getGlazeStatus()`），与状态行同一次取的快照，每 30 ms 只取一次，不另开通道。

## 5. 可能编不过 / 有警告风险的地方（逐行自查过）

1. `KnobWindow` 用 `Knob::smallHeight`（公开）与 `smallKnobMarkerBleed`（CeladonLookAndFeel.h 公开常数）——都存在；`knobLabelHeight = 18` 是本地常数。
2. `AdvancedDrawer.h` 用 `std::array<std::unique_ptr<ClayRow>, 3>`（ClayRow 在 .cpp 里定义）：构造 / 析构都在 .cpp、ClayRow 定义之后；拷贝已禁、移动未声明，编辑器所在的翻译单元不会实例化 `unique_ptr<ClayRow>` 的析构。
3. 匿名空间里的 `ModeCapsules` / `KnobWindow` 用作 `AdvancedDrawer::ClayRow`（外部链接）的成员：同一 .cpp 内，GCC 的 `-Wsubobject-linkage` 对主文件不报；该文件只在 Mac（clang）编。
4. `CloseButton` 用 `Component::setTitle`（JUCE ≥ 6.1）；`juce::GlyphArrangement::getStringWidthInt` 与现有代码同用法。
5. `-Wconversion`：新代码的 int / float / double 与 uint32 转换全是 `static_cast`；`std::abs (float)` 来自 `<cmath>`（已包含），`std::abs (int)` 来自 `<cstdlib>`（HelpText.cpp 已包含）。
6. `-Wshadow`（GCC 对参数遮蔽成员也报）：新函数的参数一律 `new…` / 不与成员同名；避开了 juce::Component（properties、flags、cursor…）、juce::Button（text）、juce::UnitTest（name、category、runner）的私有成员名；测试里 NaN / Inf 局部量不叫 `nan` / `inf`。
7. `-Wunused-*`：匿名空间里的常数与函数逐个核对过都被用到（clang 的 `-Wunused-variable` 含 `-Wunused-const-variable`）。
8. `switch` 覆盖全部枚举值（`ClayLamp`、`ClayStage`），`switch` 之后另有 `return`（与 GlazeStatusText 同写法，不触发 `-Wunreachable-code`）。
9. 中文字面量一律经 `utf8()`（已 grep 核对：没有直接把非 ASCII 字面量交给 `juce::String` 的地方）。
