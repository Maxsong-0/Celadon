## 2. 接线口径（编排器）

1. **每块 beginBlock（自动增量等算完之后）**：`clayPlanned = plannedClay()`（方案的 `plan.clay`，过渡中与自动增量**同一个 t**——与 `currentIncrements` 同一个式子——用 `blendClayPlans` 混合）→ `liveClay = ClayGuard.update(clayPlanned, analyzer.getShortTermView(), seconds, true)` → `effective.clay = resolveClayParams(manual.claySettings, liveClay, manual.glazePercent)`。只写 `effective.clay`，不碰其余 7 个参数。
2. **GLAZE ≤ 0 快速路径**：`effective = manual` 之后同样 `effective.clay = resolveClayParams(claySettings, ClayPlan{}, glaze)`（自动 = 中性 → Clay 逐位直通；手动照样生效；关 = 中性）；ClayGuard 回中性。原有 7 个参数在 GLAZE 0 逐位等于手动值的保证不变（只多写了 `clay` 一项）。宿主旁通走主路径（`paused` 只让保护冻结），同样算 `effective.clay`。
3. **保护的时间轴**：`endBlock` 按切片累计 `view.musicActive && ! paused && hostPlaying()` 的样本秒数，下一块 beginBlock 一次交给 ClayGuard 后清零。静音 / 宿主旁通 / 停播块 = 0 → 冻结。离线时 `hostPlaying()` 为真，与实时同一时间轴。
4. **自动 Clay 只在方案源支持时才有**：`slotSupportsClay` = 方案已算过、`plan.algorithmVersion == 7`、画像 `formatVersion ≥ 2`。旧画像（格式 1）/ 旧算法方案（savedPlanMode）/ 没有画像 → 自动值中性，**ClayGuard 也 reset、不工作**。过渡的一端不支持时按中性参与混合，重学 / 拧 GLAZE / 换风格后 Clay 随方案过渡平滑启用。
5. **过渡混合 `blendClayPlans`**：频率对数域、比例与 dB 线性；低切 0 的一端按 `clayLowCutFloorHz`（终点其次起点快照的值，钳到 10～60；缺字段读成 0 时用 ClayModule 最低 10 Hz）参与，两端都 0 = 0；对数结果钳在两端之间；t ≤ 0 / NaN 给 from、t ≥ 1 给 to（逐位原值）。
6. **执行快照**：`plan.clay` 存过渡混合后、保护之前的值（与 `plan.increments` 同口径，恢复后就是被沿用方案的 clay）；另存保护之后的 `liveClay` 与 ClayGuard 状态（都先按读取时核对的范围收拾）。`adoptExecution`（保存重开、沿用执行量的宿主 reset、同规格重建共用）：`clayGuard.setState(快照)`、下一块直接用快照 `liveClay`（`clayRestorePending`，与 liveTone / liveTame 同一套首块语义）、样本秒数清零；快照无效 = 中性。不沿用执行量的宿主 reset、GLAZE 回 0、重建（未沿用已听到的执行量）→ `resetClayRuntime`。执行快照因参数变化失效时清首块值（保护状态照走）。
7. **ClayGuard 常数**：跟着方案源（过渡终点）的标定快照，换了方案源（`generation` 变）才 `setConstants`；读档 / 重建 / 测试换常数后标「未知」，下一块重设。
8. **Status**：`clayLowCutHz / MonoHz / MonoAmount / WidthDb` = 上一块 `effective.clay`；`clayPhaseGuardActive` / `clayWidthGuardActive` = `active && 该项为自动 && ClayGuard 标志`；`clayNeedsRelearn = active && 至少一项自动 && committed.hasProfile && committed.profile.formatVersion < 2`。走原有 seqlock 发布。
9. **校准参考条件 manualParamsHash**：`conditionsHash` 并入 Clay 设置，但**三项都「自动」且没旁通时一个字节都不加**（哈希与 v0.1.6.2 逐位相同）；否则加记号字 `0x436c6179`（"Clay"）后逐项加「态 +（手动时）量化 1e-4 的旋钮值」+ Bypass。`samePlanningManual` 也并入 Clay 设置，beginBlock 据此重算参考条件；「自动 / 关」态下拖旋钮 → 参考条件重算但哈希不变。

## 3. 存档口径（GlazeProfile）

1. **画像按自己的格式写**：格式 1 的旧画像重存仍是格式 1（不补一组「无效」的新字段——补了画像号就变）；读格式 1 → 新字段一律 `Feature{}`、数组 0（覆盖 out 里原来的值）；格式 2 → 新字段与其余字段同样严格，缺一个整份拒收、out 不变；格式 > 2 照旧拒收。
2. **computeProfileId**：原有字段序列一字未动（首字仍是 formatVersion），格式 ≥ 2 时才把新字段接在最后：格式 1 的画像号与 v0.1.6.2 **逐位相同**（测试 Clay 2 用照抄的旧实现对照）。量化步长：S/M 与超低频占比 0.01 dB，相关度与置信度 1e-4。`bitwiseEqual` 按 XML 比较，自然覆盖新字段（格式 1 只比存得下的字段）。
3. **PLAN**：Clay 四项 `optionalField`（float 配 float，与 A5 新加的 double 重载无二义性，A5 报告已核对）；缺 = `ClayPlan{}`（monoHz 80），在但损坏 = 拒收。
4. **EXECUTION**：`formatVersion` 仍为 1（加的都是可缺省属性）；缺 = 中性；在但损坏 = 拒收；另核对：全部有限、低切 0 或 10～60、分频 40～300、比例 0～1、加宽 −3～+3、保护下限 0～1、保持秒与宽度上限 ≥ 0，不满足整份拒收（与现有执行量同一做法）。

## 4. 与规格 / 任务书的偏差及理由

1. **旧画像 / 旧算法方案时 ClayGuard 不工作**（规格只说「g > 0 才工作、只管自动态」）。反相保护不看画像（方案收单 0 也会拉到 1），旧工程若照常保护，反相低频处声音会变，违反「旧工程重新聆听前声音不变」（验收第 6 节第 1 条）。A2 报告第 4 节第 2 条同样要求这样做，已核对。
2. **manualParamsHash 只并影响声音的部分，默认设置不加字节**（任务书「与现有手动参数同一做法」）。量化同现有做法；差别是「自动 / 关」态的旋钮值不计入（规格「旋钮可拖但不生效」，拖它不该让校准待验证），以及默认设置保持旧哈希（否则所有旧工程重开后校准不适用、偏差撤回——正是任务书对 computeProfileId 担心的同一种「声音会变」）。
3. **`samePlanningManual` 并入 Clay 设置**：决策器本身不读它（A5 报告第 2 节第 1 条），并入只为参考条件及时重算；多算一次方案无害。
4. **`blendClayPlans` 的分频点细化**：收单比例为 0 的一端用另一端的分频点（规格只说「频率对数域」）。比例为 0 时 monoHz 无意义（GlazeTypes.h），这样收单从无到有时分频点不扫动。
5. **`clayNeedsRelearn` 按「格式 < 2」判定**，不按单项特征 valid：格式 2 画像里某项无效（例如歌里没有高频）重新聆听也补不上，不该提示。
6. **Status 的保护灯另与 `active` 相与**；Status 不带 Clay 旁通标志（A8 自己读 `clay_bypass`，A8 报告已按此实现）。`statusForRestored`（读档后、第一块音频之前）Clay 字段保持默认：此时编排器还不知道 GLAZE 与三态设置。
7. **`sameCalibrationPlan` 不比 Clay**：Clay 对响度的影响 < 0.2 LU（规格「由现有校准器吸收」），且 Clay 与增量随同一组方案输入变化；比进去只会让过渡中的快照多一轮校准。
