## 2. 关键设计取舍

1. **Clay 的实际参数只取编排器的 `effective.clay`**：按 ChainParams.h 冻结约定与 A6 在 GlazeController.h 写明的「GLAZE ≤ 0 时也照算」，链不自己调 `resolveClayParams`、不读 `newParams.clay`（处理器也不填它）。链只做两件事：宿主旁通时 `bypass ‖= hostBypassed`（与另外三个模块同一做法），然后 `setParams`。
2. **位置与各路径**：`processSlice` 里 Balance 之后、Color 之前；GLAZE > 0 的 Guard 时隙切片路径每片都调 `processSlice`，自动包含 Clay；NaN 恢复走 `restartWithFadeIn`，一并清 Clay；`reset`（同规格 prepareToPlay）也清。
3. **延迟**：`getLatencySamples` 写成四项相加、`restartWithFadeIn` 的额外保持段也加上 Clay——现在 Clay 恒为 0，两处数值不变，但以后 Clay 若加前瞻不会漏。
4. **三态读法**：`clayModeFromRawValue` 与 Balance Speed / Glaze Style 同一取整（`juce::roundToInt`，与 `AudioParameterChoice::getIndex` 一致），钳到 `ClayMode::automatic..manual`，边界直接取枚举值，不写魔数。
5. **旧工程**：`addMissingParameterNodes` 的特判只认 `glaze_amount` 一个 ID（写 0），**不会误伤 `clay_*`**；`clay_*` 缺席时补只带 id 的节点，JUCE 9.0.2 `setNewState` 用 `tree.getProperty (value, 默认值)` → 回到默认「自动」/ Bypass 关（已读 JUCE 源码核实）。这是有意的：旧画像（格式 1）没有立体声 / 超低频特征，自动值为 0，声音不变；已在用的实例读旧预设时也回到「自动」，与其余参数回默认一致。只改了注释，逻辑未动。
6. **界面数据源**：Clay 实际值与保护状态走已有的 `getGlazeStatus()`（Status 的 clay* 字段），没加原子量；`getGlazeEffectiveParamsForUi()` 的 `clay` 字段是默认值（注释写明）。
7. **Debug 版一致性核对**（仿 GLAZE 的 applyIncrements 范围核对）：手动值参数范围 ≡ `ClayModule` 的钳位常数（两边不一致 → 旋钮动了声音不动，或模块允许的值拧不到）；三态参数选项数 ≡ 3、默认 ≡ 自动。以后改任一边 Debug 版一启动就断。

## 3. 与规格 / 任务书的偏差及理由

1. **三态选项字符串用英文「Auto / Off / Manual」**，没有直接写「自动」「关」「手动」：照 `glaze_style` 的先例（规格写「自动 / 温润 / 冲击 / 通透」，实现选项为 Auto / Warm / Punchy / Clean，Parameters.cpp 注释「选项名用英文（宿主自动化列表里显示）」）。抽屉的三态胶囊按下标绑定、自己画中文（`CapsuleSelector::bind` 只核对选项个数），语义不变。若 Max 要宿主自动化列表里也显示中文，只改 `makeClayMode` 一行，ID 与下标都不受影响。
2. **对数刻度用项目已有的 `logRange`**（自定义 convertFrom0to1 / convertTo0to1 两个函数、不给吸附、步长 0，与 Limit Release 同一写法），没用 `setSkewForCentre`：`logRange` 是真对数（旋钮正中 = 几何中心 24.5 Hz / 约 110 Hz），skew 只是幂律近似。连续取值，参数自己只做钳制。
3. **链顺序测试没用「只开 Clay 加宽 + 只开 Color Tone」**：两者都是线性时不变（Tone 是 L/R 同一对搁架，加宽是只对 S 的高架），交换次序在数学上等价，只差浮点舍入，分辨力只剩舍入噪声。改用 Balance 的自适应 + Glue / Heat / Clip / 限幅器的非线性，并与四种位置的独立模块参考链逐位对照（见第 6 节用例 2）。
4. **`filterRingOutSeconds` 0.3 → 0.35 s**（任务书没要求，但加 Clay 后原值不再成立）：Clay 低切最低 10 Hz 的 4 阶 Butterworth 高通，最慢一对极点衰减率 sin(π/8)·2π·10 ≈ 24 /s，衰减 60 dB 约 0.29 s，成了链里最慢的一级，原 0.3 s 只剩约 10 ms 余量。只影响向宿主报的尾巴长度（`getTailLengthSeconds`），不影响音频；全工程只有处理器用它（已 grep）。如主进程认为超范围，可单独回退这一行。
5. **新用例放在新测试类 `CeladonChainClay`**（文件末尾），没往原 `ChainTests::runTest` 里加调用——严格满足「只在末尾追加、不动旧用例」。代价：`--only CeladonChain` 不会跑它，要点名 `CeladonChainClay`。
