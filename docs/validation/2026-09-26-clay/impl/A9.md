## 2. 关键设计取舍

1. **「先完整聆听再出成品」选「存档 → 新链读回」**（任务书二选一）：第一遍新链 `setParams → prepare`（与 `PluginProcessor::prepareToPlay` 同序）把整首送进去、输出丢弃；`createGlazeStateXml()` 存档；第二遍另起新链 `restoreGlazeStateXml → setParams → prepare`（= 宿主重开工程再导出）从头渲染。理由：
   - 同一条链跳回位置 0 时，限幅器前瞻延迟线、Balance / Clay 滤波器、Glue 包络里还留着歌尾，成品开头会先吐出一段歌尾；要干净就得整链 reset，而编排器的 `onHostReset` 与「保存重开」走的是同一个执行快照入口（`adoptExecution`），GLAZE 这边的量两种做法一样，模块却只有新链是干净的；
   - 这就是用户真实流程「听一遍 → 存工程 → 重开 → 离线导出」，也是 Codex rendercheck 验过的路径（实时 / 离线逐样本一致、读回后第一块保持已执行控制量）；Clay 四个实际值与保护状态随执行快照恢复（设计规格-Clay 第 7 节）。
   - 每组设置各自跑两遍（不共享第一遍）：校准参考条件含 GLAZE、风格与 Clay 手动参数哈希，共享第一遍会让第二遍的校准不适用。
2. **延迟对齐**：第二遍整段缓冲 = 原曲 + 链延迟 + 余振（0.3 s，与 `PluginProcessor::filterRingOutSeconds` 同口径）补零，原地按 `--block` 分块处理（视图，不拷贝），成品 = 丢掉开头 `getLatencySamples()` 个样本后的 原曲 + 0.3 s。各组成品等长，与原曲从 0 逐样本对齐（DAW 并排 solo 切换）。渲染中逐块核对延迟不变，变了写备注。
3. **响度对齐**：用 `celadon::LoudnessMeter`（插件自己的 BS.1770-4 表）量对齐前成品整体响度，只乘一个增益到 `--match-lufs`；32-bit float 允许 > 0 dBFS，不限幅。整体响度无读数（静音 / < −70 LUFS）时不对齐、写备注。
4. **指标口径**（都写进 metrics.md「口径」与 README）：
   - 低频相关度用分析器同一口径 ρ = 2ΣLR / (ΣL² + ΣR²) = (P_M − P_S)/(P_M + P_S)（不是皮尔逊）：它直接反映侧声道能量占比，正是收单要减的东西，也能和画像的 lowCorrelation 对照；
   - 超低频占比用分析器 subShareDb 同一定义（只看 M，整段计、不设有效音频门）；
   - 限幅 GR 按任务书「按块读 getAndResetLimitGainReductionDb」：平均 = 各块读数按块长加权（块峰值的平均，偏高于逐样本平均，已在口径里说明），最大 = 全曲最大；
   - Clay 四个实际值取成品末尾的 `getGlazeStatus()`；另加「保护介入」两列（第二遍逐块读 clayPhaseGuardActive / clayWidthGuardActive 的时长占比），因为只看末尾值看不出中途保护介入过多少。
5. **原始输入对照行**：每首歌第一行是立体声化后的原曲，用同一套量法——看 Clay 前后低频相关度、超低频的变化要有「处理前」。
6. **GLAZE 0 逐位核对**（真歌上的阳性对照）：网格里同时有 g0 自动 / g0 全关时比较对齐前成品哈希，写进备注与 stderr（规格第 4 节「逐位直通」）。CSV 的 `audio_hash` 还能跨版本比「逐位不变」。
7. **`--selftest`**：本工具不在 celadon_tests 里（单独的 EXCLUDE_FROM_ALL 目标，加测试文件要改 CMake——那是主进程的文件），本机又不能跑，所以把合成信号上的阳性对照做成工具自己的模式，render-linux.sh 渲染前先跑、失败即停（`CELADON_RENDER_SKIP_SELFTEST=1` 可跳过）。各项期望值与依据见第 6 节。
8. **服务器脚本**：远端源码 / 构建目录与 test-linux.sh 分开（`~/.cache/celadon-render/…`、`~/.cache/celadon-render-build/…`），各自 `rsync --delete` 互不删对方，渲染十几分钟也不挡测试；本机锁名不同（`celadon-render-<key>.lock`）、远端 flock 另起一把。源码同步排除 `artifacts/`（几百 MB 预览包 + 渲染结果本身）。歌曲按目录哈希缓存、`-t` 增量、`-L` 跟随符号链接（歌曲可能链到音乐库）。输出目录由工具自己建，编译 / 自检失败时不拉回；拉回成功才删远端本次输出，失败时保留并打印路径。空参数、bash 3.2 下 `set -u` 与 `"$@"` 都做了防护；额外参数经两层 `printf %q` + 远端 `eval "set -- …"` 还原（与 test-linux.sh 的 RUN 同一做法）。
9. **单线程**：每条链之间没有共享状态，但 DSP 代码没按「多链并发」验证过，服务器也是共用的，就不开线程；`nice -n 10`。

## 3. 与规格 / 任务书的偏差及理由

| 偏差 | 理由 |
|---|---|
| 成品比原曲长 0.3 s（冲出链延迟之外再冲 0.3 s 余振） | 任务书「末尾补零冲出尾巴」：只补链延迟会切掉滤波器余振；0.3 s 与插件报给宿主的尾巴同口径。各组等长、仍从 0 逐样本对齐 |
| `--style` 接受逗号列表（也是网格一维） | 任务书写 `--style auto\|warm\|punchy\|clean`，又说「按网格（GLAZE × Clay × 风格）」；列表是超集，单个值照样用 |
| 表里多了 对齐增益、真峰值、保护介入、resolved_style、listen_phase、audio_hash、原始输入行 | 规格列的都在；多的几列是解读听感时必需的旁证（例如真峰值核对 Ceiling、保护介入比例），不影响原有列 |
| 多了 `--selftest` 与脚本里的自检门 | 见第 2 节第 7 条 |
| 相关度不是皮尔逊 | 与分析器 lowCorrelation 同口径，便于和画像、保护阈值对照；左右电平不等时两者不同，已在口径与 README 注明 |
| 输入 NaN / Inf 逐样本置 0 | 插件在处理器层是整块清零；工具不经处理器，逐样本清更贴近原曲，数量写进备注 |
| 支持 .wave / .bwf / .aifc | 同属 wav / aiff 家族，JUCE 读得了；.wave / .aifc 只在扩展名找不到格式时才按内容认 |

## 4. 不确定点

1. **Status 的 clay\* 字段**由 A6 在编排器 `makeStatusPayload` 里填：20:38 核对当时的 GlazeController.cpp，四个实际值 = 上一块 `effective.clay`（三态合成之后），两个保护标志 = `active && 该项为自动 && ClayGuard 标志`，与本工具的读法一致。若之后改动，Clay 四列与保护介入两列会变成默认值（0 / 80 Hz）——表会「看起来都没处理」。
2. **自检「延迟对齐」的 > 0.9 与「链延迟 = 282」**：依据是 GLAZE 0、出厂参数时整条链近乎透明、规格写明 48 kHz / 2 ms 为 282（A7 的 ChainTests 也按 282 断言）。若别的改动让链在出厂参数下不透明，这一项会失败并挡住渲染（可用 `CELADON_RENDER_SKIP_SELFTEST=1` 先听）。
3. **第一遍能否走到「已锁定」**取决于歌长：聆听 15～30 s 有效音频 + 3 s 过渡 + 约 14 s 校准。短于约 1 分钟的歌第二遍会接着学 / 校准（备注会写明，GLAZE > 0 才写）。
4. **openrsync**：本机 `/usr/bin/rsync` 是 openrsync（协议 29）；歌曲同步用了字符类模式 `*.[wW][aA][vV]`，openrsync 手册写明支持 `[` 字符类；源码 / JUCE 同步与 test-linux.sh 完全同一组选项。
5. **耗时**：按整链约 3～5 % 单核实时估算，4 分钟歌每组两遍约 20～30 s，5 首 × 6 组约 10～15 分钟（未实测）。
6. 远端登录 shell 按 bash 处理（test-linux.sh 同一假设）。

## 5. 可能编不过的地方（已逐行自查 -Wall -Wextra -Wshadow -Wconversion -Wno-sign-conversion）

1. **依赖 A7 的 `CeladonChain` 公共接口**：`setParams (const Params&, bool)`、`prepare`、`setHostInfo`、`process → bool`、`getLatencySamples`、`getAndResetLimitGainReductionDb`、`getGlazeStatus`、`createGlazeStateXml`、`restoreGlazeStateXml`。20:07 看 A7 改过的头文件，签名未变。
2. **依赖冻结接口**：`glaze::Status` 的 `clayLowCutHz / clayMonoHz / clayMonoAmount / clayWidthDb / clayPhaseGuardActive / clayWidthGuardActive`、`ClaySettings` 各字段、`ClayMode::{automatic, off}`、`glaze::Style::{automatic, warm}`、`glaze::Phase` 五个枚举值（两个 switch 覆盖全部，缺枚举值会报 -Wswitch）。
3. **JUCE 9.0.2 写文件 API**：用的是新接口 `WavAudioFormat::createWriterFor (std::unique_ptr<OutputStream>&, const AudioFormatWriterOptions&)`（旧的指针版已 `[[deprecated]]`，没用）；`AudioFormatWriterOptions{}.withSampleRate().withNumChannels().withBitsPerSample (32).withSampleFormat (SampleFormat::floatingPoint)`；`std::unique_ptr<juce::OutputStream> stream = file.createOutputStream();`（unique_ptr<FileOutputStream> 隐式转基类）。
4. **条件运算符混用 `std::string` 纯右值与 `const std::string` 左值**（`csvRow` 里 `render ? fixed (…) : empty`、`statusText` 等）：常见写法，GCC / Clang 对同类不同 cv 只取「加 const」一个方向，不二义。
5. **`for (const auto* known : { ".wav", ".wave", … })`**：花括号列表按值推导，各元素衰减成 `const char*`，推导成 `std::initializer_list<const char*>`。
6. **snprintf**：格式串全是字面量（`%.*f`、`%lld`、`%016llx`，uint64 显式转 `unsigned long long`），缓冲 32～64 字节并使用返回值，不应触发 -Wformat / -Wformat-truncation。
7. 用到的 JUCE 接口都在 9.0.2 源码里核过：`File::findChildFiles / hasFileExtension / replaceWithData / createDirectory`、`Array::sort()`、`String::fromUTF8 / equalsIgnoreCase`、`AudioFormatManager::createReaderFor (File) / (unique_ptr<InputStream>)`、`AudioFormatReader::read (AudioBuffer<float>*, …)`、`AudioBuffer` 视图构造、`Time::getMillisecondCounterHiRes`、`Result::failed`。
8. 非 ASCII 文字只进 `std::string` / `std::cerr`（不经 `juce::String (const char*)`，免得 Debug 断言）；路径与文件名经 `juce::String::fromUTF8`。

## 6. 新增测试清单（`celadon_render --selftest`，不在 celadon_tests）

| 项 | 输入 | 断言与依据 |
|---|---|---|
| 低频相关度 左右相同 | 60 Hz、0.5 正弦，L = R | ρ = 1（±1e-12）：同一组 double 滤波器，逐位相同 |
| 低频相关度 反相 | R = −L | ρ = −1（±1e-12）：线性运算对取反逐位对称 |
| 低频相关度 电平不等 | R = 0.5 × L | ρ = 2g/(1+g²) = 0.8（±1e-12）：乘 2 的幂逐位精确；皮尔逊会给 1——阳性对照口径 |
| 低频相关度 不相关 | 两路独立白噪声（固定种子） | \|ρ\| < 0.1：125 Hz 低通后 10 s 约 2500 个独立样本，σ≈0.02，5σ |
| 超低频占比 | 0.5 sin 20 Hz + 0.5 sin 1 kHz | 10·log10(0.5/(1+(20/30)^8)) = −3.177 dB ± 0.05：Butterworth 功率响应，整数周期交叉项为 0 |
| 整体响度 | 1 kHz、两声道幅度 0.1 | −20.0 ± 0.1 LUFS：BS.1770 997 Hz 0 dBFS 单声道 = −3.01 LUFS |
| 真峰值 | 1 kHz、幅度 0.5 | −6.02 ± 0.1 dBTP：8× 插值误差 < 0.01 dB |
| 哈希 | 同一段噪声；改一个样本最低位 | 相同；不同 |
| 文件名 | g35 自动 / g12.5 全关温润 | `Song A__g35_clay-auto_auto.wav` / `Song A__g12.5_clay-off_warm.wav`；formatGlaze(0) = "0"、(100) = "100" |
| 链延迟 | 白噪声、GLAZE 0、出厂参数、块 512，走真歌同一套两遍流程 | 282 样本（设计规格-Clay 第 3 节） |
| 成品长度 | 同上 | 输入 + ceil(0.3 × 48000) |

| GLAZE 0 逐位直通 | 同上，修坯自动 vs 全关 | 两组成品哈希相同（设计规格-Clay 第 4 节） |
