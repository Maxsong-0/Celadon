## 发现

### V3-01 · medium · 测试失效（断言比看上去弱）：JUCE 9.0.2 `String::startsWith / contains / indexOf` 对 UTF-8 多字节 needle 只比 `length()` 个字节

- **文件:行**：`tests/HelpTextTests.cpp:187`（`utf8 (entry->title).startsWith (utf8 (expectation.titleStart))`）、`:198`（`.contains (utf8 ("自动：")) / ("关：") / ("手动：")`）、`:204`（`.contains (utf8 ("「自动」时旋钮不生效"))`）、`:359`（`.startsWith (help::clayRelearnHint())`）；`tests/GlazeStatusTextTests.cpp:175`（`.startsWith (utf8 ("已锁定"))`）。
- **现象**：JUCE `String` 内部是 UTF-8；`String::indexOf (StringRef)`（`juce_String.cpp:961`）与 `String::startsWith`（`:1423`）都调 `CharacterFunctions::compareUpTo (…, needle.length())`（子串查找在 `juce_CharacterFunctions.h:681–689` 的 `indexOf`），传的是**码点数**；而 `compareUpTo` 的 `char` 快路（`juce_CharacterFunctions.h:602–613`）直接 `std::strncmp (s1, s2, maxChars)` 按**字节**比。三字节汉字的 needle 只比前 1/3 的字节：`"低切"`（2 码点）只比 2 字节，凡首字与「低」前两字节相同（低 / 位 / 住 / 作 …）都算命中；`"自动："` 只比「自」；`"「自动」时旋钮不生效"`（9 码点）只比「「自动」」三个字。`contains` 即 `indexOf >= 0`，一并受影响。只会多报命中、不会漏报，所以现有文案照样通过，但**文案写错也拦不住**（例如把「自动：…」写成「自选…」、「已锁定」写成「已经…」，断言仍为真）。
- **证据**（副本 `ReviewV3Render` 用例，`scratchpad/build3-render.log`）：
  `fromUTF8("低音很宽的歌").startsWith(fromUTF8("低切")) → true`；`fromUTF8("自选").contains(fromUTF8("自动：")) → true`；`fromUTF8("abc不再限幅").indexOf(fromUTF8("不同！")) → 3`（不是 −1）；`fromUTF8("已经").startsWith(fromUTF8("已锁定")) → true`；`fromUTF8("「自动」时旋钮很灵").contains(fromUTF8("「自动」时旋钮不生效")) → true`。对照：ASCII 的 `"abcdef".contains("abd") → false`、`startsWith("abc") → true` 正确；不走 `compareUpTo` 的 `endsWith`、`operator==` 正确；`std::string::find` 正确。首次发现于我自己的断言：`metrics.md` 里明明没有「不同！」，`indexOf` 却在「不再限幅」处返回 197。
- **影响范围**：生产代码不受影响——`Source/` 里没有对中文 needle 用 `contains / startsWith / indexOf` 的地方（`AdvancedDrawer.cpp:320` 用的是 `endsWithIgnoreCase`，逐字符倒着比；`CeladonLookAndFeel.cpp:104` 是 `StringArray::contains`）。受影响的只有上述 5 处测试断言（4 处是本次新增的 HelpTextClay，1 处是 v0.6 的 GlazeStatusText）。
- **建议修法**：测试里加一个字节精确的辅助（例如 `bool utf8Contains (const juce::String& s, const char* needle) { return s.toStdString().find (needle) != std::string::npos; }`、`utf8StartsWith` 用 `rfind (needle, 0) == 0`），5 处改用它；顺手在 `tests/TestHelpers.h` 注明原因。上游 JUCE 值得报一个 issue（`compareUpTo` 的 `char` 快路应按码点走慢路，或调用方把 `maxChars` 换成字节数）。
