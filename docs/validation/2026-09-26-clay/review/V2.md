### V2-02（low · 注释与实际不符）`applyFeedback` 的注释说校准偏差「吸收前后都在」，实际上反馈后偏差归零重测

- 文件：`Source/dsp/GlazeController.cpp:1438-1442`。
- 现象：注释写「校准偏差在方案之上照常施加，吸收前后都在（biasTarget：校准适用时取已提交的偏差，改写后『保留偏差作为新轮基线』）」。实际路径：`lowerGainCap` 改了 `feedbackMaxGainDb` → 它在 `conditionsHash` 里（`GlazeController.cpp:245`）→ `currentReference.manualParamsHash` 变 → `calibrationApplicable()` 为假、`heldBiasKnown` 在下一块 `beginBlock:2089-2093` 被清 → `biasTarget()` 回 0 → 偏差按 1 dB/s 滑到 0 → 过渡结束后重开校准轮。「保留偏差作为新轮基线」只对读档 / 重建后 `heldBiasKnown` 为真的情形成立。
- 证据（复现日志，glazestep 场景，现树）：s=38 `bias=0x3f8d28e0`（1.10 dB）、s=39 `bias=0x3e6afc00`（0.23）、s=40 `bias=0`、s=42 `calB=2`（新一轮校准开始）。基线同样如此（旧公式下也归零重测），所以行为本身没有变坏。
- 定性：行为正确（上限约束的是净响度目标，偏差是控制量，新公式把两个域分开是对的；归零重测也是既有设计），只是注释的理由写错，会误导以后的维护。建议改注释：「反馈改了参考条件，已提交的校准随即不适用、偏差归零并重测；所以上限只应含方案净提升与实际退让，不含偏差——含了就在重测前把目标抬高 |偏差|」。

## 3. `applyFeedback` 修复核对（重点 ③）

- 公式核对（审核副本里的 `ReviewV2Cur`，现树独有）：GLAZE 100、冲击 / 温润两种风格、学完后素材 ×5，逐块拆开 `setParams` / `process` 读探针；每一次约束反馈的新上限 = max(手动链净增益, beginBlock 时的 `targetPlan.effectiveGainDb` + `executedGuardDb` − step)。两种风格各触发 1 次（预算受限，step 0），误差 0.000000 dB：`plan 4.4821 + guard −1.3100 → cap 3.1721`（当时偏差 +0.7864，不再被算进去）；`plan 4.7383 + guard −1.1500 → cap 3.5883`（偏差 +0.8514）。
- 语义核对：`feedbackMaxGainDb` 经 `PlanInputs::maxGainDb` 约束的是 `plan.effectiveGainDb`（净响度目标，含手动链）；校准偏差是为达到该目标补的 Limit Gain 控制量，不属于目标域。旧公式在偏差为正时把目标抬高 |偏差|（反馈几乎不降），偏差为负时多降 |偏差|；新公式两侧一致。对四条触发路径（预算受限、方案受限、上游超限、保护层卡住）统一生效；画像失配走 `lowerGainCap(sectionPlan.effectiveGainDb)` 不经 `applyFeedback`，不受影响。
- 既有测试意图：`testConstraintFeedbackConverges`、`testStuckGuardIsAbsorbed` 只断言单调 / 收敛 / 不悬挂退让 / 不低于手动链，不绑定旧公式；本机第 5 轮全套 127828 过 / 0 失败。
- 附带观察见 V2-02（注释）与 V2-01（与旧版行为的差异量）。
