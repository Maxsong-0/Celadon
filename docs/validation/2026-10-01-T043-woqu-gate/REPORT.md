# T-043 woqu g70 门槛失败：查因与修复（2026-10-01）

> 档案：BUG-010（峰值守护混合低切让低音互相抵消）、ADR-027（修坯守护的混合损失进先试后用与压力反馈）。
> 全部编译、测试、渲染在服务器上（107 测试，109 渲染 / MSVC）；本机 Mac 没编没测。回路脚本 `t043.sh`。

## 1 结论

- **不是代码回归。** 二分（`bisect-woqu-g70.txt`，各提交自己的 celadon_render）：v0.1.7.1 `49067f2` 到 T-032 前 `67b9da9` 都过，
  翻在 T-032 A4 合并 `b37632c`——R10-01 让渲染工具改取新实例默认，0.1.9.0 的「目标频谱 自动」从此在门槛里开着。main 上只关目标
  频谱 → 过（−0.169 / −0.184）。
- **损失 v0.1.7.1 就有**：T-022 时 woqu g70 也是 −0.183 LU，入口峰值恰好也降 −0.173 dB，靠「同降」豁免过关；目标频谱只挪了最大
  峰值那一下（−0.173 → −0.099 dB）。
- **不是短歌口径问题**：门槛比的是同决策重放，锁不锁定不进比较（T-022 时锁定的 g35 也是 −0.150 LU）。修坯确实帮了倒忙。
- **真因：峰值守护的混合**（ADR-014 ④，输出 x + g·(y − x)）。4 阶最小相位低切在 40～80 Hz 转了相位，0 < g < 1 时干路与低切后的
  信号部分抵消。woqu 守护介入 75 %、最小 g = 0：40～60 Hz −0.7 dB、25～40 Hz +2.1 dB（g 调制出的边带），整体 −0.2 LU；次声却只少了
  2.8 dB。原曲直接过同一低切只 −0.001 LU（`woqu-g70-band-diff.txt`）。
- **守护不能拆**：只把越界判定强制为假（g ≡ 1）跑 22 首（`compare-main-vs-noguard.txt`）——woqu −0.199 → +0.002 LU，但 somggggg
  入口峰值 −0.17 → +0.57 dB（败）。
- **两层决策都看不到它**：先试后用量的是不经守护的块峰值 P99（woqu 试出 −0.172 dB，判为有利）；压力反馈只量「超出界 B 多少 dB」，
  ADR-014 当时特意不用回收量 mean(1 − g)，理由是「温和低音」上回收量夸大了伤害——按混合损失看，那份素材（60 + 110 Hz）守护
  一回收就丢 0.4 dB 低音（GlazeControllerTests 的新日志），伤害是真的。

## 2 修法（Max 17:5x 选「两层都补」）

| 层 | 做什么 | 门槛 |
|---|---|---|
| 测量 | 守护每段把「本该输出」（g 当 1）存一份，段末按 BS.1770 K 加权累计本该与实际两份能量；量不量、差值滤波器归零都只在 64 样本网格点上定（与块长无关）。守护算术不动，输出逐位不变 | — |
| 先试后用 | 分析器在学习区间里跑两个候选（10 / 20 Hz 低切 + `ClayModule::PeakGuard`），量同一指标，进画像（可选字段 `lowCutBlendLossDb0/1`，不升格式号）；决策器按两点幂律预测，把低切封顶在预测损失 = 门槛处，地板处已超就不切、置代价位 | `clayBlendLossLimitDb` 0.09 dB |
| 运行中 | 压力反馈第二个触发量：两份能量 2 s 平滑后持续 1 s 超过门槛就降一档，与第一条共用冷却 | 0.15 dB |

门槛的数据依据（`trial-blend-vs-cutoff.txt`、`synth/`）：

- 损失随低切频率单调上升，log-log 斜率 q = 1.5～1.8（物理渐近 2：相位差 ∝ fc / f，损失 ∝ 相位差²）；两点幂律在 12 / 14 Hz 处与实测差
  ≤ 0.006 dB，所以只用两个候选（三个完整 ClayModule 候选时学习期 97.6 µs / 块，超护栏 60；两个轻量守护候选 56 µs）。
- 0.09 = 门槛容差 0.1 LU 减去试用（原始输入）对链内实测的偏差：woqu 链内比试用高 3～6 %，somggggg / mp3 低约 10 %，合成偏置低音
  高 17 %（ClayGlazeTests 第 13 条：预测 0.09 → 链内 0.105）。门槛正好放 0.1 时 woqu 会被封在 12.5 Hz、链内约 0.107，擦着门槛失败。
- 运行中 0.15 = 1.5 倍容差：正常歌 2 s 平滑后的起伏（mp3 0.07～0.12 dB）碰不到；woqu 未封顶时 0.17～0.25 dB 一直在上面。

## 3 验证

- **22 首门槛**（109，`gate22-fix-check.txt`）：**0 失败**。woqu g70 低切 20 → 11.6 Hz，链内混合损失 0.096，dLUFS −0.199 → −0.088；
  g35 16.25 → 11.6 Hz，−0.154 → −0.091。somggggg_mp3 g70 预测损失 0.097 > 0.09，12.09 → 11.57 Hz，门槛数值 +0.003 → +0.004。
  其余 170 / 176 行音频哈希与 main 逐位相同（`compare-main-vs-fix.txt`），运行层一次没触发。
- **只留运行层**（门槛常数置 0 的变体，模拟旧画像，`compare-main-vs-runtime-only.txt`）：woqu 降一档（20 → 14.1 Hz，0.215 → 0.150 dB，
  dLUFS −0.199 → −0.139，改善但不够过门槛——重新聆听后由试用层封顶）；其余 4 首低切歌哈希全同。
- **测量正确性**：ClayTests 独立 K 加权（标准表系数）核对实际输出能量（相对 1e-6）、用「缩到守护地板以下再放大」核对本该输出能量；
  分析器试用与链里 ClayModule 在同一素材上 0.2130 / 0.2134 dB；运行测量与门槛响度差一一对应（woqu 0.215 dB ↔ −0.199 LU）。
- **celadon_tests**：107 GCC 最终源码 **136867 过 / 0 败 / 0 编译警告**；`-march=x86-64-v3`（ADR-013）与 109 真 MSVC + Wine（ADR-019）
  各 136867 / 0 / 0 警告（这两轮在删掉一个未用成员之前的源码上，那处由最终 GCC 全套覆盖）。
- **性能**（109，单核，2 首低切歌 × 两遍，各 4 次）：渲染耗时 4.84 → 5.03 s（+3.9 %，约 +0.13 % 单核，含学习期试用）；分析器学习期
  护栏 56 µs / 块（< 60）。Mac 整插件基准没跑（只能在 Mac 上编）。

## 4 留给 Max

1. `clayBlendLossLimitDb` 0.09 是标定常数：降到 0.08 给 woqu 这类歌多留余量，但 somggggg / mp3 也会被轻微封顶；
2. ADR-014 当年「回收量夸大伤害」的判断被本次数据推翻（ADR-027 记录），请复核；
3. 手动低切同样经守护混合（压力反馈只缩自动项），手动态不处理——要不要提示待定；
4. 下次在 Mac 上跑整插件性能验收时把 Clay 测量的开销算进去。
