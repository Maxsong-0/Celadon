## 1. 改了什么

1. modules 模式的手工链照 `CeladonChain::setParams / processSlice` 补上 Clay：
   - `setParams (eff.clay)`；
   - 按信号顺序 prepare；
   - Balance 与 Color 之间加计时列 `clay`；
   - 模块统计带 `clayPressureDb / clayPressureSeconds`；
   - 交给 endBlock 的延迟 = 四个模块之和。
2. 新场景 `auto50xover`，只在 modules 模式有：
   - GLAZE 50；每约 50 ms 把实际收单分频点在 40 / 42 Hz 之间换一次，a = 1；
   - 周期取奇数个样本（192 kHz 为 9601），换目标时刻走遍 Balance hop 的各个相位。
3. 输出：
   - MODULES 行加 `total_worst%`、`total_structWorst%`（与 grid 同口径）、`latency`；
   - 切换场景另打 XOVER 行。
4. grid 模式的 hop 计算提成函数 `balanceHopSamples`，行为不变。
5. 非 modules 模式点名切换场景会报错退出，「all」会跳过它。

## 3. 结果

### 3.1 Clay 常态开销（clay 列，按块预算）

| | 48k / 32 | 48k / 512 | 192k / 32 | 192k / 512 |
|---|---|---|---|---|
| 平均 | 0.205～0.213 % | 0.200～0.209 % | 0.83～0.89 % | 0.77～0.83 % |

- 场景不同差得很少：三级影子运行、守护一直在算。
- 强制 a = 1 的切换场景高约 0.03 / 0.1 个百分点。

### 3.2 分频点切换（XOVER，4 次 192k / 32 + 各 1 次其他配置）

| 配置 | 切换多出（中位数） | 切换块结构性最坏 | 其他块结构性最坏 | 最坏块增加 |
|---|---|---|---|---|
| 192k / 32 | **18.2～18.5 µs**（10.9～11.1 %） | 29.6～30.4 % | 18.7～19.0 % | **+10.9～+11.4 pp** |
| 192k / 512 | 19.9 µs（0.75 %） | 7.66 % | 6.90 % | +0.76 pp |
| 48k / 32 | 4.67 µs（0.70 %） | 3.35 % | 2.63 % | +0.72 pp |
| 48k / 512 | 6.83 µs（0.06 %） | 1.51 % | 1.45 % | +0.06 pp |

- 切换块的 Clay 最坏（各遍最坏里最小的一遍）：192k / 32 为 23.8～30.5 µs。
- 实测落在 P1 估计的 15～45 µs 低端。
- 结构性最坏 ≈ Balance 做 FFT 那一块（约 19 %）+ 预热（约 11 %）≈ 30 %，离 100 % 还远。
- 对规格预算（设计规格-Clay-分析决策与验收 第 5 节「192k / 32 最坏块增加 ≤ 0.5 个百分点」）：
  - 切换那一块超出，与 P1 第 3 节第 3 条的预判一致；
  - 摊薄做法见 P1 第 6 节第 2 条，要改 LinearPhaseLowpass 或 ClayModule，需 Max 拍板。

### 3.3 单次最坏不可比

- 192k / 32 的 `total_worst%`（各遍最坏里最小的一遍）各场景在 25～59 % 之间跳（本日志；早先未存档的试跑到过 76 %），被系统抖动主导。
- 比较场景看 `total_structWorst%`：auto50 与 auto50xover 都约 18.4～19.0 %。
- 切换块不在固定相位时会被中位数滤掉，所以另看 XOVER 行。

## 4. 走过的弯路

1. 周期取整 50 ms（192 kHz 9600 个样本）：只碰到一半的 hop 相位，切换可能永远落不到 Balance FFT 那一块。改为奇数个样本。
2. 「切换块 = 整组 50 ms 里 Clay 最慢的一块」：偶尔被系统抖动顶替。有一次孤立相位的中位数读出 208 %，另一次 52 %。
   - 改成只在换目标后 3 ms 里找（切换在 64 样本网格点开始，44.1 kHz 下 1.45 ms）；
   - 结构性最坏只算至少 5 个样本的相位组。
   - 之后 4 次复测一致。

## 5. 范围外，已报 Max、未改

1. 手工链不按 Guard 10 ms 时隙切片：v0.1.6.2 起 GLAZE > 0 时真链会切。已在代码注释写明。
2. Clay 常态平均约 0.20 %（48k / 512），超过规格第 5 节「48k / 512 平均增加 ≤ 0.15 个百分点」。v0.1.7.0 的整插件性能验收（grid，对 v0.1.6.2 比）还没跑。
3. `Source/dsp/CeladonChain.h:26`、`CeladonChain.cpp:333` 的延迟注释还是 856 / 1528，没跟上 ADR-014；实际 48 kHz 为 1384。`restartWithFadeIn` 的注释也把 Clay 的延迟写成 D（574）。
