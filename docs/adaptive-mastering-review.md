# Celadon：按歌曲自适应的母带改进

2026-09-26。用户要求：插入总轨后自动改善、一个总旋钮控制力度、兼顾透明增响与染色、低 CPU；默认取向由歌曲决定。插件对外版本继续使用 **v0.1.6.2**，本轮成品另标记为 adaptive 试听包，与此前试听包分开保留。

后续更新：本报告所列的低频保真染色、声像保护和导出一致性已在下一轮实现，见 [新一轮检查与验证](colour-and-render-revision.md)。下文保留本轮历史记录。

## 结论与产品方向

项目已具备完整的 Balance → Color → Limit 主链、真峰值保护、风格混合、自动学习及响度校准。真正影响开箱效果的缺口集中在自动决策的选择性、段落变化和可信试听。继续增加旋钮或统一加大处理量，并不能解决这些问题。

本轮方向是：保持歌曲长期风格，缓慢适应段落明暗；在频段层面区分持续突出和短暂起音；把处理后的响度与原始输入实测比较。它们是 Celadon 值得打磨的组合体验，不宣称行业首创，也不代表已达到三个参考产品的听感质量。

现有商业产品已经覆盖“简单自动母带”的许多部分：[pure:limit](https://www.sonible.com/purelimit/) 提供一键分析与响度处理；[Invisible Limiter](https://aom-factory.jp/products/invisible-limiter/) 以透明前视限幅和自动时间优化为重点，其 Unity Gain Monitoring 抵消的是补偿增益；[The God Particle](https://cradle.app/products/the-god-particle) 把谐波处理、总线声音和自适应限幅结合，并提供固定的开箱设置。因此，差异化应来自处理判断、保留音乐意图和可验证的工作流，而不是只给功能取新名字。

## 本轮实现与使用

### 自动启动

新插入实例为 GLAZE 35%、Auto 风格。先采用低置信度的温和方案，播放后继续分析和学习。GLAZE 0 保持严格手动语义。显式保存的参数和缺少 GLAZE 的旧状态有独立恢复测试。

### 逐频段处理许可

自动 Tame 与手动 Tame 区分：手动量保持原曲线；自动新增部分需要当前频段具备持续局部突出的证据，遇到起音时暂缓增加削减。逐段许可在 180–450 ms 渐入，检测到起音后保护 60 ms，自动新增削减最多 2.5 dB/段。它使用已有频谱，不能可靠辨认人声语义、每个乐器或所有短齿音，也不是独立去齿音器。

### 双向明暗适应

自动 Tone 可以正向提亮，也可以负向柔化。段落判断沿用原始输入频谱，与歌曲长期画像按相同频段权重比较；通过 0.35 dB/oct 死区、有效带宽、满强度 0.15 dB/s 跟随速度和 ±0.75 dB×GLAZE 的风格上限，减少镲片或单一音符误触发。自动风格与响度目标不因短期明暗变化重新选择。算法与出厂标定快照版本升至 4；Heat 传递曲线及其查表保持上轮版本。

### 整链实测 Listen

Listen 使用已有输入/输出 K 加权能量，补偿 Balance、Color、Gain 与限幅的总体响度提升。使用 1 秒连续能量窗口，静音也纳入累计；边缘瞬态占比过高时暂缓更新，避免把跨窗鼓点误判成增响。输出仪表和校准器读取试听补偿前的母带信号；Listen 不再暂停自动处理或校准。只做衰减，不在输出比输入更弱时加大音量，以保留末级峰值保护。

这是一种缓慢跟随的等响试听辅助；子块的延迟配对是统计近似，切换或编曲突变后的短时间内不能保证完全等响。Listen 本身不切换成原音，需要结合宿主旁通比较，导出前关闭。

## 验证与边界

完整 DSP 回归 **109802 passed / 0 failed**。覆盖手动/GLAZE 0 逐位一致、真峰值、块长、分配、立体声、静音、自动化、学习与保存恢复，以及本次新增路径。首次测试为 108466 passed / 2 failed：一项旧测试仍要求偏亮素材不作负向 Tone，另一项 Listen 增益编辑后跟随过慢；修复语义与响应后全套重跑通过，未放宽原有防泵、峰值和等响门槛。

新增实测：粉噪背景中的持续 1 kHz 峰降低 **2.503 dB**，同时出现的 4 kHz 短起音变化 **−0.009 dB**；这是指定合成信号结果。44.1/48 kHz 下，纯增益、Color Output 和含 Heat/Glue/Clip/限幅的稳态素材，最终监听音频与输入的响度差为 **0.000～0.002 LU**。跨 100 ms 窗口的稀疏脉冲中性测试、17/2048 块长一致性、静音、旁通、延迟变更、大块丢环恢复通过。非零 GLAZE 双链测试确认 Listen 切换不改变处理参数、补偿前仪表或校准结果。

Listen 大幅修改 Color Output 6 dB 后，第三秒末尾 1 秒的响度差为 **−0.0241 LU**，通过原定 0.15 LU 门槛。

真实 `CeladonAudioProcessor` 的默认值与状态恢复检查 **8 项通过**。两秒时已执行自动 Tame 与 Heat；接近满刻度的密集基准素材 Gain 为 **0.049 dB**，同一素材降低输入约 12 dB 后为 **0.680 dB**。最初检查错误地要求所有输入两秒后 Gain >0.05 dB，诊断后拆为“自动频谱/染色启动”和“有余量时给出更多增益”两项，未修改 DSP 迎合测试。显式保存 0、旧状态缺参、新实例恢复旧状态、当前参数保存重开均通过。

### CPU 与延迟

本机 Apple M2 Pro、交流电、低电量模式关闭；Release/LTO，完整处理器，无界面。固定合成素材，预热 45 秒音频，每档测三次、每次 4 秒，使用现有基准工具的最快一遍平均耗时。百分比为**处理耗时占单个音频块时长**，不是整机 CPU 百分比。

| 采样率 / 块长 | 改前 Auto100 | 改后 Auto100 | 新实例 Auto35 |
|---|---:|---:|---:|
| 48 kHz / 64 | 1.286% | 1.290% | 1.241% |
| 48 kHz / 512 | 1.189% | 1.219% | 1.173% |
| 96 kHz / 64 | 2.559% | 2.556% | 2.448% |
| 96 kHz / 512 | 2.372% | 2.357% | 2.315% |

平均开销基本持平，最大增加 **0.030 个百分点**；小幅下降处不解读为确定性能提升。Auto100 全遍最坏单块占用 17.087%，P99 为 1.387%～4.013%；最坏块受操作系统调度影响。所有档位 nonFinite=0。48/96 kHz 延迟分别为 **282/378 样本**，与改前一致，未新增 FFT、过采样链或音频延迟。预热结束 profileReady=1，calibrationValid=0，phase=2/3，代表画像已取得、方案过渡或校准仍在进行，不能说已完成校准。

### 成品验证

AU/VST3 Release arm64 构建成功；两种格式的 BundleVersion 与 ShortVersion 均为 0.1.6.2，本地签名深度/严格验证通过。新 VST3 成品在测试宿主中实际实例化并处理，48 kHz 的平均块预算占用为 1.035%～1.107%，96 kHz 为 2.035%～2.160%，延迟仍为 282/378 样本。这不是用户 DAW 的验收；AU 完成构建和签名检查，尚未在用户 DAW 中试听。试听包未自动安装，也未替换此前的同版本试听包。

原始日志、源码散列和本轮差异见 `docs/validation/2026-09-26-adaptive-mastering/`。合成信号用于验证方向、幅度、稳定性、真峰值和资源开销；没有用户的真实歌曲素材，本轮不能给出主观盲听胜率，也不能保证任意歌曲插入后都更好听。

现有 27 段系统与 [Gullfoss 的感知处理设计](https://www.soundtheory.com/static/Gullfoss%20Operation%20Manual.pdf) 不是同一算法；公开功能描述不足以证明可替代。完全自适应仍需保留“不处理也是正确选择”的能力，并用不同类型的真实混音校准。
