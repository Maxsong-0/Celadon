## 口径

**百分比 = 单个音频线程上「处理耗时 / 这一块音频的播放时长」**，不是活动监视器里的整机 CPU，也不是某个 DAW 的表值。预算上限是这条线程的 10 %。装进系统的只能是 Release（Debug -O1 满载爆音就是这么来的）。

## 各级优化过什么

- 真峰值检测按块向量化（NEON / SSE2）：Limit 默认 48 kHz / 64 从 2.80 % 到 0.22 %，三处真峰值合计 1.77 % → 0.12 %。
- Clip 与 Heat 共用自写块式半带过采样器（与 JUCE 差 < −130 dBFS）；空闲跳过 + 预滚，逐位不变。
- 修坯峰值守护按 64 样本段重写、静止走快路：修坯一级快 1.3 ～ 2.0 倍（x86），输出逐位不变。分频点切换分摊预热：尖峰 +11 → +0.125 个百分点。
- 参考学习 FFT 分片摊到多个回调：192k / 32 学习路径 p99.9 从 168 µs 降到 66 µs。
- 校准参考条件缓存：192k / 32 每块省 0.1 ～ 0.2 个百分点。

## 逐位契约的编译前提

乘和加各自舍入，编译器不许融合成 FMA，否则 HalfBand / Saturator / TruePeak 的守卫在有 FMA 的目标上 `#error`：

| 编译器 | 要求 |
|---|---|
| Apple clang（Xcode） | 默认 `-ffp-contract=on`（只合并同一表达式），不加选项 |
| GCC（服务器） | `-ffp-contract=off` + `CELADON_FP_CONTRACT_OFF=1`（默认 `fast` 曾造成 369 项失败） |
| MSVC | `/fp:precise`；不许 `/fp:contract`、`/fp:fast`；八个 DSP 文件另写死 `#pragma fp_contract (off)` |
| clang-cl | `/clang:-ffp-contract=off` |
| 任何 | 不许 `-ffast-math` / `-Ofast` |

x64 的 SSE2 快路径只在「不合并乘加」时开。真峰值取大两边写死成同一条指令（x86 `maxss` / `maxps`），FTZ / DAZ 四种组合逐位一致。

跨平台的成品在最后几位上本来就不同（arm64 的 TruePeak / Balance 用融合乘加、x86 分开；Mac 的 FFT 是 vDSP；Windows UCRT 按 CPU 换超越函数实现），所以逐位契约只在同一台机器的同一种构建之间成立，跨平台对照用 dB / LU 门槛。

## 没验的

- 真实 DAW 里的侧链路由、自动化、实时导出与歌曲等响听音；编码器（AAC / MP3）后的真峰值；Windows 真机与 Intel Mac 的性能网格；老电脑、多实例并发。
- 合成信号测试不能替代听感验收。
