# GLAZE · 决策与跟随

「大旋钮不能是把所有旋钮调大，你需要根据音乐的整体状态全自动通过算法实现效果以及提高音量。」——GLAZE 边播边听这首歌，按它的响度、动态、频谱、起音一路决定怎么处理、推多少响度；旋钮只决定朝这首歌的理想母带推多远。

## 五个关键选择

| 问题 | 决定 |
|---|---|
| 怎么随音乐变 | 一直听：按主段加权的实时画像每秒喂一次决策器，自动增量按速率限制与棘轮走向新目标，慢慢升、较快降；没有聆听期，也不锁定 |
| 旋钮含义 | 强度：朝「这首歌的理想母带」推多远；0 = 完全不动（等于手动结果） |
| 手动旋钮 | 算法值为底，旋钮是微调：实际值 = clamp(手动值 + 自动增量)；绝不自动抵消你的修改 |
| 画像何时更新 | 一直在更新，随工程保存（`LIVE`）；没有「重新聆听」，也不按宿主走带判断换歌：旧统计按软遗忘逐渐淡出 |
| 风格 | 四选一：自动（默认）/ 温润 / 冲击 / 通透；自动按歌混合三种风格的权重 |

## 七个单元

| 单元 | 职责 |
|---|---|
| **MusicAnalyzer + LiveProfile** 分析器与实时画像 | 入口特征（M / S / I / LRA、PLR / PSR、频谱正负证据、起音、置信度）进一份逐小节的实时段落账（所有曲风同一份）；LiveProfile 按主段度加权，到点发布画像与 c |
| **GlazePlanner** 决策器 | 纯函数：已发布画像 + 风格 / 曲风 / 交付 + GLAZE + 手动值 + 出厂常数 → 目标（7 项自动增量、Clay 自动值、目标响度、风格权重） |
| **GlazeConstants** 出厂常数 | 风格偏好、曲风档案与 House 常数、交付三档、各模块约束、Heat 换算表；不再随工程存快照 |
| **速率限制与棘轮** | 已施加增量走向目标：增益慢慢升、较快降；此刻 m < 0.5 时净增益只降不升 |
| **G_trim + OutputLevelTracker** 出口修正 | 按出口主段电平与目标之差做很慢的修正；预算环退让时冻结。取代校准器 |
| **守护族** GlazeGuard / ContrastGuard / PsrGuard | 预算环、落差、PSR 各出一份不加大音量的退让，取最小，加在 Limit Gain 上；状态行里的原因和已退量来自同一扇正在起作用的守护门 |
| **GlazeController** 编排 | 连续调度：每块重算或施加、写状态快照；工程只存 `LIVE` |

## 每一块做什么

1. 旋钮、风格、曲风或交付相对上一块有变：用当前已发布的画像立刻重算目标。GLAZE ≤ 0 时目标增量全为 0，速率限制、G_trim 与守护退让在这一块直接落到 0，交给模块的参数逐位等于手动值。
2. 分析：入口进实时段落账，段落收尾后进 LiveProfile，到点发布画像。
3. 分析器时间跨过 1 s 网格：用新发布的画像重算目标（同一块里只算一次）。
4. 速率限制把已施加增量推向目标，慢慢升、较快降；此刻主段度 m < 0.5 时，净增益只降不升。
5. G_trim 按出口主段电平与目标之差做很慢的修正。
6. 三道守护各出一份退让，取最小，加到 Limit Gain；真峰值仍由限幅器与 Ceiling 硬保证。
7. 写状态快照（界面七条只读它）。

没有聆听、方案过渡、校准与锁定。冷启动时 c = 0，决策器走低置信度的保守方案，c 随主段质量上升。

## 决策器的目标与约束

- requestedTarget：交付、风格与 GLAZE 想要的响度；effectiveTarget：经各模块约束后当前允许追求的响度，出口修正 G_trim 与状态行的「目标」都用它。
- **一旋钮底量**（满强度请求，之后按 GLAZE、置信度、风格上限、模块预算缩放）：增响请求下限 3 dB（三档交付都有，已达偏好响度的歌也保留）、自动 Recover 8、自动 Tame 24、自动 Heat 12。
- 已够响的素材照样保留这份最少推响量（只往上推、不衰减）；流媒体 / 俱乐部两档的目标有硬上限（−8 / −5 LUFS），输入已不低于上限时请求才为 0；超限时**降低目标而不是硬压**。
- 自动 Tone 可正向提亮也可负向柔化：与画像按同权重比较，0.35 dB/oct 死区、有效带宽、满强度 0.15 dB/s 跟随、±0.75 dB × GLAZE 的风格上限（House 类曲风往亮收到 0.4 dB，见下面「曲风与交付」）。风格与响度目标不因短期明暗重选。
- 自动风格不再被没攒满的 60 s LRA 置信度整体压向通透；LRA 仍单独约束动态特征。
- 并联 Heat 的削峰份额是可选贡献：它不足时不锁死仍有余量的限幅器。
- **自动 Heat 只承担真能削的峰（算法 / 标定版本 8，0.1.8.6）**：这首歌在 Heat 上限内能削掉的峰值 ≥ 0.1 dB 时才为削峰加 Heat，否则只给风格底量（出厂三种风格都是 12）；满强度自动 Heat 由原来按风格的 70 / 50 / 20 降到 12 左右。旧工程里的常数快照读入时丢弃，方案一律用本版本的出厂常数。

## 曲风与交付

0.1.8.8 起，GLAZE 多了两个互相独立的选择，原则只有一条：**曲风只换音色目标与认主段的方式（House 类另加限幅释放跟拍与反相提示），自己不带绝对响度；响度归交付；动态预算（限幅、粘合、削波能压多少）仍归风格。**依据是调研里 House 的三个子类在动态上分不开、差别在频谱，所以曲风不碰动态预算。两个选择都不改信号链（模块与顺序不变）：它们给 GLAZE 的分析器、决策器和编排器加常数与条件，另有三处直接交给链——「目标频谱 = 自动」的形状、流媒体的 −2 dBTP 上限、House 类曲风给 LIMIT 自动释放加的拍子上限；后两处与 GLAZE 旋钮在哪里无关。「通用 + 标准」不起任何作用。

### 曲风档案

House 的三个子类在风格权重混合之后覆盖下面四项（通用一项也不覆盖；只覆盖自动部分，不改你手动设的值）：

| 项 | 通用（按风格） | Deep / Tech / Melodic |
|---|---|---|
| 自动 Tone 的参考斜率（BALANCE 段内总功率口径，粉噪 = 0） | −3.5 / −2.5 / −2.5 dB / 倍频程（温润 / 冲击 / 通透） | −2.25，三类相同 |
| 自动 Tone 的上限（两头同样 × GLAZE） | 往亮往暗都是 0.75 dB | 往亮 0.4 dB，往暗仍是 0.75 dB |
| 自动低切的目标频率 | 16 / 18 / 20 Hz（温润 / 冲击 / 通透） | 25 Hz |
| 自动加宽的风格系数 | 0.4 / 0.6 / 1.0 | 0（不自动加宽） |

「目标频谱 = 自动」时的形状斜率（dB / 倍频程，以 1 kHz 为零点）：通用按风格取（温润 → 温暖 −1.5，通透 → 明亮 0，自动与冲击 → 均衡 −0.75）；House 取 Deep −1.5、Tech −0.75、Melodic −1.25。

参考斜率 −2.25 是按 45 首独立制作的 House 成品（每个子类 15 首）标定的：三个子类的谱斜率中位数分别是 −2.21、−2.19、−2.24，量不出明暗差别，所以三类共用一个值，子类之间唯一的区别是目标频谱的形状（只在「目标频谱 = 自动」时起作用）。往亮的上限收到 0.4 dB，是因为 DJ 变速播放后，靠极高频撑起来的声音容易发假。

### House 类曲风的主段

所有曲风共用同一份实时段落账：一段 = 一小节，按宿主的位置与拍号定位；拿不到拍点时改成每 2 秒一段；同一小节重放覆盖旧值、不重复计入；最多记 512 段。曲风只换「怎么认主段」：House 类用四拍舞曲模型，通用用响度模型。画像按主段度加权，所以前奏、breakdown 进画像的分量小；此刻这一段 m < 0.5 时，棘轮让净增益只降不升，轻的段落不会被推上去。没有锁定条件、暂定方案和锁定后的补听；状态行在「跟随」前面加「House ·」。

逐小节地把前奏完全挡在外面仍然做不到：底鼓、低音都齐、只比 drop 轻 1 ～ 3 LU 的 DJ 前奏，主段度可能接近 drop。

### 限幅释放跟拍

通用的自动释放里，慢段在 100 ～ 800 ms 之间，按最近 500 ms 的平均衰减插值。以平均衰减 1.5 dB 为例，慢段约 190 ms、增益恢复约 0.56 秒，比 124 BPM 下一拍的 0.48 秒还长——下一拍的底鼓来了，增益还没回来。House 类曲风下，慢段释放取 min(自适应值, max(100 ms, 一拍 ÷ 3))，一拍 = 60000 ÷ BPM（四分音符），124 BPM 下约 160 ms。

只在以下条件全部满足时生效：曲风是 House 类；Limit 是 Auto 释放；宿主速度有效且在 100 ～ 140 BPM 之间；正在播放。任何一条不满足都照通用的走。手动 Release、短过载（< 70 ms）的快释放分支都不受影响，也与 GLAZE 是多少无关：选了 House 就是选了这种限幅行为。工程速度可能不等于音频速度（例如在默认 120 BPM 的空工程里处理成品）：上限只是收紧到一拍 ÷ 3，速度设错的后果有限，插件不做音频节拍跟踪。

### 反相提示

CLAY 通用的反相灯在慢路低频相关度低于 −0.2 时亮。House 类曲风另加一条更灵敏的提示：主段落里慢路低频相关度 < 0.6，并持续 4 小节（拿不到拍点时 8 秒），就在 GLAZE 状态行与 CLAY 卡片上写出单声道回放会丢多少低频。0.6 约对应单声道低音损失 1 dB 起（左右等功率时，单声道功率 ∝ (1 + ρ) ÷ 2）。相关度回到 0.6 以上后保持 2 秒再熄灭（离开主段落则立即熄灭），亮起时的损失 dB 按公式算、之后 1 秒平滑。只提示、不处理音频，也不自动收单——收单只改立体声、单声道回放不变，救不回来，要回混音里修；GLAZE 为 0 时不提示。

### 交付

下面算出的是 GLAZE 100 时的满强度目标，实际推多远还要乘 GLAZE 与置信度系数（= 0.35 + 0.65 × 置信度，置信度满时为 1），超出模块预算时再降低目标。流媒体与俱乐部：目标响度 = 档位响度 + 风格偏移 − 响度范围（LRA）修正，再钳进该档的允许范围；标准档：风格混合后的偏好响度 − LRA 修正，钳进 −14 ～ −7 LUFS（偏好响度本身已按风格定，不再加风格偏移）：

| 交付 | 档位响度 | 允许范围 | 交给限幅器的有效 Ceiling |
|---|---|---|---|
| 标准 | 风格混合后的偏好响度（−8.5 / −9 / −10 LUFS） | −14 ～ −7 LUFS | 你的 Ceiling − 编码余量 |
| 流媒体 | −10 LUFS | −12 ～ −8 LUFS | min(你的 Ceiling − 编码余量, −2 dBTP) |
| 俱乐部 | −7 LUFS | −9 ～ −5 LUFS | 你的 Ceiling − 编码余量，不自动抬高 |

- **风格偏移**（只用于流媒体与俱乐部）= 风格混合后的偏好响度 − 冲击的偏好响度（−9）：温润 +0.5、冲击 0、通透 −1，自动风格按权重混合。**LRA 修正**照旧（LRA 超过 6 LU 的部分，每 LU 降 1/3 dB），在钳位之前减。
- **三档都有「最少推响量」（满强度 3 dB）**：输入已经接近或超过偏好响度时仍会温和地再推一点。**流媒体与俱乐部的允许范围上限是硬上限**：连这份最少推响量也不会把目标推过它（流媒体 −8、俱乐部 −5 LUFS），输入已经比上限响时不再推；标准档没有这道硬上限。
- **流媒体的 −2 dBTP 给有损转码留余量**，交给 LIMIT 的有效 Ceiling 一开始就按它封顶，与 GLAZE 旋钮在哪里无关。俱乐部档的 Ceiling 完全由你定、不自动抬高——没有可靠的依据说明俱乐部场合该用比你设的更高的天花板。
- **目标对准「响段」**：决策器按「目标 − 画像响度」算增益。通用曲风的画像响度按响度模型认出的主段算（最响的那些段落）；House 类按四拍舞曲模型认出的主段算（drop 这类满编段落），所以俱乐部的 −7 LUFS 指的是 drop，不是整首积分——后者被前奏与 breakdown 拉低，要完整播放一遍后才作为结果出现在 OUT 的整体响度里。

### 切换

换交付或曲风时，决策器在本块开头用当前已发布的画像立刻重算目标，施加侧走同一套速率限制，慢慢升、较快降，没有单独的过渡时间，也没有校准轮。播放中换曲风时，认主段的方式在下一次开播时才换。只换交付的两版母带共用同一份画像，Tone、BALANCE 与修坯的决策相同（换曲风则会改音色目标、低切与加宽）；差在目标响度与真峰值上限，以及为达到它所用的粘合、热度与削波量（三者都按「真峰值 + 增益 − Ceiling」的超限估计分摊）。已知限制：切换后马上离线导出，开头一段可能还没推到新目标；主段还没听够（c < 0.5）时离线导出，状态行会写「导出时主段统计还没热，第一个 drop 可能偏轻：先播放一遍再导出」。

## 存档与离线导出

工程里 GLAZE 只存一棵 `GLAZE_STATE`（格式 2），里面是 `LIVE`：实时画像窗口（`LIVE_PROFILE`）、速率限制器当前增量、G_trim、自动风格权重、三道守护、出口电平统计与修坯自动值，外层 zlib + base64，无损。读回后第一块起，这些控制量逐位等于保存时；滤波器与没写进 `LIVE` 的窗从零开始。旧工程的 `GLAZE_PROFILE` / `PLAN` / `CALIBRATION` / `EXECUTION` / `GLAZE_CONSTANTS` 读到就丢，按冷启动处理，界面提示一次。宿主 reset、停播、跳播不清 `LIVE`。离线与实时走同一条处理路径；每次导出都在更新统计，所以重复导出不保证逐位相同。

## 保护统计的时隙

Guard 用 10 ms 时隙均值的 p95 近似。链按保护层的时隙边界切片，模块统计不跨时隙；宿主整块仍用同一组执行参数，新的控制量在下一宿主块应用。

保护层的计时只按音乐时间走：宿主停止、静音、宿主旁通期间统计与观察期都冻结，不会误吸收反馈。每次重算目标（每 1 s，或换风格、曲风、交付）后，保护层与上游监视的上限都跟着换。手动设置单独已超出风格预算的项（Heat 驱动、Glue 均值 / p95、Clip 深度 / 活动），保护层与上游监视对该项不再设约束——那一项的自动部分本来就是 0，按风格上限核对只会白白退让；其余项照风格上限核对（以上三条 0.1.8.6）。

## 验收总表

1. 从初始化起 GLAZE 一直为 0、曲风通用、交付标准：整链输出与参照链逐位相同（90 个场景）。
2. 决策器是纯函数：同输入逐位同输出；随 GLAZE 单调；永不超各模块上限；GLAZE 0 时增量全为 0。
3. 已够响的素材仍保留最少推响量（标准档请求不低于它）；流媒体 / 俱乐部的输入已不低于上限时请求为 0；超限时降低目标。
4. 最终输出真峰值 ≤ Ceiling + 0.01 dB（8× 表口径）。
5. 保存往返：读回后第一块起，控制量（已施加增量、G_trim、三道守护、Clay 自动值、已发布画像）逐位等于保存时；重复导出不保证逐位相同。
6. 性能：GLAZE 开着时整插件 48k / 512 增加 ≤ 0.15 %，最坏块增加 ≤ 0.5 个百分点；音频线程 0 分配 0 锁。
7. 合成音乐只调 GLAZE = 50：累计响度提升 6.47 LU；GLAZE 0 / 25 / 50 / 75 / 100 → −23.97 / −20.61 / −17.24 / −13.96 / −10.64 LUFS（单一素材，不是任意歌曲的保证）。
