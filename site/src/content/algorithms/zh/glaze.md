# GLAZE · 决策与跟随

「大旋钮不能是把所有旋钮调大，你需要根据音乐的整体状态全自动通过算法实现效果以及提高音量。」——GLAZE 边播边听这首歌，按它的响度、动态、频谱、起音一路决定怎么处理、推多少响度；旋钮只决定朝这首歌的理想母带推多远。

## 五个关键选择

| 问题 | 决定 |
|---|---|
| 怎么随音乐变 | 一直听：按主段加权的实时画像每秒喂一次决策器，自动增量按速率限制与棘轮走向新目标，慢慢升、较快降；不用先听完一段再定方案，也不锁定 |
| 旋钮含义 | 强度：朝「这首歌的理想母带」推多远；0 = 完全不动（等于手动结果） |
| 手动旋钮 | 算法值为底，旋钮是微调：实际值 = clamp(手动值 + 自动增量)；绝不自动抵消你的修改 |
| 画像何时更新 | 一直在更新，随工程保存（`LIVE`）；没有「重新聆听」，也不按宿主走带判断换歌：旧统计按软遗忘逐渐淡出 |
| 风格 | 四选一：自动（默认）/ 温润 / 冲击 / 通透；自动按歌混合三种风格的权重 |

## 七个单元

| 单元 | 职责 |
|---|---|
| **MusicAnalyzer + LiveProfile** 分析器与实时画像 | 入口特征（M / S / I / LRA、PLR / PSR、频谱正负证据、起音、置信度）进一份逐小节的实时段落账；LiveProfile 按主段度加权，到点发布画像与 c |
| **GlazePlanner** 决策器 | 纯函数：已发布画像 + 风格 + GLAZE + 手动值 + 出厂常数 → 目标（7 项自动增量、Clay 自动值、目标响度、风格权重） |
| **GlazeConstants** 出厂常数 | 风格偏好、各模块约束、Heat 换算表；不再随工程存快照 |
| **速率限制与棘轮** | 已施加增量走向目标：增益慢慢升、较快降；此刻 m < 0.5 时净增益只降不升 |
| **G_trim + OutputLevelTracker** 出口修正 | 很慢的输出侧修正（每秒最多 0.05 dB，±3 dB 以内）：比「方案要把电平改多少」和「出口相对入口实际改了多少」，两边用同一批主段；方案还没到位、此刻不在主段、证据不足 3 s 时不动，守护有退让量、或 1 s 内改过参数时冻结。取代校准器 |
| **守护** GlazeGuard | 预算环：粘合 / 限幅 / 削波超出风格预算、或限幅压得过深时，出一份不加大音量的退让（最多 3 dB），加在 Limit Gain 上；条件消失后慢慢放回 0。状态行里的原因（预算 / 限幅）和已退量来自它。0.1.8.8 ～ 0.1.8.10 另有落差、PSR 两扇守门（只给 House 类曲风用），0.1.8.11 随曲风删掉 |
| **GlazeController** 编排 | 连续调度：每块重算或施加、写状态快照；工程只存 `LIVE` |

## 每一块做什么

1. 旋钮或风格相对上一块有变：用当前已发布的画像立刻重算目标。GLAZE ≤ 0 时目标增量全为 0，速率限制、G_trim 与守护退让在这一块直接落到 0，交给模块的参数逐位等于手动值。
2. 分析：入口进实时段落账，段落收尾后进 LiveProfile，到点发布画像。
3. 分析器时间跨过 1 s 网格：用新发布的画像重算目标（同一块里只算一次）。
4. 速率限制把已施加增量推向目标，慢慢升、较快降；此刻主段度 m < 0.5 时，净增益只降不升。
5. G_trim 做很慢的修正，误差 = 方案净增益 − 实测净增益（出口与入口在同一批主段上的响度差）。最近约 128 段（有拍点时一段一小节，124 BPM 约四分钟）的历史按各段录制时的 Limit Gain 折算到此刻，按此刻的画像回看重判哪些段还算主段，录制增益离此刻超过 1 dB 的段降权、超过 3 dB 的不算；自动增量还在往方案走的块既不当证据也不积分。
6. 守护出退让，加到 Limit Gain；真峰值仍由限幅器与 Ceiling 硬保证。
7. 写状态快照（状态行六条只读它）。

没有「先听一段再定方案」、方案过渡、校准与锁定。冷启动时 c = 0，决策器走低置信度的保守方案（界面上的「预热」），c 随主段质量上升。

## 决策器的目标与约束

- requestedTarget：风格与 GLAZE 想要的响度（风格混合后的偏好响度 −8.5 / −9 / −10 LUFS，减去 LRA 超过 6 LU 部分的 1/3，钳进 −14 ～ −7 LUFS）；effectiveTarget：经各模块约束后当前允许追求的响度（画像测到的输入响度 + 方案净增益），状态行的「目标」用它。出口修正 G_trim 只用其中的方案净增益（上面第 5 步）：画像的输入响度和出口统计不是同一批段，直接比目标响度会把两边的差当成偏差去追。
- **一旋钮底量**（满强度请求，之后按 GLAZE、置信度、风格上限、模块预算缩放）：增响请求下限 3 dB（已达偏好响度的歌也再推这一点）、自动 Recover 8、自动 Tame 24、自动 Heat 12。
- 已够响的素材照样保留这份最少推响量（只往上推、不衰减），没有硬上限。超限时**降低目标而不是硬压**。
- **目标对准「响段」**：决策器按「目标 − 画像响度」算增益，画像响度按响度模型认出的主段算（最响的那些段落）；不是整首积分——后者被前奏与 breakdown 拉低，要完整播放一遍后才作为结果出现在 OUT 的整体响度里。
- 自动 Tone 可正向提亮也可负向柔化：与画像按同权重比较，0.35 dB/oct 死区、有效带宽、满强度 0.15 dB/s 跟随、±0.75 dB × GLAZE 的风格上限。风格与响度目标不因短期明暗重选。
- 自动风格不再被没攒满的 60 s LRA 置信度整体压向通透；LRA 仍单独约束动态特征。
- 并联 Heat 的削峰份额是可选贡献：它不足时不锁死仍有余量的限幅器。
- **自动 Heat 只承担真能削的峰（算法 / 标定版本 8，0.1.8.6）**：这首歌在 Heat 上限内能削掉的峰值 ≥ 0.1 dB 时才为削峰加 Heat，否则只给风格底量（出厂三种风格都是 12）；满强度自动 Heat 由原来按风格的 70 / 50 / 20 降到 12 左右。旧工程里的常数快照读入时丢弃，方案一律用本版本的出厂常数。

## 主段

实时段落账：一段 = 一小节，按宿主的位置与拍号定位；拿不到拍点时改成每 2 秒一段；同一小节重放覆盖旧值、不重复计入；最多记 512 段。主段按响度模型认（段响度相对参考的软门）。画像按主段度加权，所以前奏、breakdown 进画像的分量小；此刻这一段 m < 0.5 时，棘轮让净增益只降不升，轻的段落不会被推上去。没有锁定条件、暂定方案和锁定后的补听。

## 曲风与交付（0.1.8.11 取消）

0.1.8.8 ～ 0.1.8.10 有两个附加选择：曲风（通用 / Deep / Tech / Melodic，House 三类换音色目标、低切、加宽、认主段的模型，另加限幅释放跟拍、反相提示与落差守门）和交付（标准 / 流媒体 / 俱乐部，换目标响度，流媒体把限幅上限封顶在 −2 dBTP）。0.1.8.11 起两项连同它们的常数与守门一起删掉，只剩原来「通用 + 标准」那一条路径；那条路径的声音不变。存着其他档位的旧工程读入时改回「通用 + 标准」、界面提示一次，声音会变。

## 存档与离线导出

工程里 GLAZE 只存一棵 `GLAZE_STATE`（格式 2），里面是 `LIVE`：实时画像窗口（`LIVE_PROFILE`）、速率限制器当前增量、G_trim、自动风格权重、守护、出口电平统计与修坯自动值，外层 zlib + base64，无损。读回后第一块起，这些控制量逐位等于保存时；滤波器与没写进 `LIVE` 的窗从零开始。旧工程的 `GLAZE_PROFILE` / `PLAN` / `CALIBRATION` / `EXECUTION` / `GLAZE_CONSTANTS` 读到就丢，按冷启动处理，界面提示一次；0.1.8.10 存下的落差 / PSR 两扇守门的状态读到就丢，`LIVE` 其余部分照常读回。宿主 reset、停播、跳播不清 `LIVE`。离线与实时走同一条处理路径；每次导出都在更新统计，所以重复导出不保证逐位相同。

## 保护统计的时隙

Guard 用 10 ms 时隙均值的 p95 近似。链按保护层的时隙边界和 100 ms 子块边界（取较近的一个）切片，模块统计不跨时隙；宿主整块仍用同一组执行参数，新的控制量在下一宿主块应用。

保护层的计时只按音乐时间走：宿主停止、静音、宿主旁通期间统计与观察期都冻结，不会误吸收反馈。每次重算目标（每 1 s，或换风格）后，保护层与上游监视的上限都跟着换。手动设置单独已超出风格预算的项（Heat 驱动、Glue 均值 / p95、Clip 深度 / 活动），保护层与上游监视对该项不再设约束——那一项的自动部分本来就是 0，按风格上限核对只会白白退让；其余项照风格上限核对（以上三条 0.1.8.6）。

## 验收总表

1. 从初始化起 GLAZE 一直为 0：整链输出与参照链逐位相同（90 个场景）。
2. 决策器是纯函数：同输入逐位同输出；随 GLAZE 单调；永不超各模块上限；GLAZE 0 时增量全为 0。
3. 已够响的素材仍保留最少推响量（请求不低于它）；超限时降低目标。
4. 最终输出真峰值 ≤ Ceiling + 0.01 dB（8× 表口径）。
5. 保存往返：读回后第一块起，控制量（已施加增量、G_trim、守护、Clay 自动值、已发布画像）逐位等于保存时；重复导出不保证逐位相同。
6. 性能：GLAZE 开着时整插件 48k / 512 增加 ≤ 0.15 %，最坏块增加 ≤ 0.5 个百分点；音频线程 0 分配 0 锁。
7. 合成音乐只调 GLAZE = 50：累计响度提升 6.47 LU；GLAZE 0 / 25 / 50 / 75 / 100 → −23.97 / −20.61 / −17.24 / −13.96 / −10.64 LUFS（单一素材，不是任意歌曲的保证）。
