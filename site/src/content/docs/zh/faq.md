## 换了歌，声音怎么没跟着变？

画像一首歌一份，换歌时不会自己重新聆听。点「重新聆听」；再点一次「重新计量」清零整体响度。

## 一直停在「聆听中 / 校准中」？

- 聆听需要**有效音乐 ≥ 30 秒**左右；太短或大段静音的素材攒不够证据。
- 选了 Deep / Tech / Melodic（House 类曲风）时，聆听要凑够 64 个不重复的小节并听到主段落，通常两分钟上下；状态行会写进度，见[House 类曲风怎么聆听](/docs/glaze#house-类曲风怎么聆听)。不到 64 小节的短素材请选「通用」。
- FL Studio 的 Pattern 模式循环一小段会一直校准，内部开发版时已处理；持续「校准中」到歌结束的问题（吸收型约束反馈后校准从零重开）在 0.1.7.1 修了。若还遇到，请把工程与歌发给 Max。

## 重开工程后校准丢了？

0.1.8.5 已修：Release、低切、收单这三个旋钮的值经宿主存取后会有极小的误差，旧版因此以为设置变了、把校准丢掉。现在按容差比较，旧工程读回时也会自动认回原来的校准。

## 为什么旧工程里「高级」的项全是关？

兼容：0.1.8.5 新增的推响不刺、目标频谱、编码余量、抖动，读旧工程时一律关，声音与从前一样；新实例才默认「自动」。想用就手动开。

## 宿主没看到新版本？

宿主缓存了旧二进制。保存工程，重启宿主或重新扫描插件目录。macOS 的 AU 还可能要清 AU 缓存。

## GLAZE 拧大了不再变响？

先看状态行里的「目标 … LUFS」：动态保护排在响度前面，推到各模块的预算上限就不再推，目标随之降低，状态通常仍是「跟随 · … · 目标 … LUFS」。另有两种情形：状态行写「受手动设置限制」（标签「受手动」），是你的手动值已把某个模块的预算用完，那个模块的自动增量撤回；写「受限 · 原因 · 已退 x dB」（标签「受限」），是播放中守护正在把自动增益往回退（原因：预算 / 交付峰值 / 保对比 / PSR，最多退 3 dB），条件消失后会慢慢回来。要么接受，要么调低 GLAZE 保留起伏，要么手动加 Gain / Clip——手动值是底，但也受各模块约束。

## OUT 真峰值偶尔比 Ceiling 高 0.0x dB？

插件承诺的是自己 8× 表口径下 ≤ Ceiling + 0.01 dB，另留 0.35 dB 重建余量。不同测量器（16× 参考、重采样、有损编码后）会读到高一点。交付前设「编码余量」，并在实际编码后用独立工具复测。

## 导出出来比听到的响 / 小？

检查「等响」是否还开着（它随工程保存）、「归一化预听」是否退出。离线导出会自动关预听，实时导出不会。

## 同一首歌怎么出流媒体版和俱乐部版？

把「交付」依次选成「流媒体」和「俱乐部」，每次切换后从 drop 开始播到状态回到「已锁定」，再各导出一次，就得到两版母带。步骤与原因见[切换，以及导出两版母带](/docs/glaze#切换-以及导出两版母带)。

## Windows 提示「未知发布者」？

安装包没有代码签名。SmartScreen 里点「更多信息 → 仍要运行」。

## Intel Mac / Rosetta？

装 Intel 包；两种芯片的 AU 都过 auval。Apple Silicon 上用 Rosetta 打开的宿主也要装 Intel 包。不要自己用更高指令集重编（Rosetta 没有 AVX，会直接崩）。老 Intel 笔记本上 192 kHz 配小缓冲有爆音风险。

## 界面里出现「Debug 构建」字样？

那是调试版，CPU 远高于 Release，只供调试。正常分发只给 Release。

## 声像 / 单声道兼容会不会被 CLAY 改坏？

收单与加宽只动侧声道 S，单声道回放（L + R）完全不变；低切只删设定频率（10～60 Hz）以下的超低频（自动只在有 16 Hz 以下次声时才切）。自动态不会收单，只在低频反相时亮琥珀灯提醒。

## CPU 占用怎么看？

界面右上「延迟」旁没有 CPU 表。参考值：M2 Pro、GLAZE 100、界面关，48 kHz 约 1.3 % 音频线程预算。界面打开时另有约 1/4 核的绘制开销；「减少动效」能省一点。
